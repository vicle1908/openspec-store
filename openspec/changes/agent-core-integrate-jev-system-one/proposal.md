# Proposal: Integrate TypeSafe Jev System One into SHB Banking Ecosystem & Workspace Foundation

## Why

Discrete decision-making across banking agent workflows currently incurs excessive latency and token expenditure by forcing full autoregressive LLM generations or relying on brittle regex patterns for security-critical authorizations. In the Saigon-Hanoi Bank (SHB) Banking Ecosystem (`~/Developer/shb/*`), tool authorization guards, anti-money laundering (AML) pre-flight triage, 12-stage LangGraph harness routing, engineering skill dispatch, stage deliverable verification, and evaluation judges repeatedly either incur multi-second token generation latency or fall back to rigid regex pattern matching that misses obfuscated prompt injection, structuring behaviors, and transliterated sanctions evasions.

TypeSafe's Jev is a dedicated System One model: it evaluates typed questions against a state and returns typed values and calibrated probabilities ($p \in [0, 1]$) that application code branches on directly — without autoregressive text generation, token streaming, or output-token parsing overhead. Integrating Jev into `shb-core` establishes a unified, shared workspace foundation that provides fast semantic pre-flight guardrails, dynamic tool schema pruning, confidence-gated LangGraph harness skips, two-stage candidate skill reranking, non-generative trace evaluation scoring, and unified OpenTelemetry decision observability across the seven core SHB banking packages (`shb-core`, `shb-agent-core`, `shb-agent-harness`, `shb-ai-harness-skills`, `shb-agent-skills`, `shb-observability`, and `shb-ai-review`), with alignment to `shb-mcp-servers` and `shb-tools`, serving simultaneously as an ecosystem blueprint reusable across other multi-repo workspace organizations (`platform`, `vds`, `ascend`, `ghtk`, `fpt`).

### Non-Goals

- **Freezing `tdt/agent-core` and `tdt-core`**: The entire `~/Developer/tdt/agent-core` codebase, `tdt-core`, and `~/.tdt/` environment are strictly out of scope and frozen for this change. No files in `tdt/*` will be modified, inspected, or imported.
- **Never Bypassing Maker-Checker Invariants**: Transfers strictly exceeding the 50,000,000 VND maker-checker threshold (`MAKER_CHECKER_THRESHOLD_VND`) ALWAYS require supervisor token validation (`ModelRetry` / `PENDING_APPROVAL`). Jev is an early semantic risk classifier for sub-threshold escalation and pre-flight blocking; it NEVER bypasses or overrides mandatory maker-checker supervisor approvals.
- **Never Bypassing LangGraph Human-in-the-Loop Gates**: The LangGraph 12-stage harness's `interrupt()` gate at `StageName.PLAN_REVIEW` remains an inviolable human checkpoint. Jev decisions only govern conditional workflow edge skips (such as bypassing `StageName.API_CONTRACT` directly to `StageName.DESIGN` on high-confidence spec decisions) and never bypass human review.
- **No Generative or Streaming Text**: Jev is strictly a System One decision evaluator emitting calibrated probabilities, choices, and ordinal scores. Generative text generation, streaming chat protocols, and explainability narratives remain the sole domain of downstream generative models (such as Pydantic AI agent models).
- **Deferring Live Threshold Calibration**: Because `TYPESAFE_API_KEY` is not provisioned in the local environment, live-traffic probability threshold calibration is explicitly deferred to operational deployment. This change implements and validates the client, settings, circuit breakers, decision registries, state sanitizers, fail-closed mechanics, and comprehensive mock/unit test suites.

### Affected Ownership Boundaries

The integration spans seven discrete repositories in the SHB banking ecosystem plus alignment with MCP servers and verification tooling:
1. **`shb-core` (`shb_core` package)**: Owns foundational `JevSettings`, `JevDecisionClient`, `JevCircuitBreaker`, PAN/credential state sanitization (`sanitize_jev_state`), normalized token attribution (`JevUsage` from `typesafe_sdk.Usage`), OpenTelemetry tracing helper, optional-dependency fallback shims when `typesafe-sdk` is absent, and centralized reviewable decision definitions (`shb_core.decisions`). Provides portable contracts (`DecisionContract`, `GuardrailPolicy`, `CitationCheckContract`) for workspace reuse.
2. **`shb-agent-core` (`shb_agent` package)**: Owns banking agent pre-flight guardrails (`JevToolGuardrail`, `AuthorityClass`, `GuardrailOutcome`) covering all 10 registered banking tools (with `tool_` prefix normalization), transfer maker-checker escalation integration in `ShbAgent` and `initiate_fund_transfer`, `pay_bill` debit anomaly detection, `parse_vietqr` QR Tag 62 prompt injection screening, semantic AML screening triage in `screen_beneficiary`, Pydantic AI dynamic `prepare_tools` / `prepare` capabilities, and non-generative `JevEvaluator` evaluation scorers (`pydantic-evals` with `BANKING_EVAL_DATASET`).
3. **`shb-agent-harness` (`shb_harness` package)**: Owns confidence-gated 12-stage LangGraph workflow routing (`_should_skip_api_contract` / `a_should_skip_api_contract`) over `HarnessState` (with deterministic `ClassificationStage` metadata precedence and `"design"` vs `"api_contract"` `Choice` criteria), wired via dual sync/async `RunnableCallable` to prevent `TypeError` in `graph.invoke()` while preserving synchronous `SqliteSaver` checkpointer compatibility and inviolable human review interrupts.
4. **`shb-ai-harness-skills` (`shb_ai_harness` package)**: Owns stage deliverable citation and evidence verification (`verify_stage_deliverable_evidence` in `src/shb_ai_harness/contracts.py` with 12-to-13 stage alias mapping) validating deterministic IDs (`REQ`, `AC`, `EVD`, `DES`, `DEC`, `API`, `TASK`, `TC`, `ATP`, `VER`) alongside semantic Jev `citation_check` `Noul`s, plus fixing `src/shb_ai_harness/cli.py:20` where `schema.get("stages", {})` silently returns `{}` (`Total stages defined: 0`) by reading `schema.get("artifacts", [])` (`13` artifacts).
5. **`shb-agent-skills` (`shb_skills` package)**: Creates `src/shb_skills/matcher.py` implementing `SkillMatcher` over `SkillsCatalog` with Stage 1 deterministic lexical/category shortlist retrieval (`match()`) and Stage 2 batched per-candidate `Noul` reranking (`match_jev()` / `a_match_jev()`), re-exported in `src/shb_skills/__init__.py`.
6. **`shb-observability` (`shb_observability` package)**: Owns centralized telemetry capture (`OTelTraceSpan.attributes` and `TelemetryStore.record_jev_decision`), recording `shb.jev.decision` trace spans and `shb_jev_decisions_total` counter metrics with normalized `input_tokens`, `output_tokens` (`question_tokens`), and `total_tokens` attribution while keeping `record_span()` backward-compatible.
7. **`shb-ai-review` (`shb_review` package)**: Owns pre-flight diff hunk triage (`MR_DIFF_TRIAGE_CONTRACT` in `src/shb_review/validation/hunk_gate.py` and `src/shb_review/ai/reviewer.py`) over `DiffHunkInfo.redacted_diff` (`redact_outbound_content`-sanitized hunks) and post-generation AI finding citation verification (`MR_FINDING_CITATION_CONTRACT` with `grounded_in_diff`, `contains_speculative_language`, `contradicts_diff`) to demote ungrounded AI review findings.
8. **`shb-mcp-servers` (`shb_mcp` package)**: Aligns MCP tool execution dispatch (`src/shb_mcp/tools.py:176` `execute_tool`) with `shb-core` `GuardrailPolicy`, `MCP_TOOL_AUTHORITY_MAP`, and `mask_pan` / `sanitize_jev_state` contracts while preserving top-level response fields.
9. **`shb-tools`**: Enforces ecosystem compliance checks (`SEC-001`, `PCI-001`, `SYN-001`) across all modified codebases.

## What Changes

This change delivers a coordinated 4-layer integration across the SHB Banking Ecosystem and Workspace Foundation:

### Layer 1 — Shared Ecosystem Foundation (`shb-core`, package `shb_core`)

- **Configuration & Environment Isolation (`src/shb_core/config.py`)**:
  - Adds `JevSettings(BaseSettings)` with environment variable aliases supporting both `JEV_` and `SHB_JEV_` prefixes.
  - Automatically loads configuration from `~/.shb/.env` and optional `~/.shb/config.yaml` with secret key stripping and emits a `UserWarning` if secrets (`typesafe_api_key` or `pydantic_ai_gateway_api_key`) appear in yaml files. Strictly isolated from `~/.tdt/`.
  - Attaches `jev: JevSettings = Field(default_factory=JevSettings)` onto `ShbSettings` accessible via `get_settings().jev`.
  - Pinned default fields: `enabled: bool = False`, `model: str = "jev-1.13.0"` (with forward compatibility for preview `jev-1.14.0` in `typesafe-sdk>=0.7.5`), `timeout_seconds: float = 1.5`, `max_retries: int = 2`, `http2: bool = True`, `base_url: str | None = None`, `fail_closed: bool = True`, `circuit_breaker_threshold: int = 3`, `circuit_breaker_cooldown_seconds: float = 30.0`.
  - **Request Body Compression & Gateway/Version Compatibility**: Exposes `compression: Literal["zstd", False] | None = None`. While `typesafe-sdk>=0.7.5` enables `zstd` request body compression by default for bodies $\ge 1\text{ KiB}$, cached `typesafe-sdk==0.7.2` (`typesafe_sdk/_core/client/sync/client.py:21-33`) does not accept a `compression` keyword argument (`TypeError: unexpected keyword argument 'compression'`), and non-official proxy gateways (`PYDANTIC_AI_GATEWAY_API_KEY` / custom `base_url`) or mock `httpx2` transports may not decompress `Content-Encoding: zstd`. `JevDecisionClient` resolves `effective_compression = False if (base_url or transport is not None) else settings.jev.compression`, stores it on the wrapper, and passes `compression=effective_compression` to `TypeSafeClient` / `AsyncTypeSafeClient` **only when `"compression" in inspect.signature(TypeSafeClient.__init__).parameters`**.
- **System One Decision Client (`src/shb_core/jev.py`)**:
  - Implements `JevDecisionClient` wrapping official `typesafe_sdk.TypeSafeClient` and `typesafe_sdk.AsyncTypeSafeClient` (`evaluate` and `a_evaluate` calling `system_one`), with lightweight Pydantic/TypedDict fallback shims (`Noul`, `Choice`, `Score`, `NoulCriteria`, `NoulAnswer`, `ChoiceAnswer`, `ScoreAnswer`, `Usage`, `SystemOneResponse`, `TypeSafeError`, `TypeSafeAuthenticationError`) defined in `shb_core/jev.py` and `shb_core/decisions.py` so repositories operate cleanly even when the optional `typesafe-sdk` dependency is not installed.
  - Supports TypeSafe's three real primitives and calibrated confidence math (`docs.typesafe.ai/confidence.md`, `primitives.md`):
    - `NoulAnswer`: Exposes `noul: float` ($p \in [0.0, 1.0]$) with certainty $|2p - 1|$. A score near $0.5$ indicates maximal uncertainty between yes and no, NOT medium intensity.
    - `Choice(criteria=Mapping[str, JSONContent | None])`: Supports `None` for self-explanatory keys or pre-parsed candidate spans (`typesafe_sdk/_core/question_types.py`). `ChoiceAnswer.confidence` measures distribution concentration.
    - `Score(criteria=Sequence[JSONContent])`: 0-indexed levels $0 \dots N-1$ (`min_length=2`), returning expected value $\sum_{i=0}^{N-1} i \cdot P(i) \in [0.0, N-1]$ (`ScoreAnswer.score`, `confidence`, `probabilities`, `legend`).
  - **Caller-Only Question IDs & Structured `JSONContent` with Backticked State Paths (`docs.typesafe.ai/concepts/state.md`)**:
    - Question IDs are for caller code only and are never sent to the model. Questions carry self-contained meaning in `instructions` and `criteria` using structured `JSONContent` dicts (`{"definition": ..., "includes": [...], "excludes": [...], "contrast_with": ...}`) for nuanced domain boundaries.
    - Instructions use backticked JSON state paths (e.g., `` `transaction.narrative` ``, `` `beneficiary.name` ``, `` `ticket.stage_results.spec.summary` ``) to focus model attention on nested state attributes.
  - **Token Attribution & Normalized `JevUsage` (`response.usage`)**:
    - In `typesafe-sdk` (`0.7.2` and `0.7.5`, `typesafe_sdk/_core/response_types.py:59-67` and `typesafe_sdk/_schemas/models.py:130-137`, re-exported as `typesafe_sdk.Usage`), `Usage` defines only `input_tokens: int | None = None` and `output_tokens: int | None = None` with `ConfigDict(extra="ignore", frozen=True, strict=True)` (it does not define `question_tokens` or `total_tokens` attributes). `JevDecisionClient` reads `input_tokens = response.usage.input_tokens or 0` and `output_tokens = response.usage.output_tokens if response.usage.output_tokens is not None else (getattr(response.usage, "question_tokens", 0) or 0)` from `typesafe_sdk.Usage`, and surfaces normalized `JevUsage(input_tokens=input_tokens, output_tokens=output_tokens, question_tokens=output_tokens, total_tokens=input_tokens + output_tokens)` on the client's evaluation result, OpenTelemetry spans (`jev.input_tokens`, `jev.output_tokens`, `jev.total_tokens`), and `TelemetryStore`. Mock transport JSON bodies include `"usage": {"input_tokens": ..., "output_tokens": ...}`.
  - **Preserves Verified `typesafe-sdk` Runtime Invariants**:
    - **Explicit Credential & Base URL Resolution**: Explicitly resolves credentials as `api_key = api_key or os.environ.get("TYPESAFE_API_KEY") or os.environ.get("PYDANTIC_AI_GATEWAY_API_KEY")` and `base_url = settings.jev.base_url or os.environ.get("TYPESAFE_BASE_URL") or None`, bypassing the SDK limitation where `resolve_and_validate_api_key()` only checks `TYPESAFE_API_KEY`.
    - **HTTP/2 Transport Multiplexing (`typesafe-sdk[http2]>=0.7.2`)**: When `http2=True` and `transport is None`, explicitly instantiates `httpx2.AsyncClient(http2=True, timeout=timeout)` / `httpx2.Client(http2=True, timeout=timeout)` with configured `timeout_seconds` so `httpx2` does not fall back to its internal 5.0s default. Exposes `close()` / `aclose()` methods and sync/async context manager protocols.
    - **Safe Request ID Extraction**: Defensively catches `TypeSafeError("The response did not include a request ID.")` (`typesafe_sdk/_core/schemas/base.py:67-73`) when the `x-typesafe-request-id` header is missing, reading `raw_http_response.headers.get("x-typesafe-request-id")` with a safe empty fallback.
    - **Native Pydantic Response Model Handling**: Custom typed schemas declaring top-level question fields subclass `SystemOneResponse` (whose `_decode()` lifts `decoded["answers"][field]` onto top-level model attributes, unlike plain `BaseModel`), while `JevDecisionClient` safely normalizes and lifts `answers` when a plain `BaseModel` is passed.
    - **Consecutive Failure Circuit Breaker (`JevCircuitBreaker`)**: Tracks consecutive transport errors and HTTP 5xx responses; trips to open state after 3 failures, failing closed or safe according to policy during a 30-second cooldown period before attempting half-open probe requests.
    - **Wire-Log Clamping & State Sanitization (`sanitize_jev_state`)**: Clamps `logging.getLogger("typesafe_sdk")` to `>= logging.INFO` to prevent `RequestState._log_wire` from logging raw request payloads at `DEBUG`. Implements `sanitize_jev_state(state: Any, *, max_tokens: int = 32_000) -> Any` in `src/shb_core/jev.py` using `shb_core.security.crypto.mask_pan` and recursive secret-key redaction (`secret`, `token`, `password`, `key`, `supervisor_approval_token`, excluding `idempotency_key`) to enforce bounded (`<32k` tokens) and redacted state projections.
    - **Distributed Telemetry Spans**: Emits OpenTelemetry trace spans (`shb.jev.decision`) via `shb_core.telemetry.get_tracer("shb_core.jev")` with model, question count, latency, normalized token usage (`jev.input_tokens`, `jev.output_tokens`, `jev.total_tokens`), and outcome attributes.
- **Centralized Decision Registry & 6 Official Cookbook Patterns (`src/shb_core/decisions.py`)**:
  - Provides a single, centralized, code-reviewed module housing all atomic questions, structured `JSONContent` criteria, combining weights, risk-scaled confidence thresholds, and `MCP_TOOL_AUTHORITY_MAP` across the SHB ecosystem (strictly free of `SEC-001` secret-like literals $\ge 12$ chars or `PCI-001` unmasked 16-digit PANs in non-comment lines).
  - Defines portable foundation contracts (`DecisionContract`, `GuardrailPolicy`, `CitationCheckContract`) reusable across workspace organizations (`shb`, `platform`, `vds`, `ascend`, `ghtk`, `fpt`, `wiki`).
  - Implements the 6 official TypeSafe cookbook patterns:
    1. **Speculative Fan-Out & Single-Pass Function Calling (`patterns/fan-out.md`, `cookbooks/function_calling.md`)**: Batch intent/tool-family routing (`Choice`), per-tool safety `Noul`s, and domain-specific risk `Noul`s in a single parallel `system_one` request (`~11.5x` lower cost, `~9.6x` lower latency).
    2. **Composite Scoring (`patterns/composite-scoring.md`)**: Evaluate independent `Score` (normalized as $\text{score}/(N-1)$) and hard-veto `Noul` dimensions in one request and combine in Python so weights and thresholds can be retuned without re-running inference.
    3. **Citation & Groundedness Verification (`cookbooks/citation_check.md`)**: Atomic `Noul`s (`grounded_in_diff` / `observed_claims_grounded_in_evd`, `contains_speculative_language`, `contradicts_diff`) powering both MR diff review finding checks (`MR_FINDING_CITATION_CONTRACT`) and stage deliverable verification.
    4. **SDE Cascade / Escalation (`cookbooks/sde_cascade.md`)**: Fast System One pass handles clear cases in `~70-200ms` and escalates uncertain ($|2p - 1| < \text{threshold}$) or low-confidence cases to generative models (`DecisionHandOff` / `FallbackModel` in Pydantic AI 2.54.0) or human maker-checker / `interrupt()` review.
    5. **Pre-Parsed Candidate Value Selection (`cookbooks/pre_parsed_value_extraction_cookbook.md`)**: Extract candidate spans in code first and pass them to `Choice(criteria={..., "none": None})` so the model selects strictly from verified source spans without hallucination.
    6. **Two-Stage Reranking & Hierarchical Classification (`cookbooks/rerank_typesafe.md`, `cookbooks/hierarchical_classification.md`)**: Stage 1 lexical shortlist + Stage 2 batched per-candidate `Noul` reranking.

### Layer 2 — Banking Agent Pre-Flight Guardrails, Dynamic Tool Pruning & Evaluation Scorers (`shb-agent-core`, package `shb_agent`)

  - Maps all 10 registered banking tools in `src/shb_agent/tools/__init__.py` to `AuthorityClass` in `TOOL_AUTHORITY_MAP`:
    - `READ_ONLY`: `get_account_balance`, `query_transaction_status`, `get_transaction_history`, `query_bill`
    - `OPERATIONAL`: `verify_beneficiary_account`, `generate_vietqr`, `parse_vietqr` (`src/shb_agent/tools/vietqr.py:135`: extracts EMVCo Tag 62 `purpose` content when present for Jev prompt-injection screening while preserving `is_valid_crc: True` for 4-hex-char CRCs so `test_parse_vietqr` passes, and exposing `crc_matches_computed: bool`)
    - `FINANCIAL_TRANSFER`: `initiate_fund_transfer` (inviolable `> 50,000,000 VND` maker-checker supervisor token + sub-50M VND structuring escalation) AND `pay_bill` (`src/shb_agent/tools/biller.py`: high-value biller debit & `amount != amount_due` anomaly escalation)
    - `COMPLIANCE_CRITICAL`: `screen_beneficiary` (deterministic `RESTRICTED_KEYWORDS` & `HIGH_RISK_ACCOUNTS` first, then Jev `Noul` for transliterated/diacritic-stripped Vietnamese & English PEP/OFAC/SBV sanction evasion)
  - Implements `JevToolGuardrail`, evaluating batched atomic `Noul` questions per condition (prompt injection, split transfer structuring, evasive narrative) in a single `system_one` call.
  - Sanitizes tool arguments and state using `shb_agent.tools.audit.sanitize_payload` and `mask_pan` before dispatch.
  - Combines individual probabilities in code using weights from `shb_core.decisions`, mapping final scores against risk-scaled confidence bands (proceed above clear-threshold, block above threat-threshold, escalate within uncertain band).
- **Pydantic AI 2.54.0 Dynamic `PrepareTools`, Tool Prefix Normalization & Native Model Cascades**:
  - Leverages `pydantic-ai==2.54.0` native capability `PrepareTools(prepare_func)` (or `@agent.tool(prepare=fn)`): when speculative fan-out classifies a turn as read-only (`recommended_tool_family` with confidence $\ge 0.85$), dynamically omits financial debit tools (`initiate_fund_transfer`, `pay_bill`) from the active tool schema, preventing indirect prompt injection from triggering unauthorized debits.
  - Because `src/shb_agent/agent.py:86-152` registers 3 tools with the `tool_` prefix (`tool_get_account_balance`, `tool_query_transaction_status`, `tool_initiate_fund_transfer`) and 7 tools without `tool_` via `tool_plain`, `PrepareTools` and `Hooks` normalize tool names via `tool_name.removeprefix("tool_")` when matching against `TOOL_AUTHORITY_MAP` (`{"initiate_fund_transfer", "pay_bill"}`), and preserve `ShbAgent.run()`'s simulation path and `TestModel` compatibility (`tests/test_agent.py`) when `JEV_ENABLED=false` or when no Jev credential/mock client is configured.
  - Supports native `TypeSafeModel` / `SystemOneModel` (`pydantic_ai.models.typesafe`, `pydantic_ai.models.decision.DecisionModel`) and `DecisionHandOff` for `FallbackModel(TypeSafeModel(...), primary_llm, fallback_on=DecisionHandOff)` SDE cascades.
- **Banking Agent & AML Integration**:
  - **Maker-Checker Rule Enforcement (`src/shb_agent/agent.py`, `src/shb_agent/tools/banking.py`)**: For fund transfers, transfers strictly exceeding 50,000,000 VND (`MAKER_CHECKER_THRESHOLD_VND`) ALWAYS enforce supervisor approval token validation and cannot be bypassed by Jev. For transfers $\le$ 50,000,000 VND, semantic guardrail escalation converts the transfer to require supervisor approval (`ModelRetry` / `PENDING_APPROVAL`) or blocks it; when a valid `supervisor_approval_token` (`len >= 8`) is supplied, an `ESCALATE` outcome (including fail-closed escalation on missing Jev credentials) is satisfied by that supervisor token and returns `status="COMPLETED"`.
  - **AML Beneficiary Screening (`src/shb_agent/tools/compliance.py`)**: Preserves deterministic rule checks (`RESTRICTED_KEYWORDS`, `HIGH_RISK_ACCOUNTS`) as authoritative; when Jev is enabled, evaluates semantic `Noul` questions for transliterated or obfuscated sanctions matches, flagging matches as `FLAGGED_FOR_MANUAL_REVIEW`. Fails closed to deterministic rules if Jev fails.
  - **Audit Logging Middleware (`src/shb_agent/tools/audit.py`)**: Records guardrail decisions and Jev evaluations in structured audit trails.
- **Evaluation Scorers (`src/shb_agent/evaluation/__init__.py`, `src/shb_agent/evaluation/jev_scorer.py`)**:
  - Creates `src/shb_agent/evaluation/__init__.py` and `src/shb_agent/evaluation/jev_scorer.py` implementing `JevEvaluator` and built-in `BANKING_EVAL_DATASET` (`pydantic_evals.Dataset` / `Case`) with `pydantic-evals==2.54.0` (already installed in `.venv`, declaring `pydantic-evals>=1.70.0` in `pyproject.toml`).
  - Scores independent rubric dimensions (`Score` and `Noul`) in a single parallel request and composes overall scores in Python.
  - Full compatibility with `pydantic-evals`, recording `EvaluationReason(value=False, reason=...)` on transport errors without crashing batch evaluation runs.

### Layer 3 — Confidence-Gated 12-Stage LangGraph Routing & Deliverable Evidence Verification (`shb-agent-harness` & `shb-ai-harness-skills`)

- **Dual Sync/Async `RunnableCallable` Workflow Routing (`src/shb_harness/workflow.py`)**:
  - Addresses LangGraph internals (`langgraph/_internal/_runnable.py:424-436`) where passing a bare `async def` function to `builder.add_conditional_edges` causes synchronous `graph.invoke(...)` (used by `HarnessRunner.run_all()`) to raise `TypeError('No synchronous function provided to "branch:to:..."')`, while `SqliteSaver` checkpointer is synchronous-only.
  - Wires `RunnableCallable(_should_skip_api_contract, a_should_skip_api_contract)` into `add_conditional_edges(StageName.SPEC.value, ...)` so `graph.invoke()` calls synchronous `JevDecisionClient.evaluate()` and `await graph.ainvoke()` calls `await JevDecisionClient.a_evaluate()` natively without `asyncio.run()`.
  - Normalizes `state = HarnessState.model_validate(state) if isinstance(state, dict) else state` at the entry of `_should_skip_api_contract` and `a_should_skip_api_contract`, and runs the deterministic `classification.metadata` check (`category == "internal_refactor"` or `has_api_impact is False`) FIRST before Jev so `test_harness_conditional_routing_skip_api_contract` (`tests/test_harness.py:47`) always passes.
  - When Jev is enabled and deterministic rules do not already skip, evaluates a `Choice` decision with criteria keys `"design"` (`StageName.DESIGN.value`) vs `"api_contract"` (`StageName.API_CONTRACT.value`) over `HarnessState` using `JevDecisionClient`. High-confidence decisions (`choice == "design"` and `confidence >= 0.85`) route directly from `StageName.SPEC` to `StageName.DESIGN`, bypassing `StageName.API_CONTRACT`.
  - Fail-safe routing: when Jev is disabled, unconfigured, low-confidence (`< 0.85`), returns `"api_contract"`, or encounters transport errors, routing defaults safely to `StageName.API_CONTRACT.value`. The `interrupt()` human review gate at `StageName.PLAN_REVIEW` remains strictly preserved.
- **Stage Deliverable Evidence Verification (`shb-ai-harness-skills`, package `shb_ai_harness`)**:
  - In `src/shb_ai_harness/contracts.py`, implements `verify_stage_deliverable_evidence()` combining deterministic ID checks (`REQ`, `AC`, `EVD`, `DES`, `DEC`, `API`, `TASK`, `TC`, `ATP`, `VER`) with a 12-to-13 stage alias map (`implementation_plan -> impl_plan`, `test_plan -> test_cases`, `verification -> verify`) and Jev `citation_check` `Noul` questions (`observed_claims_grounded_in_evd`, `upstream_requirements_traced`, `planning_only_boundary_preserved`).
  - Fixes schema artifact extraction in `src/shb_ai_harness/cli.py:20` (where `stages = schema.get("stages", {})` silently returned `{}` and printed `Total stages defined: 0`) to read `stages = schema.get("artifacts", [])` (`13` artifacts).

### Layer 4 — Two-Stage Skill Reranking, Telemetry, Review Contracts & MCP Alignment (`shb-agent-skills`, `shb-observability`, `shb-ai-review`, `shb-mcp-servers`)

- **Two-Stage Skill Matching (`src/shb_skills/matcher.py`, `src/shb_skills/__init__.py`)**:
  - Creates `src/shb_skills/matcher.py` implementing `SkillMatcher` over `SkillsCatalog` (populated from `load_skills_registry()` across 38+ engineering skills in `registry.yaml`) and re-exports `SkillMatcher` in `src/shb_skills/__init__.py`.
  - Stage 1 performs fast deterministic lexical and category shortlist retrieval (`match(query, *, category=None, top_k=5)`).
  - Stage 2 (`match_jev()` / `a_match_jev()`) asks one independent `Noul` question per query-candidate pair in a single parallel request, ranking candidates strictly by descending yes-probability.
  - Enforces the shortlist subset invariant: candidates evaluated in Stage 2 must come from Stage 1, and any transport failure falls back seamlessly to the Stage 1 lexical order.
