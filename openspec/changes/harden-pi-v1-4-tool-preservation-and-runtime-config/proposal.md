# Proposal

## Why

The Pi Coding Agent (`pi` v1.4.0) runtime and its OmniRoute `/v1/responses` gateway pipeline still suffer from five verified post-alignment defects that strip up to 93% of non-shell tool outputs (`subagent`, `codemode`, `pi-lens`, `gitnexus`), silently disable multi-provider web-search routing and Firecrawl extraction, overwrite Pi 1.4.0's structured `SystemPromptSections` via `pi-gitnexus`'s `forceSystemPrompt`, collapse mid-conversation system prompt patches on `omniroute-responses`, and bloat every session's `<available_skills>` prompt with 44 internal OmniRoute CLI management skills.

Specifically:
1. **OmniRoute `/v1/responses` Stacked Compression Corrupts Non-Shell Tool Outputs (`~/Omniroute/scripts/container-entrypoint-compat.sh`)**: In `strategySelector.ts`, `adaptBodyForCompression(body)` runs before `applyStackedCompression` and executes `delete t.input`. Consequently, when `applyRtkCompression` (`chunks/53846.js` and `72459.js`) runs inside the `default-caveman` stacked pipeline (`[session-dedup, lite, rtk, codex-responses, headroom]`), `Array.isArray(a.input)` is `false` and `toolCallLookup` (`m`) is always empty (`m.size === 0`). Because `markCodexResponseEligibility` (`chunks/{14211,41669,72459,88137,98542}.js`) only protects the 9 hardcoded names in `DEFAULT_CODEX_PROTECTED_TOOL_NAMES` (`read`, `glob`, `grep`, `write`, `edit`, `websearch`, `webfetch`, `web_search`, `web_fetch`), every other Pi tool (`subagent`, `codemode`, `tool_search`, `effective_config`, `module_report`, `project_report`, `symbol_search`, `read_symbol`, `read_enclosing`, `lens_diagnostics`, `gitnexus_*`, `memory_*`, `fetch_content`, `get_search_content`, `source_check`, `intercom`) receives `a.eligible = true` and `c._rtkSkip = false`. In live sessions, `subagent({ action: "list" })` loses 14 of 15 lines (matching RTK's `npm-audit` filter on the word `High` in `High-context`), `subagent({ action: "models" })` loses 100% of agent names, `subagent({ action: "doctor" })` loses 29 lines to `codex-responses` `collapseLines`, and `bash` tool calls lose their `command` metadata.
2. **`pi-web-access` Multi-Provider Search Routing Disabled & Firecrawl Unavailable (`~/.pi/agent/web-search.json`)**: In `pi-web-access` v0.46.0 (`gemini-search.ts`), `getConfiguredSearchRouting()` returns `undefined` whenever `"provider"` or `"searchProvider"` is present in `web-search.json` (`config.searchProviderConfigured === true`). Because `~/.pi/agent/web-search.json` sets `"provider": "exa"`, `searchRouting` (`["exa", "brave", "tavily"]`) is completely bypassed. Additionally, `firecrawl.ts` has no default base URL and requires `firecrawlBaseUrl` (or `FIRECRAWL_BASE_URL`), so `isFirecrawlAvailable()` returns `false` and `fetchRouting` (`["http", "firecrawl"]`) never falls back to Firecrawl. Finally, `"workflow": "summary-review"` blocks top-level interactive/RPC `web_search` calls for 20 seconds on the local Curator UI server, and `"searchModel": "gemini-2.5-flash"` overrides the v0.46.0 default `"gemini-3.6-flash"`.
3. **`pi-gitnexus` (`0.6.4`) Sets `forceSystemPrompt` and Appends Empty Tool-Result Banners (`~/.pi/pi-gitnexus.json`, `~/.pi/agent/extensions/agentmemory/index.js`)**: Because `/Users/androidteam/Developer/.gitnexus` exists at the workspace root (holding `groups/workspace/`), `findGitNexusIndex(ctx.cwd)` returns `true` across `/Users/androidteam/Developer`. On every turn, `pi-gitnexus`'s `before_agent_start` handler returns `{ systemPrompt: event.systemPrompt + "\n\n[GitNexus active] ..." }`, setting `currentOptions.forceSystemPrompt` in Pi 1.4.0—which forces `_installAgentForcedPromptProjection()` to collapse mid-conversation `role: "system"` section updates and invalidates prompt-cache reuse for forked subagents (`oracle`). Furthermore, on every `read`, `grep`, `find`, and `bash` tool call, `pi-gitnexus` spawns `gitnexus augment <pattern>`, treats the bare stderr version line `"GitNexus Augment (1.6.12)"` as a non-empty hit, and appends `---\n[GitNexus: <name>]\nGitNexus Augment (1.6.12)\n---` even when zero symbols match.
4. **Missing `compat` Flags on `omniroute-responses` and Custom Providers (`~/.pi/agent/models.json`)**: Custom models in `~/.pi/agent/models.json` default to `supportsMidConvoSystemMessages: false`, causing Pi 1.4.0 to call `collapseSystemMessages(transcript)` and rewrite byte 0 of the leading system prompt whenever any structured prompt section (`active_subagents`, `advertised_subagents`, `mcp_servers`, or `selectedTools`) changes mid-session. In addition, `omniroute-responses` (Pi's default provider) is missing `"compat": { "supportsLongCacheRetention": true }`.
5. **Unfiltered OmniRoute Internal Skills, Unadvertised Core Subagents & Untrusted OmniRoute Path (`~/.pi/agent/settings.json`, `~/.pi/agent/trust.json`)**: Pi auto-discovers 196 skills (`92,157` chars / `~23,000` tokens in `<available_skills>`), including 44 non-symlinked OmniRoute internal CLI skills (`cli-*` and `omni-*`) in `~/.agents/skills/`; `subagents.agentOverrides` in `settings.json` omits `"advertise": true` (leaving `<advertised_subagents>` empty); and `~/.pi/agent/trust.json` omits `"/Users/androidteam/Omniroute": true` (causing `pi-lens` to refuse project-local LSP binaries when inspecting `~/Omniroute`).

### Non-Goals

- Changing Pi's default provider/model (`omniroute-responses/gemini-3.8-flash-high`), removing any of the 6 providers in `~/.pi/agent/models.json`, or removing any of the 5 managed npm packages in `~/.pi/agent/settings.json`.
- Deleting or modifying `/Users/androidteam/Developer/.gitnexus` (which is governed by `refresh-gitnexus-index-groups` and `gitnexus-stable-contract`) or deleting skill directories inside `/Users/androidteam/Developer/.agents/skills/` or `~/.agents/skills/` (which are governed by `agent-skill-distribution` and `sync-workspace-agent-skills.py`).
- Modifying git-tracked files in `/Users/androidteam/Omniroute` or patching files inside `~/.pi/agent/npm/node_modules/`.

## What Changes

- **Preserve OpenAI Responses `toolName`/`command` metadata across `adaptBodyForCompression` and restrict `rtk`/`codex-responses` to shell tools (`~/Omniroute/scripts/container-entrypoint-compat.sh`)**: Update the `markCodexResponseEligibility` replacement rule across compiled chunks `14211.js`, `41669.js`, `72459.js`, `88137.js`, and `98542.js` so it extracts both `toolName` and `command` (from `arguments.command` / `arguments.cmd`) from `body.input` `type: "function_call"` items before `delete t.input`, sets `a.eligible` to `true` only for shell tools (`/\b(bash|shell|terminal|run_command|execute_command|exec|command)\b/i` and not in `skippedCallIds`), and attaches `c._toolCommand` and `c._rtkSkip = !isShellTool` to the adapted `role: "tool"` message. Update `applyRtkCompression` in `53846.js` and `72459.js` to read `a._toolCommand` when `toolCallLookup` (`m`) is empty, ensuring all non-shell tools (`subagent`, `codemode`, `pi-lens`, `gitnexus_*`, `memory_*`, `web_search`, `fetch_content`, `read`, `glob`, `grep`, `write`, `edit`) bypass both `rtk` shell filters and `codex-responses` log/search collapsing while `bash` tool calls retain their command string.
- **Enable `pi-web-access` multi-provider routing and Firecrawl fallback (`~/.pi/agent/web-search.json`)**: Remove `"provider": "exa"` so `getConfiguredSearchRouting()` activates `searchRouting` (`["exa", "brave", "tavily"]` with `exa` primary), add `"firecrawlBaseUrl": "https://api.firecrawl.dev"` so `isFirecrawlAvailable()` returns `true`, set `"workflow": "none"` so top-level `web_search` calls do not block on the Curator server, and set `"searchModel": "gemini-3.6-flash"`.
- **Disable `pi-gitnexus` auto-augment subprocesses (`~/.pi/pi-gitnexus.json`) and convert static `forceSystemPrompt` suffixes into `promptGuidelines` (`~/.pi/agent/extensions/agentmemory/index.js`)**: Create `~/.pi/pi-gitnexus.json` (`0600`) with `{"autoAugment": false}` so `pi-gitnexus` stops spawning `gitnexus augment` and appending empty `GitNexus Augment (1.6.12)` banners on `read`/`grep`/`find`/`bash`, and install a `forceSystemPrompt` setter on `event.systemPromptOptions` inside `agentmemory/index.js` (`before_agent_start`) that intercepts static suffix appends (such as `pi-gitnexus`'s `[GitNexus active]` block), pushes the suffix into `event.systemPromptOptions.promptGuidelines`, and keeps `forceSystemPrompt` `undefined`.
- **Configure `compat` flags on custom providers in `~/.pi/agent/models.json`**: Add `"compat": { "supportsLongCacheRetention": true, "supportsMidConvoSystemMessages": true }` to `omniroute-responses`, add `"supportsMidConvoSystemMessages": true` to `cockpit`, `omniroute`, and `phanmemvip`, and add `"supportsMidConvoSystemMessages": true` to `shopapikey` and `omniroute-anthropic`.
- **Filter internal OmniRoute CLI skills, advertise core subagents, and trust `~/Omniroute` (`~/.pi/agent/settings.json`, `~/.pi/agent/trust.json`)**: Add `"skills": ["!**/cli-*", "!**/omni-*"]` to `~/.pi/agent/settings.json` (excluding the 44 non-symlinked OmniRoute CLI skills from Pi's `<available_skills>` section without altering `~/.agents/skills/` on disk), add `"advertise": true` to `scout`, `researcher`, `reviewer`, `oracle`, and `worker` in `subagents.agentOverrides`, and add `"/Users/androidteam/Omniroute": true` to `~/.pi/agent/trust.json`, plus update `~/.hermes/skills/autonomous-ai-agents/pi/SKILL.md` and `~/Developer/wiki/entities/pi.md` (synced to Notion page `3efc4b21-deb4-8129-b9c3-d7c22a453212`).
