Phase 1 Context

The Problem

PMPUtilViewModel is a 985-line god class with 30+ consumers — and a fundamental lifecycle bug that freezes prices.

Legacy PMPUtilViewModel — 985 lines

Per-Fragment TCP Sockets

Each Fragment opens its own socket. Same stock viewed in two screens = 2 TCP connections.

Reconnect Flash (~200ms)

Every onPause → unSubscribeQueryRequest() sends STREAMING_UNSCRIBE. Server forgets subscription. onResume → reSubscribe() must rebuild from scratch.

SR-3738 — BottomSheet Lifecycle

BottomSheetDialogFragment onResume may not fire when navigating back. Prices freeze and never recover.

5 Callback Variants

livePrices, USSO, history, confirm, status — each with its own fan-out logic mixed into the same 985-line class.

New PMPConnectionCenter + PMPViewModel

Process Singleton Pool

One PMPNode per unique URL. Multiple fragments share one TCP socket. Ref-counted by token.

Stale-then-Live

Connection survives onPause. App background → suspendForBackground(). App foreground → cached snapshots emitted immediately, then live ticks.

SR-3738 Fixed

detach() stops collector but leaves token open. subscribe() reuses cached token. BottomSheet lifecycle is irrelevant.

Reactive SharedFlow API

Fragments collect via repeatOnLifecycle(STARTED). PMPUpdate carries topic, indices, data, and isAllDataReturned.

Root cause: unSubscribeQueryRequest() sends STREAMING_UNSUBSCRIBE — the server forgets the subscription. The fix is to never call it on Fragment onPause. Instead, detach() only cancels the collector. The connection stays open.
Phase 1 Architecture

Solution Architecture

4 layers. Each layer does one job. Read top-to-bottom: triggers → routes → pools → collects.

How data flows: Fragment subscribes (top) → Center routes by URL (middle-top) → Existing Node emits ticks (middle-bottom) → Fragment collects updates (bottom).
How it survives lifecycle: detach() stops collecting (④). The connection (③) stays open. No new login on onResume().
Overview URL Pooling

One Phone Line Per Supplier

When 3 screens show the same stock, they share 1 TCP socket — not 3.

Result: 3 screens showing AAPL → 1 TCP socket to the HK server. 3× bandwidth savings, 3× login cost savings, 1× failure point instead of 3.
Phase 1 SR-3738 Fix

The Lifecycle Fix

detach() stops the collector — the token stays open. unsubscribe() (only in onDestroyView) closes it.

Migrated Fragment — Lifecycle Contract

class MyFragment : Fragment() {
  private val pmpViewModel:
    PMPViewModel by viewModels()

  override fun onViewCreated(...) {
    viewLifecycleOwner.lifecycleScope.launch {
      viewLifecycleOwner.repeatOnLifecycle(STARTED) {
        pmpViewModel.pmpDataFlow.collect {
          update → onPmpReceived(update)
        }
      }
    }
  }

  override fun onResume() {
    super.onResume()
    pmpViewModel.subscribe(counters, fields)
  }

  override fun onPause() {
    super.onPause()
    pmpViewModel.detach()  // collector stops
                              // token stays OPEN ✅
  }

  override fun onDestroyView() {
    super.onDestroyView()
    pmpViewModel.unsubscribe()  // closes token
  }
}

unsubscribe() Cancelled Closed Ref count −1

Phase 1 Node State Machine

PMPNode State Transitions

Stale callback guard (connSeq): A MutableStateFlow<Int> increments on each connect(). Events carry the seq number at emission time; a stale callback from a previous connection is discarded if its seq doesn't match connSeq.value.
Phase 1 Design History

Three Iterations Before Shipping

Each pivot addressed a real production risk identified through careful analysis.

Iteration 1

Modify PMPUtilViewModel Internally

Add a delegate to PMPConnectionCenter inside the existing 985-line class. Keep 30+ screens unchanged via a dispatch adapter.

Risk found: The center does not survive Fragment onPause/onResume — it closes on the Fragment's lifecycle.
Iteration 2

Gate New Connections

Add isCenterActive() gate to suppress legacy connection creation. Adapter dispatches into legacy callback chain.

Risk found: Two connections run in parallel — legacy is constructed before the gate fires. Double socket traffic.
Iteration 3 — Shipped

Pivot: New PMPViewModel

Revert PMPUtilViewModel to Phase 1 state. Create new PMPViewModel (~150 lines) as a clean wrapper. Migrate one screen at a time.

Result: SR-3738 confirmed fixed. URL pooling works. NewOrderBottomSheet migrated.
Flow-based state machine with Mutex
MutableStateFlow<State> + MutableSharedFlow<ConnEvent> replaces synchronized {}. The price-tick gate is enforced by .combine(_state) at the type level — not a runtime if. Mutex.withLock{} can be held across suspend points; synchronized{} cannot.
Kotlin object singleton
No Application registration needed. Initializes lazily on first access. Matches existing PmpConnectionPool pattern in the codebase.
Per-URL node pooling
One PMPNode per unique URL. Multiple fragments sharing the same URL reuse one TCP socket. The PMP library allows multiple subscriptions on a single connection — multiplexing by URL maximizes reuse.
60-second teardown grace
After the last token closes, a node schedules a 60-second timer before calling connection.logout(). Covers quick tab switches. Timer is cancellable — a new subscription clears it.

Phase 2 isAllDataReturned Sentinel

Implementing isAllDataReturned

IndicesDetailScreen is the only screen using the 4-arg listener — it must fire exactly once per batch.

Algorithm — PMPViewModel

class PMPViewModel : ViewModel() {
  private val emissionCounter =
    AtomicInteger(0)
  private val expectedTopicCount =
    AtomicInteger(0)

  fun subscribe(counters, fields) {
    // Rebuild index map
    mHashmapIndexOfCounter.clear()
    counters.forEachIndexed { idx, c ->
      c.PMPTopic?.let { topic ->
        mHashmapIndexOfCounter
          .getOrPut(topic) { mutableListOf() }
          .add(idx)
      }
    }
    expectedTopicCount.set(
      mHashmapIndexOfCounter.size)
    emissionCounter.set(0)

    collectorJob = viewModelScope.launch {
      token.priceUpdates.collect { (topic, rawData) ->
        val indices =
          mHashmapIndexOfCounter[topic] ?: emptyList()
        val aliasedData =
          aliasFields(rawData, subscribeFields)

        val count = emissionCounter.incrementAndGet()
        val isLast = count >= expectedTopicCount.get()
        if (isLast) emissionCounter.set(0)

        _pmpDataFlow.tryEmit(PMPUpdate(
          topic, indices, aliasedData,
          isAllDataReturned = isLast))
      }
    }
  }
}

Edge Cases

Single-topic subscription

Every emission fires isAllDataReturned=true. Correct — a single-topic batch is always complete after one tick.

Collector cancelled mid-batch

detach() cancels the collector. Next subscribe() resets both counters. Stale value cannot affect the next batch.

Server delivers fewer topics

isAllDataReturned does NOT fire. Counter is not reset. Fires when the server delivers all topics — matching legacy indexPmp == lastIndex semantics.

Re-subscribe with different counters

subscribe() resets both counters at start. New batch starts cleanly.

Phase 2 aliasFields Restoration

Restoring Field Aliasing

Legacy getFinalHashMapPmpResponse() aliased raw FIDs ("9") to canonical strings ("9,F009,P23"). Without this, migrated screens silently show empty price fields.

The Problem

Legacy aliases "9" → "9,F009,P23" in the callback:

// Legacy: data arrives keyed by alias
aliased = {
  "9,F009,P23": "123.45",   // aliased key
  "11,F011,P8": "124.00"
}

// Consumer reads:
linkMapPMP["9,F009,P23"]  // ✅ works with aliased
linkMapPMP["9,F009,P23"]  // ❌ empty with raw — silent fail!
Critical: The landed NewOrderBottomSheet migration does NOT call aliasFields. This may be silently broken for price fields that don't match raw FID lookups. Fix: add aliasFields to PMPViewModel in this MR.

The Solution — aliasFields()

private fun aliasFields(
  rawData: LinkedHashMap<String, String>,
  subscribeFields: List<
    WatchListColumnsSettingModel>
): LinkedHashMap<String, String> {
  val aliased = linkedMapOf<String, String>()
  val canonicalValues =
    subscribeFields.map { it.value }
      // ["9,F009,P23", "11,F011,P8", ...]

  rawData.forEach { (rawKey, value) ->
    val canonical = canonicalValues.firstOrNull {
      it.split(",").contains(rawKey)
    }
    if (canonical != null) {
      aliased[canonical] = value
    } else {
      aliased[rawKey] = value  // pass through
    }
  }
  return aliased
}
Placement: Private in PMPViewModel. PMPNode stays screen-agnostic (raw FIDs). Only the ViewModel's collector aliases.

Phase 3 Architecture

Two Path, Two Token Architecture

LIVE (per-product URL) and QUERY (historicalURL) use separate PMPNode instances and separate token classes.

Why separate PMPQueryToken: PMPToken.priceUpdates is typed as LinkedHashMap<String, String>. Adding List<String> to the same flow requires runtime casts. A separate class gives compile-time type safety with zero overhead.

override fun historyChartCallback(
  queryReturnBean: QueryReturnBean?
) {
  if (queryReturnBean == null) return

  val dayCloses: List<String> =
    queryReturnBean.itemList
      .orEmpty()
      .mapNotNull { it.val }
      .takeLast(250)  // HISTORICAL_WORKING_DAY_POINT

  // Sub-sample: keep every 10th + last

    { i, _ -> i % 10 == 0 || i == dayCloses.lastIndex }

  _event.tryEmit(ConnEvent.ChartData(
    topic = queryReturnBean.topic ?: return,
    chartPoints = sampled
  ))
}

All Phases Decisions

Key Design Decisions

D1: PMPUpdateKind enum + init{} invariants
Conservative choice matching PMPRequestType style. Sealed class rejected for lower boilerplate at 13+ consumption sites. init{} enforces LIVE: data≠null, QUERY: chartData≠null, USSO: data≠null.
D2: Separate PMPQueryToken class
PMPToken.priceUpdates is typed LinkedHashMap. Adding List<String> to same flow requires runtime casts. Separate class = compile-time safety.
D3: Historical URL = separate PMPNode
PMPSettingModel.liveChart.historicalURL is a different URL. Naturally gets its own node — no subclass needed.
D4: Flow-based state machine with Mutex
P1-P5 pipelines replace synchronized{} blocks. The type system enforces the Connected gate. Mutex.withLock{} can be held across suspend points.
D5: One collector per Fragment, dispatch on kind
Two collectors would race on pmpDataFlow replay=1. Single collector with switch on update.kind is canonical.
D6: Orphan chart topics silently dropped
Matches legacy: PMPUtilViewModel fires mOnQueryCallback only when listIndexOfCounter.isNotEmpty(). QUERY collector skips topics not in mChartTopicIndexMap.
D7: Per-subscribe emission counter
AtomicInteger tracks batch completion for isAllDataReturned. Resets on every subscribe() call. Single-topic = always isAllDataReturned=true.
D8: aliasFields restored in PMPViewModel
Raw FIDs ("9") → canonical values ("9,F009,P23"). Fixes both TopMarket migration and pre-existing NewOrderBottomSheet silently broken field lookups.
