# Seven-CLI Review Workflow

## Purpose

Verify that seven installed coding-agent CLIs can run noninteractively with their configured default model/provider and produce a substantive review. This is a local capability check, not a model benchmark.

## Reviewers and invocations

- Claude: `claude -p PROMPT --max-turns 10 --output-format text --no-session-persistence`
- Codex: `codex exec --ephemeral PROMPT`
- Antigravity: `agy -p PROMPT --output-format text --print-timeout 5m`
- Kimi: `kimi -p PROMPT --output-format text`
- OpenCode: `opencode run PROMPT`
- Pi: `pi -p --no-session --no-tools --no-extensions PROMPT`
- Goose: `goose run --no-session -q --max-turns 10 -t PROMPT`

No command passes a model, provider, endpoint, API key, or reasoning override. Session, tool, extension, output-format, turn, and timeout controls do not select a model/provider. Kimi's executable is `kimi`; `fable-5` is a model alias, not an executable.

## Execution

A full round always runs all seven CLIs in these sequential batches, with members of a batch concurrent:

1. Claude, Agy, Goose
2. OpenCode, Codex, Kimi
3. Pi alone

A smoke probe must exit 0 and include `CONNECTION_OK`. If smoke fails, review is skipped and the round fails. One CLI failure does not cancel siblings or later batches. There are no silent retries.

The retained fixture is UTF-8, below 20,000 bytes, and embedded identically in every review prompt. The runner checks its SHA-256 before and after the round.

## Evidence and classification

The Python runner invokes CLIs directly, without shell pipelines. It retains separate redacted stdout/stderr, true return code, timestamps, duration, executable path/version, prompt and fixture hashes, output sizes/hashes, and parsed status. A zero return code alone is not success.

A valid response has exactly one `VERDICT:` label with `APPROVE`, `APPROVE_WITH_CONDITIONS`, or `REJECT`, plus exactly one non-empty `FINDINGS:` and `RECOMMENDATIONS:` section. Optional Markdown emphasis around labels is accepted.

- `APPROVE` with no findings -> `PASS`
- `APPROVE` with findings -> `PASS_WITH_FINDINGS`
- `APPROVE_WITH_CONDITIONS` -> `PASS_WITH_FINDINGS`
- `REJECT` -> `REJECTED`
- Missing executable, timeout, signal, invalid invocation, configuration failure, nonzero process result, empty output, and malformed review use distinct non-passing statuses.

A full round passes only when all seven smoke probes are `PASS` and all seven reviews are `PASS` or `PASS_WITH_FINDINGS`.
