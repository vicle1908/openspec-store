# Design

## Context

See `proposal.md` for motivation and scope. OmniRoute `v3.8.53` runs on `iosteam-mac-mini` under Docker Compose `--profile base` (`127.0.0.1:20128`/`20129`) backed by named volume `omniroute-data` (`/app/data/storage.sqlite`), serving 16 local coding-agent configurations and remote peer `macbook-pro-m5` over Tailscale Serve. Upstream git tracking (`/Users/androidteam/Omniroute`) MUST stay at zero tracked modifications (`git status --porcelain --untracked-files=no` empty) so `~/Omniroute/scripts/update.sh` can fast-forward across upstream releases without merge conflicts.

## Goals / Non-Goals

**Goals:**
- Eliminate macOS Keychain (`docker-credential-osxkeychain`, `errSecAuthFailed -25293`) failures and digest-pin pull/rollback hazards in unattended `com.omniroute.update-check` (`check-upstream.sh`) and `update.sh` Gate 2 (`pull`) using running-container image digest comparison, OCI Distribution Spec v1.1 Registry HTTP API v2, ephemeral isolated `DOCKER_CONFIG` directories (`docker pull "$IMAGE_REF"` + `docker compose --profile base pull "$SERVICE" redis`), and fail-closed `docker-compose.override.yml` digest rollback on post-swap gate failures.
- Remove the `200 ms` (`5 req/s`) Bottleneck inter-request spacing bottleneck (`minTimeBetweenRequestsMs: 0`) so `concurrentRequests: 64` and `requestsPerMinute: 600` admit simultaneous bursts immediately per Little's Law ($L = \lambda \cdot W$).
- Stop daily ~125 MB `db_*_pre-write.sqlite` growth in `/app/data/db_backups/` via OmniRoute's native `DISABLE_SQLITE_AUTO_BACKUP=true` + `DB_BACKUP_MAX_FILES=2` / `DB_BACKUP_RETENTION_DAYS=2` contract, clean ~315 MB of obsolete pre-Docker host files in `~/.omniroute/`, cap `~/.omniroute/snapshots/` at 5 verified `.sqlite` files, and enforce `0700`/`0600` permissions.
- Idempotently pin `{ isActive: false, healthCheckInterval: 0 }` on disabled `pm` connection `f3aaa87c-4af7-4a83-a636-98983119b9bc` (`is_active = 0`, `health_check_interval = null` in live SQLite), delete unused 1-step combo `phanmemvip` (`ad4dace4-9072-42a8-8503-e6188e325890`), and reconcile `compression_combo_assignments` to the exact 14 active combo UUIDs while preserving the 9 inactive banned `agy` rows as an import-deduplication safety blocklist.

**Non-Goals:**
- Editing any git-tracked source file in `/Users/androidteam/Omniroute`.
- Mutating `~/.docker/config.json` globally (other private registries such as `registry.giaohangtietkiem.vn` continue using `credsStore: osxkeychain` in interactive user sessions).
- Deleting banned inactive `agy` rows in `provider_connections` or altering any of the 16 workstation coding-agent client configs.

## Decisions

### 1. Official Stable Image Currency, `SETUP_GUIDE.md` / `DOCKER_GUIDE.md` Alignment & Dual-Registry OCI v2 Pulls
- **Official Image Audit & Channel Policy**:
  - `omniroute-base` (`diegosouzapw/omniroute@sha256:b52a17661a1aff42ffb78f349f423e986dfc55b57274f28559f8387622ef8ee4`) is verified against both Docker Hub (`diegosouzapw/omniroute:latest` / `:3.8.53`) and OmniRoute's official GHCR mirror (`ghcr.io/cheaper-inference/omniroute:latest` / `:3.8.53` per `.github/workflows/docker-publish.yml:81-82`; note `ghcr.io/diegosouzapw/omniroute` froze at `3.8.33`). Mutable `:next` (`release/v3.8.54`) and `:main` channels are excluded per `docs/guides/DOCKER_GUIDE.md:554` ("not supported for production use").
  - `omniroute-redis` runs upstream `docker-compose.yml:77`'s older `redis:8.6.5-alpine`. Overriding `services.redis.image` in untracked `~/Omniroute/docker-compose.override.yml` to **`docker.io/library/redis:8.10.3-alpine@sha256:71885d8cc6e42f2bc0aa2eb853bfc4be200b5108a46ac50e117ae1df0531fb80`** (`redis:alpine`) AND adding `depends_on: { redis: { condition: service_healthy } }` on `omniroute-base` (matching `SELF_HOST_GUIDE.md` / `docker-compose.selfhost.yml:62-64` and `DOCKER_GUIDE.md:201`) eliminates cold-boot `ioredis` connection races while keeping git-tracked `docker-compose.yml` untouched.
- **Official `SETUP_GUIDE.md` & `DOCKER_GUIDE.md` Runtime Alignment**:
  - **Timeout Baseline (`SETUP_GUIDE.md:287-335`, `runtimeTimeouts.ts:325-349`)**: When `REQUEST_TIMEOUT_MS` is unset, `getApiBridgeTimeoutConfig` leaves `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS` at `300_000 ms` (`5m`) even though `FETCH_TIMEOUT_MS` and `API_BRIDGE_PROXY_TIMEOUT_MS` default to `600_000 ms` (`10m`), aborting >5m SSE turns on `:20129` (`cockpit` launcher). Explicitly setting `REQUEST_TIMEOUT_MS=600000` and `STREAM_IDLE_TIMEOUT_MS=600000` in `/Users/androidteam/Omniroute/.env` (propagated automatically via `docker-compose.yml:39` `env_file: .env` without duplicating them in `docker-compose.override.yml`) raises `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS` to `600_000 ms` across all upstream and bridge hops while keeping `.env` as the single source of truth.
  - **Loopback, MCP/A2A & Single-Replica Memory Sizing (`SETUP_GUIDE.md:248-250`, `DOCKER_GUIDE.md:273-350,660-740`)**: Explicitly set `APP_BIND_HOST=127.0.0.1`, `REDIS_BIND_HOST=127.0.0.1`, `OMNIROUTE_BASE_URL=http://127.0.0.1:20128`, and `OMNIROUTE_USE_TURBOPACK=0` (avoiding build-time Turbopack OOMs) while keeping `API_HOST=0.0.0.0` (required inside the container for Docker bridge DNAT on `127.0.0.1:20129:20129`) and `REQUIRE_API_KEY=false` (per `omniroute-agent-cli-routing` and `grok-cli-provider-routing` specs; host ports bind strictly to `127.0.0.1` and Tailscale Serve enforces tailnet identity). Keep `OMNIROUTE_MEMORY_MB=4096` paired with matching `NODE_OPTIONS=--max-old-space-size=4096` (suppressing `warnConflictingHeapLimits` against `docker-compose.yml:51`'s `2048`) and `mem_limit: 5g` (~1 GiB native/SQLite headroom inside the 6 GiB Docker Desktop LinuxKit VM shared with `shb-schedule`), plus `stop_grace_period: 40s` (`SHUTDOWN_TIMEOUT_MS=30000` + `5s` margin) and lightweight `/healthz` Docker probes.
- **OCI Distribution Spec v1.1, Running-Container Digest Comparison & Isolated `DOCKER_CONFIG` Rationale**:
  - `check-upstream.sh` executes under `umask 077` and resolves the local digest as a single canonical line from the running `omniroute` container's image ID (`IMG_ID=$(docker inspect omniroute --format '{{.Image}}')` -> `docker image inspect "$IMG_ID" --format '{{range .RepoDigests}}{{println .}}{{end}}' | grep -oE 'sha256:[a-f0-9]+' | head -n 1`, falling back to `$IMAGE` only when the container is absent) so multi-registry `RepoDigests` entries never fail string equality and a pulled-but-unverified `:latest` tag after a failed deploy never clears `~/.omniroute/update-available`. It queries the remote `Docker-Content-Digest` directly via anonymous OCI v2 Bearer token + `HEAD` (`application/vnd.oci.image.index.v1+json, application/vnd.docker.distribution.manifest.list.v2+json`) on Docker Hub (`registry-1.docker.io/v2/diegosouzapw/omniroute/manifests/latest`) in ~180 ms, automatically failing over to official GHCR (`ghcr.io/v2/cheaper-inference/omniroute/manifests/latest`) before falling back to `DOCKER_CONFIG="$TMP_DOCKER_CFG" DOCKER_HOST="${DOCKER_HOST:-unix://$HOME/.docker/run/docker.sock}" docker buildx imagetools inspect` where `$TMP_DOCKER_CFG/config.json` is `{"auths":{},"credHelpers":{"index.docker.io":"","https://index.docker.io/v1/":"","registry-1.docker.io":"","docker.io":"","ghcr.io":""}}`.
  - `update.sh` executes under `umask 077`, enforces `chmod 0600 "${SNAPSHOT_DIR}/${SNAPSHOT_NAME}"` in Gate 1 immediately after `docker cp` + SQLite consolidation, prunes `~/.omniroute/snapshots/*.sqlite` in Gate 9 to keep at most the 5 newest verified snapshots, and applies the ephemeral `DOCKER_CONFIG` + `DOCKER_HOST` wrapper in Gate 2 around `docker pull "$IMAGE_REF"` followed by `docker compose --profile base pull "$SERVICE" redis`: `docker pull "$IMAGE_REF"` refreshes `diegosouzapw/omniroute:latest` for Gate 3 (`digest-match`) even while `docker-compose.override.yml` pins the old `@sha256:...` digest, while `docker compose --profile base pull "$SERVICE" redis` pulls `redis` and preserves the space-padded `" pull "` argument pattern checked by `tests/test_omniroute_lock_and_watchdog.py:L375,L773`. In addition, `cleanup_update()` records the pre-deploy `override.yml` digest before line 270 and restores it automatically if `exit_rc != 0` on any subsequent gate (`Gate 4`..`Gate 9`), preventing manual rollback or `omniroute-watchdog.sh` from redeploying a failed image.

### 2. Zero-Gap Burst Admission (`minTimeBetweenRequestsMs: 0`)
- **Upstream Source Contract**: `src/shared/validation/schemas/settings.ts:44` validates `minTimeBetweenRequestsMs: z.number().int().min(0).optional()`, and `open-sse/services/rateLimitManager.ts:169-171` implements `resolveMinTime(0) -> 0` (`// 0 or missing means "no minimum gap"`).
- **Rationale**: Under Little's Law ($L = \lambda \cdot W$), bounding concurrency (`concurrentRequests: 64`) and reservoir rate (`requestsPerMinute: 600`) already prevents upstream overload. Keeping `minTimeBetweenRequestsMs: 200` serialized simultaneous bursts on auto-protected API-key combos (`deepseek-v4.1-flash`, `kimi-k3.1-pro`, `muse-spark-1.3`) and learned-cap `agy` floors (`capMinTimeWithFloor`) to `5 req/s` (`12.6s` tail queue wait at 64 concurrent turns). Setting `minTimeBetweenRequestsMs: 0` via `PATCH /api/resilience` updates in-memory Bottleneck limiters immediately inside one SQLite `key_value` write transaction.

### 3. Native `DISABLE_SQLITE_AUTO_BACKUP=true` + Bounded Retention & Host Snapshot Hygiene
- **Upstream Source Contract**: `src/lib/db/backup.ts:347` (`if (reason !== "manual" && reason !== "pre-restore" && isSqliteAutoBackupDisabled()) return null;`) and `src/lib/db/backupRetention.ts:131-145` (`resolveDbBackupRetention` prioritizes `process.env.DB_BACKUP_MAX_FILES` and `process.env.DB_BACKUP_RETENTION_DAYS` over `MAX_DB_BACKUPS = 20`). Note that `DELETE /api/db-backups` enforces `requireOperatorCredential` (`403` to Bearer API keys, `#16899`).
- **Transaction & Lock Boundaries**:
  1. First verify and take a fresh transactional SQLite snapshot (`better-sqlite3` `.backup()`, followed by host `PRAGMA wal_checkpoint(TRUNCATE);`, `PRAGMA journal_mode=DELETE;`, `PRAGMA quick_check = ok`, and removing transient `-wal`/`-shm` sidecars) into `~/.omniroute/snapshots/` (`mode 0600`) before any container recreation or file removal.
  2. Persist `backup: { autoBackupEnabled: false, keepLastNBackups: 2 }` via `PATCH /api/settings/database`, then acquire `/usr/bin/lockf -s -t 60 ~/.omniroute/update.lock` and recreate `omniroute-base` with `DISABLE_SQLITE_AUTO_BACKUP=true`, `DB_BACKUP_MAX_FILES=2`, and `DB_BACKUP_RETENTION_DAYS=2` set solely in `/Users/androidteam/Omniroute/.env` (`env_file: .env`, keeping `docker-compose.override.yml` strictly for Compose-level overrides) *before* running provider/combo/assignment API mutations (because `compressionCombos.ts:508`, `providers.ts:642`, and `combos.ts:43` invoke `backupDbFile("pre-write")`).
  3. After all API mutations settle and outside any `.migration-snapshot-*` window, run `PRAGMA wal_checkpoint(TRUNCATE)` and verify `PRAGMA quick_check = ok` on live `/app/data/storage.sqlite` immediately before unlinking the two pre-existing `db_*_pre-write.sqlite` (`177 MB`) files in `/app/data/db_backups/`.
  4. On host `~/.omniroute/` and `/Users/androidteam/Omniroute/`, remove only verified pre-Docker legacy artifacts (`~/.omniroute/storage.sqlite`, `storage.sqlite-wal`, `storage.sqlite-shm`, `db_backups/`, `server.log`, `server.err`, `call_logs/`, `logs/`, `log_archives/`, and `/Users/androidteam/Omniroute/data.bak-20260824/`), consolidate any retained WAL-mode host snapshots (`pre-carbon-concurrency-20261111-015747.sqlite`) to `journal_mode=DELETE`, retain the 5 newest verified `.sqlite` files in `~/.omniroute/snapshots/` with zero `*.sqlite-wal` / `*.sqlite-shm` sidecars, preserve `~/.omniroute/backups/scale-omniroute-concurrency-and-add-gemini-4-carbon/` intact, and enforce owner-only `go-rwx` permissions (`0700` on directories and executable scripts/binaries, `0600` on snapshots, logs, and data files).

### 4. Transactional Provider/Combo Quarantine & `compression_combo_assignments` Reconciliation
- **Upstream Source Contract**:
  - `PUT /api/providers/f3aaa87c-4af7-4a83-a636-98983119b9bc` (`{ isActive: false, healthCheckInterval: 0 }`) idempotently pins `healthCheckInterval: 0` alongside `is_active = 0` so credential health sweeps (`scheduler.ts:183` `intervalMs === null -> return`) stay permanently disabled even if re-evaluated.
  - `DELETE /api/combos/ad4dace4-9072-42a8-8503-e6188e325890` deletes unused `phanmemvip`, and `PUT /api/context/combos/default-caveman/assignments` (`src/lib/db/compressionCombos.ts:486-500`) runs inside a single `db.transaction(...)` that deletes all prior `default-caveman` rows (both stale plain-name strings and deleted combo UUIDs) and inserts the exact 14 active combo UUIDs.
  - Banned `agy` rows (`is_active = 0`, `test_status = 'banned'`) remain untouched so `findExistingAgyConnection` (`agyAuthImport.ts:201`) continues blocking accidental re-imports with `409 duplicate_account`.

## Risks / Trade-offs

- **Risk**: Disabling `pre-write` auto-backups inside `/app/data/db_backups/` removes automatic pre-mutation copies inside the container volume before `modelsDevSync` writes.
  - **Mitigation**: `update.sh` Gate 1 creates a `quick_check`-verified host SQLite snapshot before every image upgrade, `pre-migration` (`preMigrationBackup.ts`) and `manual`/`pre-restore` backups remain unaffected by `DISABLE_SQLITE_AUTO_BACKUP=true`, and `~/.omniroute/snapshots/` retains 5 verified point-in-time single-file SQLite snapshots (`0600`) on the host filesystem.
- **Risk**: Setting `minTimeBetweenRequestsMs: 0` removes artificial inter-request spacing on auto-protected API-key providers (`deepseek`, `kimi-coding`).
  - **Mitigation**: `concurrentRequests: 64` and `requestsPerMinute: 600` remain enforced by Bottleneck, and upstream `Retry-After` / body-stated 429 caps in `capSettingsWithinBudget` (`rateLimitManager.ts:198-214`) still compute `windowMs / N` dynamically whenever an upstream provider signals a rate cap.
