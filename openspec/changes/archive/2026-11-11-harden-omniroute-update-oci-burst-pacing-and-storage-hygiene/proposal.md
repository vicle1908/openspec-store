# Proposal

## Why

Unattended OmniRoute upstream update checks fail silently on macOS Keychain (`errSecAuthFailed -25293`), `update.sh` Gate 2 skips refreshing `:latest` when `docker-compose.override.yml` pins a digest, a residual `200 ms` Bottleneck pacing floor throttles 64-way subagent bursts to `5 req/s`, unconfigured daily `pre-write` SQLite copies and legacy pre-Docker host files bloat volume/host storage, and an unused `phanmemvip` combo (referencing disabled connection `f3aaa87c` with unset `health_check_interval`) plus orphaned `compression_combo_assignments` pollute routing and assignment state.

Specifically, five verified operational, image-currency, and official Setup/Docker Guide alignment gaps remain after scaling OmniRoute `v3.8.53` (`sha256:b52a1766...`, verified as the latest official stable release across both Docker Hub `diegosouzapw/omniroute:latest` and GHCR `ghcr.io/cheaper-inference/omniroute:latest`) to 64 heavy streams and 14 combos:
1. **Headless Docker Hub Keychain Failure (`-25293`), Digest-Pin Pull Deadlock & Outdated Redis Sidecar (`8.6.5-alpine` -> `8.10.3-alpine`)**: `~/.docker/config.json` sets `"credsStore": "osxkeychain"`. Under unattended `LaunchAgent` execution (`com.omniroute.update-check` every 12h), `check-upstream.sh` calls `docker buildx imagetools inspect diegosouzapw/omniroute:latest 2>/dev/null` (comparing against local `:latest` rather than the running `omniroute` container's image), which invokes `docker-credential-osxkeychain`, fails with `errSecAuthFailed (-25293)`, swallows stderr, and exits `0` with `WARNING: Could not fetch remote digest`. In `update.sh`, Gate 2 (`docker compose --profile base pull "$SERVICE"`) inherits the same `osxkeychain` dependency and pulls the *old* `@sha256:...` digest pinned in `docker-compose.override.yml` instead of refreshing `diegosouzapw/omniroute:latest` (`$IMAGE_REF`) for Gate 3, while post-Gate-4 failures leave `docker-compose.override.yml` pinned to the failed digest. Meanwhile `omniroute-redis` runs upstream's `redis:8.6.5-alpine` rather than the latest official stable `docker.io/library/redis:8.10.3-alpine` (`sha256:71885d8cc6e42f2bc0aa2eb853bfc4be200b5108a46ac50e117ae1df0531fb80`).
2. **Official Setup/Docker Guide Drift (`SETUP_GUIDE.md` Timeouts/MCP & `DOCKER_GUIDE.md` / `SELF_HOST_GUIDE.md` Redis Boot Gate)**: Because `REQUEST_TIMEOUT_MS` is unset in `~/Omniroute/.env`, `runtimeTimeouts.ts:340-349` leaves `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS=300000` (`5m`) on `:20129` even though `FETCH_TIMEOUT_MS` and `API_BRIDGE_PROXY_TIMEOUT_MS` are `600000` (`10m`), truncating >5m coding-agent SSE turns (`cockpit` launcher). In addition, `omniroute-base` lacks `depends_on: { redis: { condition: service_healthy } }` (standard in `SELF_HOST_GUIDE.md` / `docker-compose.selfhost.yml:62-64`), `.env` omits explicit `APP_BIND_HOST=127.0.0.1`, `REDIS_BIND_HOST=127.0.0.1`, and `OMNIROUTE_BASE_URL=http://127.0.0.1:20128` (`SETUP_GUIDE.md` MCP/A2A contract), and `.env:75` retains stale `OMNIROUTE_USE_TURBOPACK=1` (documented in `DOCKER_GUIDE.md:273-320` as OOM-prone for Docker builds).
3. **Serial `200 ms` Burst Pacing Bottleneck (`minTimeBetweenRequestsMs`)**: Although `settings.requestQueue` was scaled to `concurrentRequests: 64` and `requestsPerMinute: 600`, `minTimeBetweenRequestsMs` remained at `200`, forcing Bottleneck limiters (`open-sse/services/rateLimitManager.ts:263`, including auto-protected API-key combos `deepseek-v4.1-flash`, `kimi-k3.1-pro`, and `muse-spark-1.3`, plus `capMinTimeWithFloor` on learned 429 caps) to serialize burst arrivals at `5 req/s` (`300 RPM`), adding up to `12.6 seconds` of artificial queue delay across 64 concurrent turns.
4. **Unbounded `pre-write` SQLite Copies & Legacy Host `~/.omniroute/` Bloat**: `DISABLE_SQLITE_AUTO_BACKUP=false` in `~/Omniroute/.env` causes daily `modelsDevSync` runs (`04:49Z`) to write ~125 MB `db_*_pre-write.sqlite` copies into `/app/data/db_backups/` (currently `177 MB`, defaulting to `MAX_DB_BACKUPS = 20` / `~2.7 GB` ceiling in `backupRetention.ts:18`), while host `~/.omniroute/` still holds ~315 MB of pre-Docker legacy artifacts (`storage.sqlite*` from Oct 15, `db_backups/` from Jul 30, `server.log`, `server.err`, `call_logs/`, `logs/`, `log_archives/`), `~/Omniroute/data.bak-20260824/` (`7.6 MB` world-readable `0644`), and `1.8 GB` across 14 snapshots with `0644`/`0755` permissions and orphaned `-wal`/`-shm` sidecars.
5. **Dead `phanmemvip` Combo, Unpinned `f3aaa87c` Health Interval & Orphaned Combo Assignments**: Disabled connection `f3aaa87c-4af7-4a83-a636-98983119b9bc` (`pm`, `https://api.phanmemvip.shop/v1`, currently `is_active = 0` with `health_check_interval = null` after `HTTP 401 "Invalid API key"`) is still referenced by unused 1-step combo `phanmemvip` (`ad4dace4-9072-42a8-8503-e6188e325890`, which fails every request with `503`), while `compression_combo_assignments` holds 16 stale UUID/name rows (including `phanmemvip`) because `DELETE /api/combos/{id}` lacks cascade cleanup on `routing_combo_id`.
## What Changes

- **Official Stable Image Currency, Dual-Registry OCI v2 Digest Resolution & Isolated `DOCKER_CONFIG` Pulls (`~/Omniroute/docker-compose.override.yml`, `~/Omniroute/scripts/check-upstream.sh`, `~/Omniroute/scripts/update.sh`)**:
  - Keep `omniroute-base` on the latest official published stable SemVer image (`diegosouzapw/omniroute@sha256:b52a17661a1aff42ffb78f349f423e986dfc55b57274f28559f8387622ef8ee4`, `v3.8.53`), upgrade `services.redis.image` in `~/Omniroute/docker-compose.override.yml` from `redis:8.6.5-alpine` to the latest official stable **`docker.io/library/redis:8.10.3-alpine@sha256:71885d8cc6e42f2bc0aa2eb853bfc4be200b5108a46ac50e117ae1df0531fb80`** (`redis:alpine`) with `depends_on: { redis: { condition: service_healthy } }` on `omniroute-base` (`SELF_HOST_GUIDE.md` / `DOCKER_GUIDE.md`), and align `/Users/androidteam/Omniroute/.env` (single source via `docker-compose.yml` `env_file: .env`) with official `SETUP_GUIDE.md` (`REQUEST_TIMEOUT_MS=600000`, `STREAM_IDLE_TIMEOUT_MS=600000`, `OMNIROUTE_BASE_URL=http://127.0.0.1:20128`, `APP_BIND_HOST=127.0.0.1`, `REDIS_BIND_HOST=127.0.0.1`, `OMNIROUTE_USE_TURBOPACK=0`) without duplicating `.env` keys in `docker-compose.override.yml` or modifying git-tracked `docker-compose.yml`.
  - Update `check-upstream.sh` (with `umask 077`) to compare the running `omniroute` container's single extracted image digest (`IMG_ID=$(docker inspect omniroute --format '{{.Image}}')` -> `docker image inspect "$IMG_ID" --format '{{range .RepoDigests}}{{println .}}{{end}}' | grep -oE 'sha256:[a-f0-9]+' | head -n 1`, falling back to `$IMAGE` only when the container is absent) against the upstream multi-arch index digest resolved primarily via the **OCI Distribution Specification v1.1 / Docker Registry HTTP API v2** on Docker Hub (`diegosouzapw/omniroute:latest`) with automatic secondary OCI v2 mirror fallback to official GHCR (`ghcr.io/cheaper-inference/omniroute:latest`, per `docker-publish.yml:81-82`), then fallback to `docker buildx imagetools inspect` under an ephemeral mode-`0700` `DOCKER_CONFIG` directory containing `{"auths":{},"credHelpers":{"index.docker.io":"","https://index.docker.io/v1/":"","registry-1.docker.io":"","docker.io":"","ghcr.io":""}}` plus `DOCKER_HOST` preservation and explicit stderr logging.
  - Update `update.sh` (with `umask 077`, `chmod 0600` on Gate 1 host snapshots after `docker cp`, and Gate 9 pruning to keep at most the 5 newest verified snapshots in `~/.omniroute/snapshots/`) so Gate 2 runs `docker pull "$IMAGE_REF"` followed by `docker compose --profile base pull "$SERVICE" redis` under the same ephemeral mode-`0700` `DOCKER_CONFIG` (`credHelpers` empty-string overrides + `DOCKER_HOST` preservation, cleaned via `trap`), `:latest` refreshes before Gate 3 despite `override.yml`'s digest pin, both `omniroute-base` and `redis` pull without `-25293` failures, and `cleanup_update` automatically restores the pre-deploy `override.yml` digest if any post-swap gate fails.
- **Zero-Gap Burst Pacing (`PATCH /api/resilience`)**:
  - Set `settings.requestQueue.minTimeBetweenRequestsMs` to `0` (`resolveMinTime(0) === 0`) via `PATCH http://127.0.0.1:20128/api/resilience` while preserving `concurrentRequests: 64`, `requestsPerMinute: 600`, and `maxWaitMs: 15000`.
- **In-Volume `db_backups` Suppression/Retention & Host `~/.omniroute/` Hygiene**:
  - Configure `DISABLE_SQLITE_AUTO_BACKUP=true`, `DB_BACKUP_MAX_FILES=2`, and `DB_BACKUP_RETENTION_DAYS=2` in `/Users/androidteam/Omniroute/.env` (propagated via `env_file: .env` without duplicating in `docker-compose.override.yml`), persist `backup: { autoBackupEnabled: false, keepLastNBackups: 2 }` via `PATCH /api/settings/database`, recreate `omniroute-base` under `update.lock` before provider/combo/assignment mutations, and run `PRAGMA wal_checkpoint(TRUNCATE)` + `PRAGMA quick_check = ok` on live `/app/data/storage.sqlite` before unlinking the two existing `db_*_pre-write.sqlite` (`177 MB`) files in `/app/data/db_backups/`.
  - Remove obsolete pre-Docker host artifacts in `/Users/androidteam/.omniroute/` (`storage.sqlite`, `storage.sqlite-wal`, `storage.sqlite-shm`, `db_backups/`, `server.log`, `server.err`, `call_logs/`, `logs/`, `log_archives/`) and `/Users/androidteam/Omniroute/data.bak-20260824/`, prune `/Users/androidteam/.omniroute/snapshots/` to keep the 5 newest verified single-file SQLite snapshots consolidated in `journal_mode=DELETE` with zero `*.sqlite-wal` / `*.sqlite-shm` sidecars, and enforce owner-only (`go-rwx`) permissions across `~/.omniroute/` (`0700` on directories and executable scripts/binaries, `0600` on snapshots, logs, and data files).
- **Provider, Combo, and Assignment Hygiene (Preserving Banned `agy` Safety Blocklist)**:
  - Idempotently quarantine disabled `pm` connection `f3aaa87c-4af7-4a83-a636-98983119b9bc` via `PUT /api/providers/f3aaa87c-4af7-4a83-a636-98983119b9bc` (`{ isActive: false, healthCheckInterval: 0 }`) and delete unused combo `phanmemvip` (`DELETE /api/combos/ad4dace4-9072-42a8-8503-e6188e325890`), leaving the exact 14 active workstation combos.
  - Reconcile `compression_combo_assignments` via `PUT /api/context/combos/default-caveman/assignments` to reference only the 14 active combo UUIDs (eliminating duplicate plain-name and deleted `phanmemvip` entries).

### Explicit Non-Goals

- Modifying any git-tracked source file in `/Users/androidteam/Omniroute` (`git status --porcelain --untracked-files=no` MUST remain empty).
- Deleting the 9 inactive/banned `agy` rows (`is_active = 0`, `test_status = 'banned'`) in `provider_connections` — `src/lib/oauth/utils/agyAuthImport.ts:201` (`findExistingAgyConnection`) relies on those inactive rows as a deduplication blocklist against accidentally re-importing banned accounts, and `tokenHealthCheck.ts:566` skips `!conn.isActive` with zero runtime cost.
- Switching `omniroute-base` to mutable pre-release/development channels (`:next` `release/v3.8.54` or `:main`, explicitly marked unsupported for production in `docs/guides/DOCKER_GUIDE.md:554`) or switching `redis` to release-candidate tags (`8.12-rc2-alpine`); removing `omniroute-redis` from `--profile base`; or altering any of the 16 workstation coding-agent client configuration files or `~/.docker/config.json` global credential store.
