# Design

## Context

See `proposal.md` — Why for problem motivation.

Detailed root-cause, live database state, and post-apply audit findings verified across `/Users/androidteam/Omniroute`, `/Users/androidteam/Developer/scripts/omniroute-watchdog.sh`, and the live `omniroute` container (`diegosouzapw/omniroute:latest`, `v3.8.51`, OCI index digest `sha256:8bd462c9f60d8eda79329cfbb6ea7ea723505fe7721beb944f3d43835409e218`):

1. **Synchronous Startup Blocking, Managed Worker `BEGIN IMMEDIATE` Contention & Out-of-Band Integrity Policy (`src/lib/db/core.ts:952-977,1372-1410`, `src/lib/db/healthCheckWorker.ts:1-49`, `src/lib/db/healthCheck.ts:326-380,508-686`)**:
   - By default (`DB_HEALTHCHECK_STARTUP_DEFERRED_ENABLED = "false"` in `src/shared/constants/featureFlagDefinitions.ts:957-969`), `getDbInstance()` runs `runDbHealthCheck(db, ...)` synchronously on the main Node.js thread before HTTP routes can serve `/healthz`. On the pre-compaction 4.03 GB (`983,682`-page) `storage.sqlite` with `425,838` `quota_snapshots` rows, synchronous startup took ~270–300s, exceeding Docker's `start_period: 120s` + 3 retries (~210–255s) and triggering `com.omniroute.watchdog` `SIGTERM` restarts.
   - Setting `DB_HEALTHCHECK_STARTUP_DEFERRED_ENABLED=true` moves startup verification into `healthCheckWorker.ts` via `setImmediate` (`core.ts:1378-1383`). However, in `core.ts:954`, `const skipIntegrityCheck = skipIntegrity || process.env.OMNIROUTE_SKIP_DB_HEALTHCHECK === "1"` applies globally to **every** `runManagedDbHealthCheck()` invocation: deferred startup (`core.ts:1380`), the 6-hour scheduled timer (`core.ts:937`), and manual `POST /api/db/health` (`src/app/api/db/health/route.ts:31`), not just startup.
   - Inside `healthCheckWorker.ts:22-35`, the child worker first runs `runDbHealthCheck` read-only outside a transaction; if `job.autoRepair && result.issues.length > 0` (e.g. a single stale `quota_snapshots` row or broken combo reference), it creates a backup and enters `connection.immediate(...)` (`BEGIN IMMEDIATE` with `timeout: 5000` ms) to re-run `runDbHealthCheck` using the same `skipIntegrityCheck` setting.
   - Live read-only inspection of the compacted `/app/data/storage.sqlite` (`1,111,265,280` bytes / `271,313` pages, `PRAGMA auto_vacuum = 2` / `INCREMENTAL`, `key_value` `scheduler/vacuumDrift = "null"`, flat `autoVacuumMode = "\"INCREMENTAL\""` and `scheduledVacuum = "\"weekly\""`, `feature_flags = []` with no DB override) confirmed that a single read-only `PRAGMA quick_check` takes **`6,454 ms` (~6.45s)**. If `OMNIROUTE_SKIP_DB_HEALTHCHECK=1` were unset, any `autoRepair` pass in `healthCheckWorker.ts` would run a second ~6.45s `PRAGMA quick_check` plus a 321,297-row `scanQuotaSnapshots` loop **inside `BEGIN IMMEDIATE`**, holding the exclusive SQLite write lock for well over the 5,000 ms `busy_timeout`.
   - **Integrity Policy Decision**: Retain both `DB_HEALTHCHECK_STARTUP_DEFERRED_ENABLED=true` and `OMNIROUTE_SKIP_DB_HEALTHCHECK=1` in `~/Omniroute/docker-compose.override.yml` (allowing in-app managed health checks to run logical table checks/repairs without `quick_check` write-lock contention), and enforce physical SQLite B-tree verification out of band via:
     1. **Watchdog Step 3 Periodic Read-Only Full `PRAGMA integrity_check` (Every 6 Hours / `21600s`)**: When `omniroute` is `running`, `State.Health.Status != starting`, and `/healthz` returns HTTP 200, `omniroute-watchdog.sh` (while holding the FD `9` `/usr/bin/lockf` lock) checks `~/.omniroute/integrity-last-ok` mtime (`stat -f %m`). When missing or age `>= 21600s`, it runs an in-container read-only `better-sqlite3` (`{readonly:true, fileMustExist:true, timeout:15000}`) `db.pragma('integrity_check')` inside an isolated `child_process.spawnSync` bounded to `110,000 ms` (`SIGKILL`) and wrapped by host `gtimeout --signal=TERM --kill-after=5s 120s`. It touches `~/.omniroute/integrity-last-ok` **only** when every returned row equals `'ok'`, and on any failure or timeout logs `ERROR` and exits non-zero **without** restarting an otherwise healthy gateway.
     2. **Updater Gate 1 & Gate 9 Read-Only `PRAGMA quick_check`**: Bounded by `gtimeout` (`run_bounded`) before and after deployment.
2. **Root Cause of `conversation_turn_nodes` Explosion (`4,859,612` rows in 30 days) & 9.07 GB Volume Footprint**:
   - In `open-sse/services/conversationTracker.ts:432-564` (`resolveConversationId()`), whenever a request's message history diverges from a candidate chain (`match.anchorHasChild === true`), OmniRoute mints a new `agentic_conversations` root (`turn_count = 1`) and re-inserts every historical turn (`0..N-1`) with a new chain hash (`O(N^2)` amplification). While `rotateCallLogs()` trims `call_logs` to `CALL_LOG_RETENTION_DAYS = 7` days, `retention.conversationTurnNodes` defaulted to `30` days.
   - Before compaction, `/app/data` on `omniroute_omniroute-data` held `storage.sqlite` (`4.03 GB`), `/app/data/storage.sqlite.snapshot.bak` (`3.02 GB` from `2026-10-10`), and `/app/data/db_backups/*_pre-migration.sqlite` (`2.02 GB` from `2026-10-03`).
3. **Why PID/Epoch Lockfiles Failed Audit & Why Native macOS `/usr/bin/lockf` Is Required**:
   - The initial implementation coordinated `~/.omniroute/update.lock` by checking `if [[ -f "$LOCK_FILE" ]]` and writing `printf '%s %s\n' "$$" "$(date +%s)" > "$LOCK_FILE"`. Independent audit proved three flaws:
     1. **Non-atomic check-then-write race**: Two concurrent contenders can both observe the lock absent or stale and both set `LOCK_OWNED=true`.
     2. **Unsafe wall-clock expiry & metadata parsing**: A live `update.sh` or offline `VACUUM` running for `>= 1800s` (or a lockfile with non-decimal/octal tokens such as `08` that pass `^[0-9]+$` regex but fail bash `$(( ... ))` arithmetic under `set -euo pipefail`) caused `omniroute-watchdog.sh` to delete the lock or fall through to container actions while the owner was still alive.
     3. **Unlink inode race**: Removing (`rm -f`) `~/.omniroute/update.lock` on release or stale detection allows a new process to lock a different inode than a contender.
   - On macOS, `/usr/bin/lockf` provides native kernel `flock(2)` synchronization on an open file descriptor: opening persistent `~/.omniroute/update.lock` (`umask 077; exec 9>>"$LOCK_FILE"`) and calling `/usr/bin/lockf -s -t 0 9` acquires an exclusive kernel lock on FD `9` held by the shell process until FD `9` closes or the shell exits (`EX_TEMPFAIL = 75` on contention).
4. **Historical Oct 19 Backup & Transaction Gap vs. Current State**:
   - During the historical 2026-10-19 cleanup (Tasks 2.2 & 2.3), the pre-maintenance check verified `/Users/androidteam/.omniroute/snapshots/pre-update-20261003-220431.sqlite` (`2026-10-03`, `api_keys = 1`, `provider_connections = 20`) instead of capturing a fresh pre-prune snapshot of the 2026-10-19 live DB (`api_keys = 1`, `provider_connections = 32`, `combos = 5`). In addition, the historical prune executed `DELETE` statements in autocommit mode rather than a single joint transaction and logged postconditions rather than asserting them fail-closed.
   - Although all `1` `api_keys`, `32` `provider_connections`, and `5` `combos` survived the 2026-10-19 prune and `VACUUM` intact in `/app/data/storage.sqlite`, the historical pre-prune backup gap cannot be retrospectively repaired; a fresh host snapshot of the current 32-provider compacted database must be captured in `~/.omniroute/snapshots/` under `/usr/bin/lockf -k -t 0 ~/.omniroute/update.lock`.
5. **CLI Daemon Verification vs. Local Bridge Metadata**:
   - Upstream `omniroute status` (`bin/cli/commands/status.mjs:35-95`) never contacts the running server; it reads local `package.json` and local `DATA_DIR/storage.sqlite` (which under `~/.local/bin/omniroute`'s isolated `/tmp/omniroute-cli-bridge-*` always reports `database.exists: false`). Similarly, upstream `omniroute keys list` (`bin/cli/commands/keys.mjs:214-240`) probes `/api/v1/providers/keys` (HTTP 404 on v3.8.51) and falls back to opening the empty local bridge SQLite file.
   - To prevent false-green local metadata or empty bridge fallbacks, `~/.local/bin/omniroute` is hardened so `omniroute status` queries live `/api/monitoring/health` + `/api/omniroute/status` (failing non-zero when the daemon is unreachable while resolving package version from `/Users/androidteam/Omniroute`) and `omniroute keys list` queries canonical `GET /api/providers?limit=5000` filtered to `authType === "apikey" && apiKey` (returning masked `{id, provider, name, isActive, maskedKey}` metadata and failing closed non-zero when unreachable), alongside native remote-backed commands `omniroute health --json`, `omniroute quota status`, and `omniroute combo list --output json`.

## Goals / Non-Goals

**Goals:**
- Keep `omniroute-base` startup non-blocking and prevent `healthCheckWorker.ts` `BEGIN IMMEDIATE` write-lock stalls via `DB_HEALTHCHECK_STARTUP_DEFERRED_ENABLED=true` and `OMNIROUTE_SKIP_DB_HEALTHCHECK=1` in `~/Omniroute/docker-compose.override.yml`, paired with a 6-hour bounded read-only full `PRAGMA integrity_check` (`~/.omniroute/integrity-last-ok`) in `omniroute-watchdog.sh`.
- Maintain reclaimed `omniroute_omniroute-data` storage (~1.07–1.11 GB `storage.sqlite`, 0 orphaned in-volume backups, dual flat + dotted `databaseSettings` retention keys `conversationTurnNodes = 7`, `quotaSnapshots = 14`, `callLogs = 30`), and capture a fresh post-compaction 32-provider host backup in `~/.omniroute/snapshots/`.
- Replace all PID/epoch/age/unlink lock handling in `~/Developer/scripts/omniroute-watchdog.sh`, its provenance mirror `platform/openspec-store/scripts/omniroute-watchdog.sh`, and `~/Omniroute/scripts/update.sh` with macOS native `/usr/bin/lockf -s -t 0 9` on persistent FD `9` (`~/.omniroute/update.lock`), holding the lock across the entire watchdog or updater lifecycle.
- Harden `~/Omniroute/scripts/update.sh` so temporary container snapshots are cleaned up before FD `9` lock release, probes/backups are bounded with `gtimeout` (`run_bounded`), Gate 1 fails closed if host `PRAGMA wal_checkpoint(TRUNCATE)` does not return `0|*` (`busy == 0`) before removing `-wal`/`-shm` sidecars and re-verifies post-checkpoint `PRAGMA quick_check = ok`, and `{readonly:true, timeout:15000}` is documented accurately as SQLite's `busy_timeout`.

**Non-Goals:**
- Editing upstream-tracked source files in `~/Omniroute/src/` or `~/Omniroute/open-sse/`.
- Building local Docker images instead of using official `diegosouzapw/omniroute` images.
- Retrospectively fabricating a pre-prune 2026-10-19 backup; historical evidence is preserved accurately and supplemented with a fresh post-compaction host backup.

## Decisions

### 1. Existing Patterns Referenced
- **Deployment Override (`~/Omniroute/docker-compose.override.yml`)**: Extend `services.omniroute-base.environment` alongside `NODE_OPTIONS=--max-old-space-size=4096`.
- **Upstream Child-Worker Healthcheck (`src/lib/db/core.ts:952-977,1373-1383`, `src/lib/db/healthCheckWorker.ts:22-35`)**: Use `DB_HEALTHCHECK_STARTUP_DEFERRED_ENABLED=true` and `OMNIROUTE_SKIP_DB_HEALTHCHECK=1` (global managed-health `quick_check` skip) so `autoRepair` never runs `PRAGMA quick_check` inside `BEGIN IMMEDIATE`.
- **Script Provenance Manifest (`platform/openspec-store/config/script-provenance-manifest.tsv:30`)**: Mirror any change to `/Users/androidteam/Developer/scripts/omniroute-watchdog.sh` byte-for-byte to `/Users/androidteam/Developer/platform/openspec-store/scripts/omniroute-watchdog.sh` and verify zero SHA-256 drift across all 8 tracked scripts.

### 2. Native Kernel Descriptor Lock Protocol (`/usr/bin/lockf` on `~/.omniroute/update.lock`) & Watchdog Step 3 Integrity Check
- **Persistent Inode & FD `9` Acquisition**:
  - `~/.omniroute/update.lock` is a persistent lock file created under `umask 077` and opened for append on file descriptor `9` (`exec 9>>"$LOCK_FILE"`). It is **never** unlinked (`rm -f`) and stores no PID or timestamp metadata; arbitrary or legacy file contents/mtime are ignored by the kernel lock.
  - Calling `/usr/bin/lockf -s -t 0 9` acquires a non-blocking BSD `flock(2)` exclusive lock on FD `9` held until FD `9` closes or the shell exits (`EX_TEMPFAIL = 75` on contention). Child commands in `omniroute-watchdog.sh` close FD `9` (`9>&-`) so spawned helpers cannot hold the lock past parent exit.
- **Watchdog Full-Cycle Serialization & Step 3 6-Hour Read-Only `PRAGMA integrity_check` (`omniroute-watchdog.sh`)**:
  - **Step 0 (Lock)**: Opens `~/.omniroute/update.lock` on FD `9` and runs `/usr/bin/lockf -s -t 0 9`. On `rc == 75`, logs skip and exits `0`; on any other non-zero exit code, logs `ERROR` and fails closed non-zero.
  - **Steps 1 & 2 (Daemon & Container Recovery)**: Verifies `docker info` (invoking `docker-service.sh start` with `9>&-` if needed) and probes `http://127.0.0.1:20128/healthz` (restarting or bringing up `omniroute-base` with `9>&-` when unhealthy or stopped outside `starting`).
  - **Step 3 (Periodic 6-Hour Read-Only Full `PRAGMA integrity_check`)**: Executed **only** when `omni_status == "running"`, `omni_health != "starting"`, and `/healthz` returns HTTP 200 (while still holding FD `9`). Inspects `~/.omniroute/integrity-last-ok` mtime via `stat -f %m`; when missing or age `>= 21600` seconds (6 hours), runs `gtimeout --signal=TERM --kill-after=5s 120s docker exec omniroute node -e ...` (with `9>&-`), which spawns an in-container child process bounded to `timeout: 110000, killSignal: 'SIGKILL'` opening `/app/data/storage.sqlite` via `better-sqlite3` (`{readonly:true, fileMustExist:true, timeout:15000}`) and evaluating `db.pragma('integrity_check')` (requiring all rows `=== 'ok'`, no `autoRepair`, printing summary `'ok'` only). On pass, updates `~/.omniroute/integrity-last-ok`; on failure or timeout, logs `ERROR` and exits non-zero **without** restarting the healthy gateway.
- **Updater Lock, Pre-Release Cleanup Trap & Fail-Closed Checkpoint (`update.sh`)**:
  - After Gate 0 (`~/.omniroute/update-available` exists) and argument validation, `update.sh` opens `exec 9>>"$LOCK_FILE"` (`umask 077`) and runs `/usr/bin/lockf -s -t 0 9` before `pre-state`. On `rc == 75`, it logs active lock contention, retains `$FLAG_FILE`, and exits `1`; on any other lock error, it fails closed non-zero.
  - Once locked, `cleanup_update` (`trap cleanup_update EXIT`) captures the original exit status (`local exit_rc=$?`), removes in-container `/tmp/${SNAPSHOT_NAME}` **before** shell exit releases FD `9`, and exits `$exit_rc` without unlinking `~/.omniroute/update.lock` or parsing PID ownership.
  - Gate 1 bounds `docker` and host `sqlite3` calls with `gtimeout` (`run_bounded`), documents `{readonly:true, timeout:15000}` as SQLite `busy_timeout`, verifies host `PRAGMA wal_checkpoint(TRUNCATE)` outputs `0|*` (`busy == 0`) before removing `-wal`/`-shm` sidecars (failing closed and retaining sidecars on checkpoint failure), re-verifies post-checkpoint host `PRAGMA quick_check = ok`, and retains verified snapshots in `~/.omniroute/snapshots/`.
- **Manual Offline Maintenance Pattern**:
  - Operators and automation executing offline container/SQLite maintenance invoke `/usr/bin/lockf -k -t 0 ~/.omniroute/update.lock <command>`, holding the kernel lock on the persistent inode (`-k` prevents `lockf` from unlinking the file) for the duration of `<command>`.

### 3. SQLite Storage Reclamation, Volume Ownership & Transaction Boundaries
- **Docker Volume & UID Invariant**:
  - Compose volume `omniroute-data` maps to Docker Engine volume **`omniroute_omniroute-data`**, with `/app/data` owned by UID:GID **`1000:1000`** (`node:node`). One-shot maintenance commands MUST run with `--user 1000:1000` against `omniroute_omniroute-data:/app/data`.
- **`better-sqlite3` `timeout: 15000` Semantics vs. Wall-Clock Bounds**:
  - Passing `{ readonly: true, timeout: 15000 }` configures SQLite's `PRAGMA busy_timeout = 15000` (waiting up to 15 seconds for conflicting locks to clear), not a wall-clock execution limit once a scan starts; wall-clock execution bounds are enforced via host `gtimeout` and Node `spawnSync(..., { timeout })`.
- **ISO-8601 Timestamp Cutoff & Dual Flat + Dotted `key_value` Upsert**:
  - Pruning queries bind JavaScript `new Date(Date.now() - days * 86400000).toISOString()` (`'YYYY-MM-DDTHH:MM:SS.sssZ'`) so ASCII collation matches `'T'` timestamps accurately.
  - Both flat legacy keys (`conversationTurnNodes`, `quotaSnapshots`, `callLogs`) and canonical dotted keys (`retention.conversationTurnNodes`, `retention.quotaSnapshots`, `retention.callLogs`) are upserted in `key_value` (`namespace = 'databaseSettings'`).
- **Transaction & Fail-Closed Assertion Boundaries**:
  - **Pre-Maintenance Snapshot & Checkpoint Boundary**: Under `/usr/bin/lockf`, capture a fresh host snapshot via `db.backup('/tmp/<snapshot>.sqlite')` and `docker cp` to `~/.omniroute/snapshots/<snapshot>.sqlite`, verify host `sqlite3 ... "PRAGMA quick_check;"` equals `ok`, require `sqlite3 ... "PRAGMA wal_checkpoint(TRUNCATE);"` to return `0|*` (failing closed if non-zero) before removing `-wal` and `-shm` sidecars, and re-verify `PRAGMA quick_check = ok`.
  - **Joint Pruning Transaction Boundary**: Inside the stopped/offline maintenance window, execute the `databaseSettings` upserts and the `DELETE` statements on `conversation_turn_nodes`, orphaned `agentic_conversations`, and `quota_snapshots` inside a single explicit `db.transaction(...)` (`BEGIN IMMEDIATE ... COMMIT`).
  - **Offline Compaction & Postcondition Assertion Boundary**: Execute `PRAGMA wal_checkpoint(TRUNCATE); VACUUM;` outside the transaction, then programmatically assert (`process.exit(1)` on mismatch) that `PRAGMA quick_check === 'ok'`, file ownership is `1000:1000`, and `api_keys`, `provider_connections`, and `combos` counts are `>=` pre-maintenance baselines.

## Risks / Trade-offs

- **[Risk] Child processes spawned by `omniroute-watchdog.sh` inherit open FD `9`** → **Mitigation**: Close `9>&-` on child command invocations in `omniroute-watchdog.sh` and remove `/tmp/${SNAPSHOT_NAME}` in `update.sh` before shell exit closes FD `9`.
- **[Risk] Out-of-band `PRAGMA integrity_check` hangs or detects corruption while gateway is serving traffic** → **Mitigation**: Run strictly read-only (`readonly: true, fileMustExist: true, timeout: 15000`, no `autoRepair`) inside an isolated child process bounded to `110s` (`SIGKILL`) and outer `gtimeout 120s`, only every 6 hours (`~/.omniroute/integrity-last-ok`), and log/exit non-zero on failure without restarting an otherwise healthy container.
- **[Risk] Historical 2026-10-19 prune used a 2026-10-03 (20-provider) snapshot rather than a fresh 32-provider pre-prune snapshot** → **Mitigation**: Preserve the historical record accurately without fabricating a retroactive pre-prune snapshot, and capture a fresh post-compaction host snapshot of the live 32-provider database in `~/.omniroute/snapshots/` under `/usr/bin/lockf -k -t 0 ~/.omniroute/update.lock`.
