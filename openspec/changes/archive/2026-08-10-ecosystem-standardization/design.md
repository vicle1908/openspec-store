# Design: ecosystem-standardization

## Context

The agent ecosystem (agent-core, agent-harness, agent-docs-sync) was audited for inconsistencies from parallel development. An initial gap list was proposed, then validated by multiple agents independently.

## Validated Findings

### Coverage Config — Already Aligned

All three repos have identical `[tool.coverage.run]` in pyproject.toml:
```toml
[tool.coverage.run]
source = ["src"]
omit = ["tests/*", "**/__pycache__/*"]
```

Initial report that docs-sync was missing this was incorrect — it was present at lines 98-100.

### Typer Versions — Already Aligned

All three repos pin `typer>=0.25.1`. No version drift.

### Build Artifacts — One Remaining Gap

`agent-core/src/reports-out/` contains 324 tracked daily report files (blocked-*, wip-age-*). These are:
- Orphaned: no Python code or Makefile target references them
- Not gitignored: tracked in git history
- Generated: timestamped daily reports from a now-removed workflow

**Action:** Remove from git, add to .gitignore.

### Documentation — Not Duplicates

- **CLAUDE.md**: Auto-generated by GitNexus with repo-specific content (symbol counts, resource URIs). Not a consolidation target.
- **AGENTS.md**: Each repo has distinct instructions matching its role. Not duplicates.

### graphify-out/ — Intentionally Tracked

All three repos track graphify-out/ per explicit .gitignore comments. This is by design, not a gap.

## Decision

The only actionable gap within the ecosystem-standardization scope is removing `src/reports-out/` from agent-core. All other proposed items are either already closed or validated as non-gaps.

## Scope Exclusion

Repos outside the agent ecosystem (code-daily-scan, jira-epic-report, jira-skill, tdt-core, tdt-observability) lack `[tool.coverage]` config but are not in scope for this change. They can be addressed in a separate standardization effort if needed.
