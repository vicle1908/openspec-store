# Design: Persist Agent TCC Provenance and Skill Surface Hygiene Across Automated Toolchain Upgrades

## Overview

This design specifies the cross-repository and host architecture to maintain macOS TCC provenance (`Accessibility`, `ScreenCapture`, `SystemPolicyAllFiles`) and clean workspace skill surfaces (`sync-workspace-agent-skills.py --check`) across automated daily maintenance runs while keeping `scripts/tcc_provenance.py` lean and strictly fail-closed.

## Problem Statement & Verified Invariants

1. **SIP, `SecurityAgent`, and `tccd` (`TCCDAccessIdentity`) Attribution Invariants**:
   - `SecurityAgent` and `LocalAuthentication` (`LAAuthenticationSheetController`) gate interactive modifications in `System Settings > Privacy & Security`, and macOS System Integrity Protection (SIP) blocks direct SQLite writes to `/Library/Application Support/com.apple.TCC/TCC.db` (`SF_RESTRICTED`) even under `root`.
   - Disassembly of `/System/Library/PrivateFrameworks/TCC.framework/Support/tccd` (`-[TCCDAccessIdentity initWithAttributionChain:...]`, `0x10002736c`–`0x100028290`) confirms how macOS attributes TCC requests:
     - **Responsible-Process Inheritance (`responsible_path`)**: When a coding agent CLI (`claude`, `omp`, `node`, `opencode`, `goose`, `kimi`, `uv`, `python3`) executes inside an `Orca` (`Orca Terminal Host.app` / `Orca.app`), `Herdr` (`herdr server`), or `Python.app` (`org.python.python`) supervised session, `tccd` attributes the TCC check to the **responsible parent supervisor**. Conversely, when a CLI is launched directly from `launchd` without an authorized supervisor parent, `tccd` evaluates the CLI's own `client_type = 1` resolved path (`proc_pidpath`).
     - **`client_type = 0` (Bundle ID) vs. `client_type = 1` (Absolute Path)**: `tccd` checks `NSURLIsApplicationKey` (`0x1000280d8`). Application bundles (`Orca.app` / `Orca Terminal Host.app` `com.stablyai.orca`, `Orca Computer Use.app` `com.stablyai.orca.computer-use`, and Homebrew's `.../Resources/Python.app` `org.python.python`) are keyed by `client_type = 0` (`CFBundleIdentifier`) and preserve TCC grants across versioned directory changes as long as their `csreq` certificate matches (`TeamIdentifier = 6CX3WHS9HZ` for Orca; `Developer Agent Code Signing` `H"65340d85afd298131c682d8463087891292a2b59"` for `Python.app`). Bare Mach-O binaries (`NSURLIsApplicationKey = NO`) are keyed by `client_type = 1` (`proc_pidpath`).
2. **`NSOpenPanel` Dot-Extension UTType Rejection for Versioned Binaries (`2.1.310`, `python3.15`)**:
   - In `System Settings > Privacy & Security > Screen & System Audio Recording`, the `+` (`NSOpenPanel`) file picker filters selectable items by UTType (`public.unix-executable` / `com.apple.application-bundle`). Because `2.1.310` and `python3.15` contain dots (`.310`, `.15`), `LaunchServices` (`mdls -name kMDItemContentType`) classifies them as dynamic document UTTypes (`dyn.ah62d4rv4ge8xgqmu` / `dyn.ah62d4rv4ge8xcrk`) rather than `public.unix-executable`, leaving the `Open` button disabled unless temporarily renamed to a dotless filename (`claude_2_1_310` / `python315`) while selecting and rename-restored immediately before clicking `Open`.
3. **Unlinked `goose` Shadow Binary vs. Homebrew Cellar Link**:
   - Restoring `/opt/homebrew/bin/goose` via `brew unlink block-goose-cli && brew link --overwrite block-goose-cli` points `/opt/homebrew/bin/goose` back to `/opt/homebrew/Cellar/block-goose-cli/1.56.0/bin/goose`, signed with `Developer Agent Code Signing` so it holds valid `Accessibility` and `ScreenCapture` grants in `TCC.db`.
4. **Dual-Runner Execution & Script Provenance Contract**:
   - In `MODE=apply`, `~/Developer/scripts/workstation-daily-update.sh:494-502` invokes `uv run --directory ~/Developer/shb/shb-schedule shb-schedule run-now workstation-daily-update` (`shb/shb-schedule/src/shb_schedule/workflows/workstation_update.py`) and returns `0`.
   - Furthermore, `step_integrity_and_store_validation()` verifies that `~/Developer/scripts/workstation-daily-update.sh` matches `platform/openspec-store/scripts/workstation-daily-update.sh` and `config/script-provenance-manifest.tsv`.
5. **LaunchAgent Responsible-Process FDA Attribution (`com.developer.workstation-daily-update.plist`)**:
   - Previously, `~/Library/LaunchAgents/com.developer.workstation-daily-update.plist` set `ProgramArguments[0] = "/bin/bash"`, which lacked `kTCCServiceSystemPolicyAllFiles` (Full Disk Access) and caused scheduled `08:00` runs (`data/updates/2026-10-22.json`, `2026-10-24.json`) to fail with `tcc_provenance: "ERROR" (TCC.db not readable)`.
   - Live testing in `gui/502` proved that setting `ProgramArguments[0] = "/opt/homebrew/opt/python@3.15/Frameworks/Python.framework/Versions/3.15/Resources/Python.app/Contents/MacOS/Python"` (`CFBundleIdentifier = org.python.python`, `client_type = 0`, signed with `Developer Agent Code Signing`) attributes the entire LaunchAgent job tree to `org.python.python` (`TCC_READABLE = True`), preserving Full Disk Access across all future Homebrew Python patch upgrades without weakening Darwin `ERROR` fail-closed semantics to `SKIPPED`.
6. **`skills update -y` Recreating `~/Developer/data/skills`**:
   - `/opt/homebrew/Cellar/skills/1.7.2/libexec/lib/node_modules/skills/dist/cli.mjs:7958` checks `existsSync(join(cwd, "data"))`. Because `~/Developer/data` exists (storing `data/updates/*.json`), `skills update -y` recreates `~/Developer/data/skills` (`AstrBot` surface) on every run, causing `sync-workspace-agent-skills.py --check` to exit `1` (`surface_violations=data/skills`).

## Architectural Decisions

### 1. Local Code-Signing Authority, Direct 9-Identity TCC Enrollment & Zero-YAGNI Fail-Closed Verification
- **Certificate**: `CN=Developer Agent Code Signing`, SHA-1 leaf anchor `H"65340d85afd298131c682d8463087891292a2b59"`, trusted for Code Signing in `~/Library/Keychains/login.keychain-db`.
- **Target Handling & Post-Upgrade Signing**:
  - **`goose`**: Enforce `brew link --overwrite block-goose-cli` whenever `/opt/homebrew/bin/goose` is missing, a broken symlink, or a non-symlink file (`not is_symlink() or not exists()` / `! -L || ! -e`), and sign the resolved Homebrew Cellar binary (`1.56.0`) with `Developer Agent Code Signing`.
  - **`org.python.python` (`client_type = 0`) & `python3`**: Sign `/opt/homebrew/opt/python@3.15/Frameworks/Python.framework/Versions/3.15/Resources/Python.app` (`--identifier org.python.python --deep`) and `python3` (`--identifier org.python.python3`) with `Developer Agent Code Signing` after Homebrew upgrades so `org.python.python`'s `client_type = 0` bundle grant in `TCC.db` (`Accessibility`, `ScreenCapture`, `SystemPolicyAllFiles`) remains valid across all Homebrew patch revisions (`3.15.0_1`+).
- **Strict Direct Verification in `scripts/tcc_provenance.py` (Zero Dead Parameters)**:
  - Keep `scripts/tcc_provenance.py` lean, unchanged, and strictly read-only (`mode=ro`, zero system mutations): every target in the 9-identity workstation set (`omp`, `node`, `opencode`, `goose`, `claude`, `kimi`, `herdr`, `python3`, `org.python.python`) must satisfy its own direct `TCC.db` record (`auth_value = 2` and `SecStaticCodeCheckValidity = 0`) for every required service.
  - **No Unattributed Supervisor Masking**: The presence of authorized `com.stablyai.orca`, `herdr`, or `org.python.python` rows in `TCC.db` never causes a standalone or `launchd`-spawned CLI to pass verification when its own `client_type = 1` row is missing or denied.

### 2. Dual-Runner Hook Synchronization & `Python.app` LaunchAgent FDA Supervision
- Implement unconditional post-Homebrew and post-Agent-CLI `sign_agent_binaries()` (`Python.app`, `python3`, `goose` via `brew link --overwrite block-goose-cli`) and post-`skills update` surface pruning in **both**:
  1. `/Users/androidteam/Developer/shb/shb-schedule/src/shb_schedule/workflows/workstation_update.py` (`step_homebrew_update` / `step_agent_cli_update` and `step_skills_refresh`), and
  2. `/Users/androidteam/Developer/platform/openspec-store/scripts/workstation-daily-update.sh` (mirrored to `/Users/androidteam/Developer/scripts/workstation-daily-update.sh` with matching SHA-256 in `config/script-provenance-manifest.tsv`).
- Update `~/Library/LaunchAgents/com.developer.workstation-daily-update.plist` so `ProgramArguments` invokes `/opt/homebrew/opt/python@3.15/Frameworks/Python.framework/Versions/3.15/Resources/Python.app/Contents/MacOS/Python -c "import subprocess; raise SystemExit(subprocess.call(['/bin/bash', '/Users/androidteam/Developer/scripts/workstation-daily-update.sh']))"`. Because `Python.app` (`org.python.python`, `client_type = 0`) holds Full Disk Access and is re-signed automatically on upgrade, scheduled `08:00` runs read `TCC.db` directly without any `SKIPPED` workaround, preserving `openspec/specs/workstation-remote-and-agent-permissions/spec.md`'s requirement that Darwin TCC errors must never be classified as skips.
- Add `has_unaligned_authority_drift(auth_rec, manifest_rec) -> bool` and `Reconciled Authority Status: RECONCILED|DRIFT_DETECTED` to `scripts/inventory-workstation-toolchain.py` so Stage 9 of `workstation-daily-update.sh` reconciles `authority_reconciliation` against `manifest_reconciliation` in a single pass (matching `workstation_update.py:1028-1105` without spawning a redundant `--json` subprocess) while keeping Stage 12 strict (`openspec validate --all --strict --store openspec-store`).

### 3. Automated `data/skills` Pruning & Snapshot Manifest Refresh
- Update `sync-workspace-agent-skills.py` (in default reconciliation mode `not args.check` as well as `--accept-refresh` and `--bootstrap-snapshot`), `workstation_update.py:step_skills_refresh()`, and `workstation-daily-update.sh` to automatically remove unallowlisted `~/Developer/data/skills` and `~/Developer/agent/skills` symlink trees created by `skills update -y` before running surface parity validation.
- Execute `python3 scripts/sync-workspace-agent-skills.py --bootstrap-snapshot` so `/Users/androidteam/Developer/.agents/.skill-snapshots/{current,previous}/manifest.json` is refreshed with current skill hashes and `files + lock` `total_bytes`.

### 4. `uv` Python `3.14.9` Standardization, `uv tool upgrade --all` & `pyproject.toml` Clean-Break Alignment
- Preserve `scripts/tcc_provenance.py`'s read-only contract by keeping `sign_agent_binaries()` in `workstation-daily-update.sh` and `workstation_update.py` signing only the 3 TCC-enrolled targets (`Python.app`, Homebrew `python3`, and `goose`) without touching `uv`'s managed Python binary.
- Run `uv python upgrade` inside both `workstation_update.py:step_uv_tools_update()` and Stage 4 of `workstation-daily-update.sh` (alongside `uv tool upgrade --all`, upgrading `cpython-3.14.5-macos-aarch64-none` to `cpython-3.14.9-macos-aarch64-none`), reinstall `tavily-cli` onto `uv`-managed Python `3.14` (`uv tool install --reinstall --python 3.14 tavily-cli`), remove unused `uv` Python `3.11`/`3.12` (`~/.local/bin/python3.11`), and uninstall zero-dependent Homebrew legacy Python formulae (`python@3.10`, `python@3.11`, `python@3.12`) so `obsolete_candidate_count == 0`.
- Standardize `platform/openspec-store/pyproject.toml` (`[tool.uv]` with `package = false` and `python-preference = "only-managed"`, `testpaths = ["tests", "scripts/test-version-authority-governance.py"]`, `-p no:cacheprovider`), remove `<3.15` upper bounds (`requires-python = ">=3.14"`) in `tdt/tdt-core/pyproject.toml` and `ai-tooling/workspace-python-template/pyproject.toml` (with `package = false` under `[tool.uv]`), align `ai-tooling/wiki-mcp-server/pyproject.toml` (`requires-python = ">=3.14"`, `[tool.uv]`), and run `uv lock --upgrade && uv sync` across all 5 target repositories.

## Transaction Boundaries

- **Central OpenSpec Store (`/Users/androidteam/Developer/platform/openspec-store`)**: `scripts/workstation-daily-update.sh`, `scripts/inventory-workstation-toolchain.py`, `scripts/sync-workspace-agent-skills.py`, `config/script-provenance-manifest.tsv`, and unit tests (`scripts/test-version-authority-governance.py`) are committed atomically in `openspec-store`.
- **SHB Scheduler Repository (`/Users/androidteam/Developer/shb/shb-schedule`)**: `src/shb_schedule/workflows/workstation_update.py` and `tests/test_workstation_update_workflow.py` are committed in `shb/shb-schedule`.
- **Host Environment (`/Users/androidteam`)**: Keychain signing, `brew link --overwrite block-goose-cli`, `~/Library/LaunchAgents/com.developer.workstation-daily-update.plist`, `~/Developer/scripts/workstation-daily-update.sh` sync, `~/Developer/data/skills` removal, `.skill-snapshots` bootstrap, and `TCC.db` verification are verified on the live host and recorded with SHA-256 digests in `evidence.md`.
