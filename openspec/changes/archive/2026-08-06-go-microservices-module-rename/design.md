# Design: go-microservices Module Rename & Assessment Infrastructure

## Architecture

### Module Path Rename Strategy

The rename follows a bottom-up approach:

1. **Foundation**: `tests/ecosystem-verification/go.mod` (module path + replace directives)
2. **Services**: Each service's `go.mod` (require + replace for ecosystem-verification)
3. **Platform**: `platform/go.mod` (require + replace)
4. **Scripts**: `scripts/validation/go.mod`, `scripts/composeevidence/go.mod`
5. **Go Source**: All `.go` files with import statements
6. **Go Sum**: All `.go.sum` files (regenerated by go mod tidy)

### GitNexus Name Resolution

GitNexus derives repo name from `git remote get-url origin`, not directory name.
The fix uses path-based `--repo` flags instead of basename, which is more robust
across different naming conventions.

### Assessment Infrastructure

The assessment system uses three knowledge modalities for validation:
- **graphify** (CLI): AST-level structural analysis
- **GitNexus** (MCP): Semantic analysis with impact/context queries
- **LLM Wiki** (MCP): Curated knowledge pages

Monthly cron runs comprehensive checks and generates dated reports.

## Trade-offs

### Preserving Archived Specs

Archived OpenSpec specs retain the old `microservices` name intentionally.
These are historical records and changing them would break audit trails.
Active specs are updated to reflect the new naming.

### Go Module Replace Directives

All services use `replace` directives pointing to local paths
(`../../tests/ecosystem-verification`). These paths don't change with
the module rename, so only the module path string needs updating.

### Docker/K8s Namespace Changes

Production namespaces change from `microservices` to `go-microservices`.
This requires coordinated deployment across all environments.
Staging uses `go-microservices-staging`, production uses `go-microservices`.

## Risk Assessment

- **Low risk**: Go module paths are internal references, not external APIs
- **Low risk**: Assessment infrastructure is additive (new files/targets)
- **Medium risk**: K8s namespace changes require deployment coordination
- **Mitigation**: All builds pass, GitNexus re-indexed, pre-commit hook verified

## Implementation Notes

- Used `sed -i ''` for bulk replacements (macOS BSD sed syntax)
- Verified each surface independently (go.mod → Go imports → scripts → deploy)
- Ran `go build ./...` on platform, order-service, and ecosystem-verification
- Re-indexed GitNexus after rename to ensure correct name resolution
