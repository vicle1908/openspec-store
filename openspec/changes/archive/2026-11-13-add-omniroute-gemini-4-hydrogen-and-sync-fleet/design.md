# Design

## Context

See `proposal.md` — Why for problem motivation. Two developer workstations share the single OmniRoute (`v3.8.53`) gateway container (`omniroute` backed by Docker named volume `omniroute_omniroute-data`) on `iosteam-mac-mini`:
1. **`iosteam-mac-mini` (`100.70.16.83`, `/Users/androidteam`, `--store openspec-store`)**: Hosts OmniRoute (`127.0.0.1:20128` / `127.0.0.1:20129`), `omp/18.20.0`, and 14 companion coding CLIs/editors.
2. **`macbook-pro-m5` (`macbook-pro-ca-l-1`, `100.106.143.78`, `/Users/vinhlk`, `--store shb-specs`)**: Consumes OmniRoute over Tailscale Serve (`https://iosteam-mac-mini.tailc6b508.ts.net`) and currently holds validated active change `add-omniroute-gemini-4-hydrogen-combo-and-config` (`0/11` tasks applied, awaiting `/opsx:apply`).

Live `storage.sqlite` inspection on `2026-11-13` established four constraints shaping this design:
- **Upstream Hydrogen Entitlements & Quota Family**: Google Cloud Code Assist (`v1internal`) exposes four separate tier endpoints (`gemini-4-hydrogen-{low,medium,high,xhigh}` -> `M527`, `M526`, `M525`, `M528`, `1,048,576` context, `262,144` max output tokens). Of the 14 active `agy` OAuth connections, 7 advertise Hydrogen without `-disabled` sentinels: active `g1-ultra-tier` `62af823b` (`95.53%` 5h / `71.20%` weekly, already background-synced at `2026-11-13T08:16:57Z`) plus 6 WTU `g1-pro-tier` accounts (`38782750` at `69.97%` 5h / `48.38%` weekly, `9c033d6f` at `~68%` 5h / `~45%` weekly, and `37f9924d`, `573e3f41`, `3f3085b1`, `a94216f4` resetting `2026-11-14T00:35Z`). Meanwhile, `0532bad4` and `338764b8` downgraded to `g1-pro-tier` (`excludedModels: ["carbon"]`, `gemini-4-hydrogen-disabled`).
- **`getAntigravityQuotaFamily` Behavior in `v3.8.53`**: `open-sse/services/antigravityQuotaFamily.ts:29` classifies `bare.startsWith("gemini-4")` as `"argon"`, folding `gemini_4_argon_weekly` (`0%` on all 6 WTU Pro accounts) into `selectAntigravityQuotaWindowNames()`. Under `strategy: "quota-weighted"`, `open-sse/services/combo/quotaStrategies.ts:913` (`entry.remainingPercent > 0`) drops all 6 WTU Pro accounts.
- **`POST /api/combos` Non-Idempotency**: `src/app/api/combos/route.ts:94-97` rejects duplicate combo names with `HTTP 400 { "error": "Combo name already exists" }`.
- **OMP Built-In vs Gateway Model IDs**: In `omp/18.20.0`, built-in `google-antigravity` exposes `gemini-4-hydrogen-{low,medium,high,xhigh}` (no bare `gemini-4-hydrogen`), whereas OmniRoute exposes top-level `gemini-4-hydrogen` alongside the four explicit tier combos.

## Goals / Non-Goals

**Goals:**
- Reuse the established pure-configuration pattern from `2026-11-11-scale-omniroute-concurrency-and-add-gemini-4-carbon` (`PATCH /api/model-capability-overrides`, `/api/combos`, `/api/context/combos/default-caveman/assignments`, surgical host config inserts with `0600` SHA-256 backups) with zero edits to git-tracked `~/Omniroute` files or `container-entrypoint-compat.sh`.
- Guarantee order-independent execution with `macbook-pro-m5` (`add-omniroute-gemini-4-hydrogen-combo-and-config`) via check-then-create/update gateway API calls and AgentMemory mesh (`:3111`) UUID synchronization.
- Reconcile `iosteam-mac-mini`-owned invariants that `macbook-pro-m5` intentionally leaves untouched (`19`-combo `default-caveman` assignments, Carbon downgraded-step spec accuracy, `iosteam-mac-mini` OMP `task` role + 14 companion CLI/editor catalogs).

**Non-Goals:**
- Patching `antigravityQuotaFamily.ts` across 21 compiled Next.js server chunks (would violate the zero-new-chunk-patch policy and break `strategy: "priority"` parity with `macbook-pro-m5`'s `tailscale-omniroute-gateway` spec).
- Direct SSH or Orca remote writes into `/Users/vinhlk/**` on `macbook-pro-m5`.

## Decisions

### Decision 1: Idempotent Upsert of WTU-Pro-First `priority` Tier Combos + `combo-ref` Top-Level Alias + 3 Combo-Scoped Effort Rules
- **Choice**:
  1. **Capability Overrides First (`Authorization: Bearer $OMNIROUTE_API_KEY`)**: Source `OMNIROUTE_API_KEY` from `~/.zshenv` (required on all `/api/*` and `/v1/models` loopback routes per `requireManagementAuth.ts:59-125`), execute `POST /api/providers/62af823b-f3d7-4e6b-87a9-98069167d4f6/sync-models`, `DELETE /api/resilience/model-cooldowns` with `{"all": true}` (`resilience/model-cooldowns/route.ts:52`), and 16 single-key `PATCH /api/model-capability-overrides` calls (`antigravity/gemini-4-hydrogen-{low,medium,high,xhigh}` × `{context_length: 1048576, max_input_tokens: 1048576, max_output_tokens: 262144, reasoning_efforts: "low,medium,high,xhigh"}`) **before** combo/rule creation. Verify inventory sync via `GET /api/providers/62af823b.../models` and override persistence via `GET /api/model-capability-overrides` + `GET /v1/models`.
  2. **Check-Then-Create/Update 5 Combos (Tier Combos First)**: Read `GET /api/combos`; for each target combo name, call `POST /api/combos` if missing or `PUT /api/combos/{id}` if already created by `macbook-pro-m5`:
     - First, the 4 tier combos `gemini-4-hydrogen-{xhigh,high,medium,low}` (`strategy: "priority"`, `context_length: 1000000`, `context_cache_protection: false`, `config: { maxRetries: 1, failoverBeforeRetry: true, retryDelayMs: 500, fallbackDelayMs: 0, targetTimeoutMs: 180000, handoffThreshold: 0.85, handoffModel: "", maxMessagesForSummary: 30, maxComboDepth: 3, trackMetrics: true, reasoningTokenBufferEnabled: true, zeroLatencyOptimizationsEnabled: true, hedging: false, fallbackCompressionMode: "off", predictiveTtftMs: 0, candidatePool: ["agy"], resetAwareQuotaCacheTtlMs: 300000, resetAwareQuotaCacheMaxStaleMs: 3600000, resetWindowQuotaCacheTtlMs: 300000, resetWindowQuotaCacheMaxStaleMs: 3600000 }`), ordered `[38782750, 9c033d6f, 62af823b, 37f9924d, 573e3f41, 3f3085b1, a94216f4]`.
     - Next, top-level `gemini-4-hydrogen` (`strategy: "priority"`, `context_length: 1000000`, `context_cache_protection: false`, the exact same `config` object, and `models: [{ kind: "combo-ref", comboName: "gemini-4-hydrogen-high" }]`).
  3. **Check-Then-Create/Update 3 Named Reasoning-Routing Rules**: Read `GET /api/settings/reasoning-routing-rules`; deduplicate by `(scope === "combo", comboId === hydrogenCombo.id, sourceEffort)` and call `POST /api/settings/reasoning-routing-rules` when absent or `PATCH /api/settings/reasoning-routing-rules/{id}` when present (`PUT` returns `405` on `[id]/route.ts:27`) with required `name: "gemini-4-hydrogen-{low,medium,xhigh}"` (`reasoningRouting.ts:26`), `sourceEffort: "low" | "medium" | "xhigh"`, `targetKind: "combo"`, `targetComboId: tierCombo.id`, `effortMode: "inherit"`, `enabled: true`.
  4. **19-Combo `default-caveman` Assignment**: Call `PUT /api/context/combos/default-caveman/assignments` with strict Zod payload `{"routingComboIds": [<19 active combo UUIDs>]}` (`assignments/route.ts:11-15`).
- **Rationale**:
  - Applying `reasoning_efforts` capability overrides ahead of reasoning-routing rules ensures `src/lib/modelCapabilities.ts:696` resolves `supportsThinking: true` (`reasoningEfforts: ["low","medium","high","xhigh"]`), preventing `resolveCapability()` (`src/lib/reasoningRouting/policy.ts:451-474`) from returning `"unknown"` during `/api/settings/reasoning-routing-rules/simulate`.
  - Ordering WTU Pro `38782750` (`69.97%` 5h) and `9c033d6f` (`~68%` 5h) ahead of Ultra `62af823b` (`95.53%` 5h) protects `62af823b` (currently the sole active Ultra account serving `gemini-4-carbon*` and `gemini-4-argon*`) from 8-way `modelRoles.task` subagent bursts while matching `macbook-pro-m5`'s post-review step order. Setting `config.failoverBeforeRetry: true` activates `failoverBeforeRetryExplicit` (`open-sse/services/comboConfig.ts:357-364`, `executeTargetAttempt.ts:1158`), skipping same-account `retryDelayMs` sleep whenever a sibling step exists so concurrent `429`s on Step 1 (`38782750`) fail over immediately (`0 ms`) to Step 2 (`9c033d6f`) while keeping `maxRetries: 1` (`retryDelayMs: 500`) on the final step.
  - Using `combo-ref` on `gemini-4-hydrogen` avoids duplicating the 7 connection UUIDs while `resolveNestedComboTargets()` (`src/app/api/v1/models/catalog.ts:611`) propagates `max_output_tokens: 262144` into `/v1/models`, and passing the identical `config` object on `gemini-4-hydrogen` ensures default `"high"` calls expanded under default `nestedComboMode: "flatten"` (`comboConfig.ts:138`, `combo.ts:853-861`) retain `targetTimeoutMs: 180000`, `failoverBeforeRetry: true`, `predictiveTtftMs: 0`, and the four `reset*QuotaCache*` keys required by `omniroute-compression-and-routing`.
- **Alternatives Considered**:
  - *`strategy: "quota-weighted"` with a new `container-entrypoint-compat.sh` chunk patch*: Rejected because `antigravityQuotaFamily` is duplicated across 21 Next.js chunks in `v3.8.53` and changing `strategy` away from `"priority"` would fail `macbook-pro-m5`'s `tailscale-omniroute-gateway` verification gate.
  - *Blind `POST /api/combos`*: Rejected because `src/app/api/combos/route.ts:95` fails with `HTTP 400 "Combo name already exists"` if `macbook-pro-m5` applies Wave 1 first.

### Decision 2: `iosteam-mac-mini` OMP Role Promotion (`task -> omniroute/gemini-4-hydrogen:high`) and 15-Client Fleet Catalog Parity
- **Choice**:
  - Follow the established `omniroute-fleet-model-catalog-rollout` and `omp-model-config-audit` patterns:
    - Stage and smoke-test `/Users/androidteam/.omp/agent/{models.yml,config.yml}` in an isolated profile (`OMP_CODING_AGENT_DIR` with read-only `.backup` of `agent.db`, `models.db`, `skill-descriptions.db`, `advisor.enabled: false`, `memory.backend: off`, and empty `fallbackChains`) before sequential atomic promotion (`mode 0600`).
    - Register all 5 combos (`gemini-4-hydrogen` + `gemini-4-hydrogen-{xhigh,high,medium,low}`) across `omp` and the 14 companion CLIs/editors (`pi`, `prime-agent`, `hermes`, `opencode`, `kilo`, `codex`, `kimi` under `omniroute-anthropic` with `support_efforts = ["low", "medium", "high"]`, `grok`, `goose`, `droid`, `claude` `omniroute-pm.json` across `modelOverrides` + `modelPicker.options`, `muse` across `model_reasoning_efforts` + `model_catalog`, `qwen`, `zed`), preserving `x-omniroute-no-memory: "true"`, client output-token caps (`262144` where supported; `65536` on `kimi-code`, `muse`, etc.), and companion startup defaults, and update `scripts/setup-macbook-omniroute-client.sh` (`openspec-store/scripts/` and `~/Developer/scripts/`) from `14` to `19` required combos.
- **Rationale**: Exposing both `gemini-4-hydrogen` (auto-dispatched by effort rules) and explicit `gemini-4-hydrogen-{xhigh,high,medium,low}` matches `iosteam-mac-mini`'s existing `gemini-4-argon{,-high,-medium,-low}` and `gemini-4-carbon{,-high,-medium,-low}` convention across all 15 tools while matching `macbook-pro-m5`'s `omniroute/gemini-4-hydrogen:high` `task` role.
- **Alternatives Considered**:
  - *Registering only bare `gemini-4-hydrogen` without explicit `-xhigh`/`-high`/`-medium`/`-low` entries*: Rejected on `iosteam-mac-mini` because Chat-Completions / fixed-effort clients (`goose`, `zed`, `droid`, `qwen`) benefit from direct tier-pinned combo IDs (`gemini-4-hydrogen-xhigh`, `-low`) without relying on client-side `reasoning_effort` flags.

### Decision 3: Transaction Boundaries, Backup Manifests, and Peer Mesh Handoff
- **Transaction Boundaries**:
  1. **OmniRoute SQLite (`omniroute_omniroute-data`)**: Backed up before mutation via `better-sqlite3` `.backup()` into `/Users/androidteam/.omniroute/snapshots/pre-hydrogen-fleet-<ts>.sqlite` (`mode 0600`, `PRAGMA quick_check = ok`, retaining `<= 5` snapshots per `omniroute-runtime-customization`). Each Bearer-authenticated (`Authorization: Bearer $OMNIROUTE_API_KEY`) REST mutation (`PATCH /api/model-capability-overrides`, `POST/PUT /api/combos`, `POST/PATCH /api/settings/reasoning-routing-rules`, `PUT /api/context/combos/default-caveman/assignments`) commits atomically inside OmniRoute's SQLite connection without container restart.
  2. **`iosteam-mac-mini` Host Dotfiles (`/Users/androidteam/.*`)**: Pre-mutation backups and `sha256-manifest.json` (`mode 0600`) written to `/Users/androidteam/.omniroute/backups/add-omniroute-gemini-4-hydrogen-and-sync-fleet/`. Each file verifies pre-write SHA-256 equality and replaces via atomic sibling temp-file rename (`fs.rename` / `os.replace`), restoring `0600` after `droid exec` if Factory Droid re-serializes `~/.factory/settings.json` to `0644`.
  3. **AgentMemory Mesh (`127.0.0.1:3111` <-> `100.106.143.78:3111`)**: Post-verification coordination step invokes Bearer-authenticated (`Authorization: Bearer $(cat ~/.agentmemory/secret)`) `POST /agentmemory/remember`, `POST /agentmemory/signals/send`, and bidirectional `POST /agentmemory/mesh/sync` on both peers so `macbook-pro-m5` sees the live gateway UUIDs and idempotent upsert note without `HTTP 401` rejections.

## Risks / Trade-offs

- **[Risk] Upstream `M528` (`gemini-4-hydrogen-xhigh`) handling of `thinkingConfig.thinkingLevel` clamping** → **Mitigation**: `open-sse/services/thinkingBudget.ts:65-88` maps budgets to `"low" | "medium" | "high"` while forwarding model ID `gemini-4-hydrogen-xhigh` (`M528`) verbatim. Task 2.4 runs protocol-exact live probes (`POST /v1/responses` with `max_output_tokens: 32768` + `reasoning.effort`, `POST /v1/chat/completions` with `max_completion_tokens: 32768` + `reasoning_effort`, and `POST /v1/messages` with `max_tokens: 32768` + `output_config.effort`) against both `gemini-4-hydrogen` (`"high"`) and `gemini-4-hydrogen-xhigh` (`"xhigh"`), confirming HTTP `200` and `call_logs` model attribution.
- **[Risk] Concurrent `/opsx:apply` on `macbook-pro-m5` running blind `POST /api/combos`** → **Mitigation**: `iosteam-mac-mini` uses idempotent name/rule-key upserts, matches `macbook-pro-m5`'s exact 5 combo names, 7-step WTU-first order, and 3 reasoning-routing rules, and immediately syncs the created UUIDs + `GET /api/combos` upsert guidance to `100.106.143.78:3111` via Bearer-authenticated AgentMemory mesh.
- **[Risk] `/v1/models` compressed response size (`<= 35,000` bytes invariant)** → **Mitigation**: Adding 5 combo entries adds `< 1 KB` gzipped; Task 2.4 explicitly asserts `curl --compressed` `size_download <= 35000`.
