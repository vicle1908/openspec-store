### Requirement: Cross-Workstation Gateway Coordination Signal Over AgentMemory Mesh
After provisioning or verifying Gemini 4 Hydrogen gateway combos, capability overrides, and reasoning-routing rules on `iosteam-mac-mini`, the workflow SHALL publish the canonical combo UUIDs and rule identifiers to peer workstation `macbook-pro-m5` via AgentMemory mesh synchronization.

#### Scenario: Peer workstation receives provisioned Hydrogen gateway UUIDs with zero mesh sync errors
- **WHEN** `iosteam-mac-mini` completes gateway Hydrogen combo and reasoning-routing provisioning and invokes Bearer-authenticated (`Authorization: Bearer $AGENTMEMORY_SECRET`) `POST /agentmemory/remember`, `POST /agentmemory/signals/send`, and bidirectional `POST http://127.0.0.1:3111/agentmemory/mesh/sync` + `POST http://100.106.143.78:3111/agentmemory/mesh/sync`
- **THEN** both mesh sync responses SHALL return HTTP `200` with `errors: []`
- **AND** the synchronized record SHALL list the exact 5 `gemini-4-hydrogen*` combo UUIDs, 19 `default-caveman` assignment UUIDs, and 3 named `scope: "combo"` reasoning-routing rule IDs so `macbook-pro-m5`'s `add-omniroute-gemini-4-hydrogen-combo-and-config` apply workflow can verify or upsert by name without `HTTP 400 "Combo name already exists"` collisions
