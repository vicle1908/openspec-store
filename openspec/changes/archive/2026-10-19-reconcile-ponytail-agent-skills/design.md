# Design

## Context

See `proposal.md` — Why for motivation.

An independent post-archive audit of `2026-10-19-adopt-ponytail-agent-skills` (archived at commit `c09d952a`) against live workstation and repository state identified six architectural and operational gaps that shape this corrective design:

1. **Hermes Loader Topology vs. Workspace Project Links**:
   - On this workstation, Hermes Agent (`~/.hermes/hermes-agent/agent/skill_utils.py`) loads skills from user profile scope (`~/.hermes/skills/`), configured `external_dirs`, and explicitly trusted nearest Git-root project skills.
   - Because `/Users/androidteam/Developer` is an umbrella workspace directory rather than a Git root, the relative symlinks created by `/opt/homebrew/bin/skills add` under `/Users/androidteam/Developer/.hermes/skills/ponytail*` are never loaded by Hermes at runtime.
   - Meanwhile, `platform/openspec-store/scripts/sync-workspace-agent-skills.py` currently reconciles user-scope symlinks only for Codex/standard `.agents` (`~/.agents/skills/` via `config/codex-user-skill-manifest.txt`) and Claude Code (`~/.claude/skills/` via `config/claude-user-skill-manifest.txt`). Existing host links for Grok (`~/.grok/skills/`) and Goose (`~/.config/goose/skills/`) exist outside the synchronizer and must be preserved without turning the synchronizer into an unbounded multi-agent installer.
2. **Skills CLI Single-Writer Lockfile Resolution, Target Fanout, and Blind Up-to-Date Checks**:
   - In `/opt/homebrew/bin/skills` v1.7.2 (`cli.mjs:1093`), `getLocalLockPath(cwd)` is hardcoded to `join(cwd, "skills-lock.json")`. Both `skills add` and `skills update -y` (invoked with `cwd=/Users/androidteam/Developer`) read and write `/Users/androidteam/Developer/skills-lock.json` exclusively.
   - `/Users/androidteam/Developer/.agents/skills-lock.json` (currently 60 entries matching the root lockfile) is referenced by workspace discovery specs and audits, but the Skills CLI never reads or updates it.
   - During `skills update -y`, the CLI scans `cwd` for agent directories and prints target headers such as `Updating for: Universal, AstrBot, Claude Code, Eve, Hermes Agent` depending on ambient directories or CLI version detection, so project updates cannot be assumed to touch only three static directories without a pre/post workspace surface inventory.
   - Furthermore, `skills update -y` compares the fetched upstream folder hash against `skills-lock.json`'s `computedHash` and prints `✓ All project skills are up to date` without hashing or inspecting local files under `/Users/androidteam/Developer/.agents/skills/`. Consequently, `computedHash` alone cannot restore deleted/corrupted local files or prove local-byte integrity.
3. **Refresh Outcome Parser Divergence and Pre-Mutation Drift Spec Conflict**:
   - **Specification and Shell runner** (`ecosystem-tooling-and-skills-upgrade/spec.md` requirement `Drift is observable before content is replaced` and `platform/openspec-store/scripts/workstation-daily-update.sh`, mirrored to `/Users/androidteam/Developer/scripts/workstation-daily-update.sh` under `config/script-provenance-manifest.tsv`): Both the existing main spec and script comments/output claim that `drift=1` is determined *before* any skill content is replaced. In reality, `skills update -y` has no `--dry-run` or `--check` flag and `Updated N skill(s)` / `✓ Updated <name>` are emitted *after* files are mutated. In addition, `classify_refresh` treats `Updated 0 skill(s)` as `drift=1`, fails to recognize `All global skills are up to date`, and suppresses `already_current=1` whenever `path_ambiguous > 0`.
   - **DBOS workflow step** (`/Users/androidteam/Developer/shb/shb-schedule/src/shb_schedule/workflows/workstation_update.py:step_skills_refresh`): Inspects `proc.stdout` only (ignoring `proc.stderr`), misses `Updated N skill(s)` in its `m_ref` regex (`(\d+)\s+skills?\s+(?:refreshed|updated)`), falls back to counting every match of `(?:refreshed|updated)\b` (which double-counts per-skill `✓ Updated <name>` lines plus the `Updated N skill(s)` summary line), misses `Multiple current paths match` for `path_ambiguous`, and sets `already_current = 1` on any zero exit code with `refreshed == 0`—even when CLI output is empty, ambiguity-only, or unrecognized.
4. **Specification Policy Conflicts and Unmodified Vendor Guidance**:
   - `workspace-topology-and-hygiene` forbids `/Users/androidteam/Developer/skills-lock.json`, directly contradicting `skills` CLI's hardcoded project registry path.
   - `workspace-openspec-skill-discovery` enforces a `<=60`-character description limit (`<=57`-character trigger) designed for internally authored skills, whereas upstream vendor skills (`DietrichGebert/ponytail`) ship folded YAML descriptions (`description: >`) whose actual YAML-decoded UTF-8 lengths are `142–371` bytes (including the folded block scalar trailing newline: `ponytail-gain` 142, `ponytail-help` 142, `ponytail-debt` 174, `ponytail-review` 292, `ponytail-audit` 295, `ponytail` 371 bytes) under the 1,024-byte `skill-index-hygiene` ceiling. Prior archived evidence (`2026-10-19-adopt-ponytail-agent-skills/evidence.md`) used a line-based regex that truncated the final line of folded YAML scalars and omitted trailing newlines, misreporting the six skills as `141/75/173/291/294/366` bytes.
   - `agent-skill-distribution` requires 40-character hexadecimal Git commit SHAs for all Git-backed entries, whereas official rolling CLI vendor mode (`skills add` / `skills update -y`) records `source`, `sourceType`, `skillPath`, and `computedHash` without a commit SHA.
   - Upstream `ponytail-help/SKILL.md` documents Claude/Codex plugin-tier features (`/ponytail band`, session-start auto-activation via `PONYTAIL_DEFAULT_MODE` / `~/.config/ponytail/config.json`, `/plugin marketplace update ponytail`, and Codex plugin-namespaced `$ponytail:ponytail` triggers) that do not apply to the standalone skills-only installation tier, while canonical `SKILL.md` files must remain unmodified for CLI update compatibility.
5. **Central OpenSpec Store vs. External Execution Boundaries**:
   - Central planning and store implementation live in `/Users/androidteam/Developer/platform/openspec-store` (`allowedEditRoots` restricted to the central store).
   - External repository `/Users/androidteam/Developer/shb/shb-schedule` and live host filesystem paths outside the central store (`/Users/androidteam/Developer/skills-lock.json`, `/Users/androidteam/Developer/.agents/`, `/Users/androidteam/Developer/scripts/workstation-daily-update.sh`, `~/.hermes/skills/`, and bounded snapshot storage) cannot be mutated by central `openspec` apply without separately authorized execution packets.

## Goals / Non-Goals

**Goals:**
- Establish a single-writer lockfile and explicit acceptance architecture where `/Users/androidteam/Developer/skills-lock.json` is the sole CLI-writable registry, `/Users/androidteam/Developer/.agents/skills-lock.json` is a generated read-only mirror published only via explicit `--accept-refresh` verification, and recoverable `current` + `previous` accepted snapshots preserve all registry-tracked canonical skill directories, registry copies, and SHA-256 digests.
- Define deterministic handling for manual native `npx skills update` / `skills update` invocations, explicit initial snapshot bootstrap verification, independent upstream provenance verification vs. local no-op hash checks, pre/post workspace agent-surface inventory checks, and exact-scope recovery for failed or partial refreshes.
- Unify refresh outcome classification (`drift`, `refreshed`, `already_current`, `path_ambiguous`, `failed`) and a 13-case shared test fixture matrix across `workstation-daily-update.sh` and `shb-schedule:step_skills_refresh` without runtime cross-repository file imports, while modifying `ecosystem-tooling-and-skills-upgrade` to replace false pre-mutation drift claims with honest post-update and check-mode semantics.
- Expose the six Ponytail skills to Hermes through manifest-owned user-scope links (`~/.hermes/skills/<name>`) verified by Hermes's native skill loader without pruning unrelated or non-manifest-owned Hermes links, while preserving existing Grok and Goose links.
- Reconcile topology, frontmatter budget (`142–371` YAML-decoded bytes), rolling provenance, and accurate host-specific standalone invocation guidance across the five governing specifications while keeping archive `2026-10-19-adopt-ponytail-agent-skills` (`c09d952a`) and upstream `SKILL.md` files immutable.
- Enforce explicit central-store vs. external-repository (`shb-schedule`) and external-host execution packets and acceptance gates.

**Non-Goals:**
- Building a custom Git/GitHub skill fetcher, custom lockfile format, or new background scheduler to replace `/opt/homebrew/bin/skills` (`npx skills`), `shb-schedule`, or `workstation-daily-update.sh`.
- Importing Python modules across repository boundaries at runtime between `/Users/androidteam/Developer/shb/shb-schedule` and `/Users/androidteam/Developer/platform/openspec-store`.
- Enabling Hermes blanket `external_dirs` scanning of `~/Developer/.agents/skills` or granting project trust to non-Git parent directories.
- Editing vendor `SKILL.md` files, mutating the archived change `2026-10-19-adopt-ponytail-agent-skills`, or expanding user-scope manifest synchronization to manage Grok or Goose skill directories.

## Decisions

### Decision 1: Single Writable Root Registry, Explicit `--accept-refresh` Mirror Publication, and Bounded `current`/`previous` Accepted Snapshots Over All Registry-Tracked Canonical Roots

- **Choice:**
  1. **Single CLI Writer vs. Explicit Generated Mirror**:
     - `/Users/androidteam/Developer/skills-lock.json` is the sole writable project registry mutated by `/opt/homebrew/bin/skills` (`npx skills`).
     - `/Users/androidteam/Developer/.agents/skills-lock.json` is a generated read-only compatibility mirror written exclusively by `sync-workspace-agent-skills.py --accept-refresh` (or initial `--bootstrap-snapshot`) after acceptance verification succeeds.
     - **Command Mode Separation in `sync-workspace-agent-skills.py`**:
       - `--check` is strictly read-only and non-mutating: it verifies symlink parity, YAML frontmatter budgets, lockfile parity between `/Users/androidteam/Developer/skills-lock.json` and `/Users/androidteam/Developer/.agents/skills-lock.json`, workspace agent-directory surface allowlists, and local skill file SHA-256 digests against `.skill-snapshots/current/manifest.json`.
       - Default invocation (no mode flags) reconciles declared symlinks only and MUST NOT implicitly copy `skills-lock.json` to `.agents/skills-lock.json` or rotate snapshots.
       - `--accept-refresh` explicitly validates a completed `skills update` state (scheduled or manual), updates `.skill-snapshots/{current,previous}/`, and publishes `.agents/skills-lock.json`.
       - `--bootstrap-snapshot` initializes `.skill-snapshots/current/` only after running full structural, YAML, and independent source/content verification of the installed registry-tracked skill roots (never assuming pre-existing `skills-lock.json` `computedHash` values prove local bytes are authentic).
  2. **Unified Snapshot and Recovery Scope (All Registry-Tracked Canonical Skill Roots)**:
     - Maintain `/Users/androidteam/Developer/.agents/.skill-snapshots/` with strictly two accepted generations (`current/` and `previous/`).
     - Both the snapshot store and the External Host Execution Packet cover the exact same scope: **all registry-tracked canonical skill directories** under `/Users/androidteam/Developer/.agents/skills/<name>/` declared in `/Users/androidteam/Developer/skills-lock.json` (currently 60 entries, including the 6 `ponytail*` skills and the 54 other CLI-tracked skills), plus `/Users/androidteam/Developer/skills-lock.json` and `/Users/androidteam/Developer/.agents/skills-lock.json`. Untracked local or generator-owned skill roots (`openspec-*`, `gitnexus-*`, `graphify`, `qi-hybrid-search`, etc.) and any directory outside `/Users/androidteam/Developer/.agents/skills/` are excluded from snapshot overwrite/recovery.
     - Each generation's `manifest.json` records `accepted_at` (UTC ISO-8601), CLI version, total snapshot byte size, per-skill entry metadata (`source`, `sourceType`, `skillPath`, `computedHash`), `source_revision` (`<40-hex-sha>` only when independently verified against the upstream repository commit/tree, else `"unknown"`), `upstream_verified` (`true`/`false`), per-file SHA-256 digests, and YAML-decoded `SKILL.md` `description` UTF-8 byte lengths.
  3. **Source-Integrity vs. Local-Byte Verification Rules**:
     - Hashing local files after a refresh cannot by itself prove newly fetched content is authentic upstream bytes (hashing corrupted new bytes merely records a corrupted digest). Verification therefore separates no-op validation from candidate update acceptance:
       - **No-op refresh validation (`refreshed == 0` and root `computedHash` unchanged from `current/`)**: Local byte integrity is verified by matching every file's live SHA-256 digest under each registry-tracked `/Users/androidteam/Developer/.agents/skills/<name>/` directory against `.skill-snapshots/current/manifest.json`. Any modified, missing, or unexpected file fails verification immediately, even if `skills update` printed `✓ All project skills are up to date`.
       - **Candidate update acceptance (`refreshed > 0` or root `skills-lock.json` changed)**: Before promoting a candidate to `current/`, `--accept-refresh` verifies:
         1. Unrelated entries in `/Users/androidteam/Developer/skills-lock.json` are preserved intact and no unapproved skill name or `source` collision exists against `current/` or global `~/.agents/skills/` installations.
         2. All six Ponytail entries retain `"source": "DietrichGebert/ponytail"`, `"sourceType": "github"`, and `"skillPath": "skills/<name>/SKILL.md"`.
         3. Every registry-tracked canonical skill directory resolves to a readable uppercase `SKILL.md`, contains no `NON_OFFICIAL_ENTRY_DIRS` (`.cursor-plugin`, `cursor-plugin`, `claude-plugin`), and has a valid YAML-decoded frontmatter `description` within the 1,024 UTF-8 byte ceiling.
         4. **Pre/Post Workspace Surface Inventory**: No new unallowlisted project agent skill directories or duplicate copies were materialized in `/Users/androidteam/Developer/` (only `.agents/skills/`, `.claude/skills/`, `.hermes/skills/`, and isolated `.codex/skills/` are permitted in `/Users/androidteam/Developer/`).
         5. **Upstream Provenance Check**: Where the upstream Git commit/tree and blob digests for `source` + `skillPath` are independently verified against the local files, `source_revision` is recorded as the exact 40-hex commit SHA and `upstream_verified: true`. If independent upstream blob verification is not performed or unavailable, `source_revision` MUST be recorded as `"unknown"` with `upstream_verified: false`, and neither logs nor evidence may claim the updated bytes are "byte-identical upstream".
  4. **Commit / No-Op / Failure & Partial-Mutation Recovery**:
     - *Verified update*: Atomically rotate `current/` → `previous/`, write the new `current/` snapshot, and atomically write `/Users/androidteam/Developer/.agents/skills-lock.json` from the verified root `skills-lock.json`.
     - *Verified no-op*: Keep `current/` and `previous/` unchanged; if `/Users/androidteam/Developer/.agents/skills-lock.json` drifted from the verified root `skills-lock.json` while all on-disk skill bytes match `current/manifest.json`, atomically reconcile `.agents/skills-lock.json`.
     - *Failed or partial refresh*: When `skills update` exits non-zero, times out, emits unrecognized or incomplete output (such as `Refreshing N` with no completion summary/lines), materializes unallowlisted project agent directories, or fails byte/YAML/collision checks, the pipeline MUST NOT publish `.agents/skills-lock.json` and MUST NOT report accepted success. It diffs live registry-tracked `/Users/androidteam/Developer/.agents/skills/<name>/` directories and `/Users/androidteam/Developer/skills-lock.json` against `current/manifest.json` to report exact partial file and lockfile mutations, then either restores **only** the affected registry-tracked canonical skill directories and `/Users/androidteam/Developer/skills-lock.json` from `current/` (when recovery is invoked) or leaves `.agents/skills-lock.json` at the last accepted state and exits non-zero / `DEGRADED`.
- **Rationale:** Aligns with `skills` v1.7.2's `cwd/skills-lock.json` writer, prevents `.agents/skills-lock.json` from acting as a second writer or absorbing unverified mutations, ensures manual `npx skills update` runs require explicit `--accept-refresh` verification, and provides exact-scope byte recovery across all 60 registry-tracked skills.
- **Alternatives Considered:**
  - *Symlinking `.agents/skills-lock.json -> ../skills-lock.json` or implicitly copying on every `sync-workspace-agent-skills.py` run*: Rejected because any partial or unverified `skills update` mutation would immediately pollute the `.agents/skills-lock.json` mirror without passing acceptance checks.
  - *Snapshotting only the 6 `ponytail*` directories while running workspace-wide `skills update -y`*: Rejected because `skills update -y` in `/Users/androidteam/Developer` refreshes all 60 registry-tracked skills; partial-mutation recovery must cover the same registry-tracked set that `skills update -y` can mutate.

### Decision 2: Shared Refresh Outcome Semantics, Spec Correction for Post-Mutation Drift, and 13-Case Fixture Matrix Across Shell and DBOS

- **Choice:**
  1. **Modify `ecosystem-tooling-and-skills-upgrade` Spec + Self-Contained Parsers**:
     - Modify `### Requirement: Drift is observable before content is replaced` and `### Requirement: Skill content refresh outcomes are reported` in `ecosystem-tooling-and-skills-upgrade` so the specification itself states that `--check` mode is non-mutating (inspecting lockfile/snapshot state without invoking `skills update`), while apply mode invokes `skills update -y` and reports `drift` as observed update activity during the refresh rather than claiming a pre-mutation dry-run check.
     - Keep `classify_refresh` in `platform/openspec-store/scripts/workstation-daily-update.sh` (Bash 3.2) and `step_skills_refresh` in `shb/shb-schedule/src/shb_schedule/workflows/workstation_update.py` (Python 3) self-contained with zero cross-repository runtime imports, bound to identical outcome rules and verified by the same 13-case fixture matrix.
  2. **Canonical Classification Rules**:
     - **Input normalization**: Combine `stdout` and `stderr` (`2>&1` in shell; `f"{proc.stdout or ''}\n{proc.stderr or ''}"` in Python) and strip ANSI CSI/OSC/erase sequences and `\r`.
     - **`refreshed` (completed updates only; summary-first, no double-counting)**:
       - Match explicit numeric completion summaries first: `Updated (\d+) skill\(s\)`, `(\d+) skills? (?:refreshed|updated)`, or `(?:refreshed|updated):\s*(\d+)`. When matched, set `refreshed` to that exact integer (`Updated 0 skill(s)` → `refreshed=0`).
       - Only when no numeric completion summary line is present, count distinct per-skill completion lines matching `^\s*✓\s+Updated\s+(?![0-9]+\s+skill)\S+`.
       - **Never** sum per-skill `✓ Updated <name>` lines with the `Updated N skill(s)` summary line, and **never** use `Refreshing N skill(s)` or `Found N update(s)` to set `refreshed` (those report attempted activity, not completed updates).
     - **`drift` (attempted or completed update activity)**:
       - Set `drift` only when `refreshed > 0` or when a positive numeric update-activity header (`Found ([1-9][0-9]*) (?:global )?update`, `Refreshing ([1-9][0-9]*) skill`, `([1-9][0-9]*) (?:skills? )?drifted`, or `drift:\s*([1-9][0-9]*)`) is present. `Updated 0 skill(s)` or `0 skills drifted` yields `drift=0`.
     - **`path_ambiguous` (informational skip detection)**:
       - Match explicit numeric `(\d+)\s+(?:skills?\s+)?(?:path\s+)?ambiguous` or `ambiguous:\s*(\d+)` first; otherwise count `Multiple current paths match` blocks (or bulleted skill entries under that header, minimum `1` when the header appears).
     - **`already_current` (requires explicit up-to-date evidence; never inferred from `Checking` + ambiguity alone)**:
       - Match explicit numeric `(\d+)\s+(?:project\s+|global\s+)?skills?\s*\(?s?\)?\s*already\s+(?:current|up to date)` or `(?:already current|up to date):\s*(\d+)` when present.
       - Otherwise, set `already_current = 1` **only** when an explicit up-to-date summary marker (`All (?:project |global )?skills are up to date` or `(?:project |global )?skill\(s\) already\s+up to date`) is present and `refreshed == 0`.
       - When both an explicit up-to-date summary marker and `Multiple current paths match` appear in the same run, both `already_current` (`>=1`) and `path_ambiguous` (`>=1`) are preserved. Conversely, if a run prints only `Checking N skill(s)…` and `Multiple current paths match …` with **no** explicit up-to-date marker or count, `already_current` MUST remain `0`.
     - **`failed` (fail-closed on non-zero exit, incomplete `Refreshing N`, unrecognized output, or post-refresh verification failure)**:
       - Set `failed = max(failed, 1)` when:
         1. `returncode != 0` (including timeout `124`);
         2. An explicit positive failure count (`([1-9][0-9]*)\s+(?:skills?\s+)?(?:failed|failures)` or `failed:\s*([1-9][0-9]*)`) or fatal error line (`Error:`, `ERR!`, `fatal:`, `EACCES`, `ENOENT`) appears in combined `stdout`/`stderr`;
         3. Activity headers (`Found [1-9]\d* (?:global )?update` or `Refreshing [1-9]\d* skill`) appear without any completed summary (`Updated \d+ skill`) or per-skill completion line (`✓ Updated <name>`);
         4. `returncode == 0` produces **no recognized summary pattern** (none of: numeric update/current/ambiguous summary, `✓ Updated <name>`, `All (?:project |global )?skills are up to date`, `(?:project |global )?skill\(s\) already up to date`, or `Multiple current paths match`); or
         5. Post-refresh acceptance/parity verification (`sync-workspace-agent-skills.py --accept-refresh` / `--check`) fails.
       - Preserve any parsed `refreshed`, `already_current`, and `path_ambiguous` counts when `failed >= 1` so partial progress before failure is never masked.
  3. **Shared 13-Case Canonical Fixture Matrix**:
     Both `platform/openspec-store/tests/` and `shb/shb-schedule/tests/test_workstation_update_workflow.py` MUST verify these 13 fixtures:
     - `F01_v172_project_all_current`: `Checking 6 skill(s)…\n✓ All project skills are up to date` (`rc=0`) → `drift=0, refreshed=0, already_current=1, path_ambiguous=0, failed=0`.
     - `F02_global_all_current`: `Checking 4 skill(s)…\n✓ All global skills are up to date` (`rc=0`) → `drift=0, refreshed=0, already_current=1, path_ambiguous=0, failed=0`.
     - `F03_v172_per_skill_plus_summary`: `✓ Updated ponytail\n✓ Updated ponytail-help\nUpdated 2 skill(s)` (`rc=0`) → `drift>0, refreshed=2, already_current=0, path_ambiguous=0, failed=0`.
     - `F04_explicit_zero_updated`: `Updated 0 skill(s)\n✓ All project skills are up to date` (`rc=0`) → `drift=0, refreshed=0, already_current=1, path_ambiguous=0, failed=0`.
     - `F05_global_found_refreshing_completed`: `Found 3 global update(s)\nRefreshing 3 skill(s)\n✓ Updated a\n✓ Updated b\n✓ Updated c` (`rc=0`) → `drift>0, refreshed=3, already_current=0, path_ambiguous=0, failed=0`.
     - `F06_refreshing_without_completion_fails`: `Found 2 global update(s)\nRefreshing 2 skill(s)` (`rc=0`, no completion summary or `✓ Updated` lines) → `drift>0, refreshed=0, already_current=0, path_ambiguous=0, failed=1`.
     - `F07_ambiguous_only_no_current`: `Checking 1 skill(s)…\nMultiple current paths match "docfork-docs" — skipping them.` (`rc=0`, no up-to-date summary) → `drift=0, refreshed=0, already_current=0, path_ambiguous=1, failed=0`.
     - `F08_ambiguous_with_explicit_current`: `Checking 60 skill(s)…\nMultiple current paths match "docfork-docs" — skipping them.\n✓ All project skills are up to date` (`rc=0`) → `drift=0, refreshed=0, already_current=1, path_ambiguous=1, failed=0`.
     - `F09_numeric_summary_with_counts`: `42 skills updated\n3 skills already current\n1 skills drifted\n2 path ambiguous` (`rc=0`) → `drift=1, refreshed=42, already_current=3, path_ambiguous=2, failed=0`.
     - `F10_partial_mutation_then_failure`: `✓ Updated ponytail\nError: clone failed for repo` (`rc=1`) → `drift>0, refreshed=1, already_current=0, path_ambiguous=0, failed=1` (status `DEGRADED`).
     - `F11_stderr_fatal_error`: `stdout="Checking 6 skill(s)…\n"`, `stderr="Error: EACCES: permission denied, open '/Users/androidteam/Developer/skills-lock.json'\n"` (`rc=1`) → `drift=0, refreshed=0, already_current=0, path_ambiguous=0, failed=1`.
     - `F12_timeout_124`: `Checking 60 skill(s)…\nRefreshing 1 skill(s)` (`rc=124`) → `drift>0, refreshed=0, already_current=0, path_ambiguous=0, failed=1`.
     - `F13_unrecognized_exit_zero`: `something unexpected happened` (`rc=0`) → `drift=0, refreshed=0, already_current=0, path_ambiguous=0, failed=1`.
- **Rationale:** Fixes every parser defect across shell and DBOS while preserving strict repository runtime independence and updating the governing spec where the false pre-mutation drift claim originated.
- **Alternatives Considered:**
  - *Updating only `workstation-daily-update.sh` comments while leaving `Drift is observable before content is replaced` unchanged in `ecosystem-tooling-and-skills-upgrade/spec.md`*: Rejected because the spec itself would remain at odds with `skills update` CLI capabilities and truthful reporting.

### Decision 3: Selected Hermes User-Scope Manifest Synchronization, Non-Destructive Link Ownership, and Native Loader Verification

- **Choice:**
  1. Create `platform/openspec-store/config/hermes-user-skill-manifest.txt` declaring the six Ponytail skill slugs (`ponytail`, `ponytail-audit`, `ponytail-debt`, `ponytail-gain`, `ponytail-help`, `ponytail-review`).
  2. Extend `platform/openspec-store/scripts/sync-workspace-agent-skills.py` to reconcile `user_hermes_skills` into `USER_HERMES_SKILLS = HOME / ".hermes" / "skills"`.
  3. **Non-Destructive Ownership in `~/.hermes/skills/`**:
     - Unrelated global or Hermes-native entries in `~/.hermes/skills/` (real directories or symlinks resolving outside `WORKSPACE_AGENTS`) are strictly preserved; any name collision between a declared manifest entry and an unrelated non-workspace entry in `~/.hermes/skills/` fails closed (`user_hermes_skills.conflicts`) without overwriting.
     - Pre-existing resolvable symlinks in `~/.hermes/skills/` that point into `WORKSPACE_AGENTS` but are **not** listed in `hermes-user-skill-manifest.txt` MUST NOT be deleted merely because they are absent from the selected Hermes manifest (honoring the `ecosystem-tooling-and-skills-upgrade` principle that undeclared resolvable user-scope links are preserved/reported rather than pruned without explicit ownership removal). Only broken links or links previously recorded as owned by `hermes-user-skill-manifest.txt` and subsequently removed from that manifest may be pruned.
  4. Retain `/Users/androidteam/Developer/.hermes/skills/ponytail*` and `/Users/androidteam/Developer/.claude/skills/ponytail*` project-level relative symlinks (`../../.agents/skills/<name>`), while enforcing the pre/post workspace agent-surface inventory check around `skills update -y` so any unexpected new project agent directory in `/Users/androidteam/Developer/` is caught and rejected.

## Risks / Trade-offs

- **[Risk] Developer runs manual `npx skills update` in `/Users/androidteam/Developer` without running `--accept-refresh`** → Mitigation: `sync-workspace-agent-skills.py --check` (strictly non-mutating) and default link-sync runs refuse to silently copy root `skills-lock.json` over `.agents/skills-lock.json`; they report unaccepted lockfile/byte drift against `.skill-snapshots/current/` until explicit `--accept-refresh` verifies and promotes the state (or restores `current/`).
