# Design

## Context

See `proposal.md` - Why for motivation. On `iosteam-mac-mini`, `@fission-ai/openspec@2.0.0` is already installed at `/Users/androidteam/.npm-global/bin/openspec` (`OpenSpec 2.0.0 (npm, global)` on Node `v26.13.1`). During the `2026-11-12` daily maintenance run, `sync-workspace-agent-skills.py` detected `1.17.0 -> 2.0.0` version drift and invoked `openspec update /Users/androidteam/Developer/platform/openspec-store`, leaving `platform/openspec-store` with 97 unstaged modifications/deletions and 24 untracked symlinks alongside the unrelated in-progress change `openspec/changes/add-tailscale-media-relay-for-ios-and-peers/`.

Meanwhile:
1. `/Users/androidteam/.config/openspec/config.json` still contains `"delivery": "skills"`, which OpenSpec `2.0.0` retired (`dist/core/global-config.js:179`: `withoutUnsetRetiredDelivery()` never writes `delivery` on new configs, preserving it only if already present on disk).
2. `platform/openspec-store/scripts/sync-workspace-agent-skills.py` still models `OPENSPEC_ADAPTER_SKILL_TREES` as 8 independent physical skill directories, rejects non-`"skills"` `"delivery"` values (`openspec-delivery-mismatch`), and checks symlink ownership in `reconcile_links()` solely via `os.path.realpath(path)`. Under OpenSpec `2.0.0`, `platform/openspec-store/.claude/skills/openspec-*` is itself a symlink to `../../.agents/skills/openspec-*`, so `os.path.realpath()` resolves `~/Developer/.claude/skills/openspec-*`, `~/.claude/skills/openspec-*`, and `~/.agents/skills/openspec-*` all the way to `platform/openspec-store/.agents/skills/openspec-*`, bypassing `managed_target_roots=(store_claude_skills,)` and `(workspace_agents,)` when pruning deselected or broken links.
3. On peer workstation `macbook-pro-m5` (`2026-11-13-migrate-openspec-2-shared-skill-layout`, archived at `shb-specs` `a87d7a6`), OpenSpec `2.0.0` convergence is already active across `.agents/skills/.openspec-target`, canonical `.agents/skills/openspec-*`, `own-files` relative symlinks, and `openspec update --dry-run --json` verification.

## Goals / Non-Goals

**Goals:**
- Reconcile `~/.config/openspec/config.json`, `platform/openspec-store` skill/symlink trees, `sync-workspace-agent-skills.py`, unit tests, and runbook documentation onto a single OpenSpec `2.0.0` shared-skill contract.
- Enforce full OpenSpec `2.0.0` topology verification inside `sync-workspace-agent-skills.py --check` so both `workstation-daily-update.sh` (Stage 6) and `shb-schedule` (`step_skills_refresh`) inherit `2.0.0` drift gates without duplicating orchestration logic.
- Preserve existing synthetic unit-test fixture isolation (`test_ponytail_skill_reconciliation.py`), Bright Data skill symlinks (`brightdata-cli`, `data-feeds`, `search`), `.opencode/` runtime files, third-party `.skill-snapshots/`, and concurrent OpenSpec changes.

**Non-Goals:**
- Changing CLI installation ownership from `~/.npm-global/bin/openspec` to standalone or Homebrew.
- Editing `workstation-daily-update.sh` or `shb/shb-schedule`, which already invoke `sync-workspace-agent-skills.py --check` and file-locked reconciliation.
- Altering third-party `skills-lock.json` entries or rotating `.agents/.skill-snapshots/{current,previous}/`.

## Decisions

### 1. Keep Existing Centralized `sync-workspace-agent-skills.py` Maintenance Pattern
- **Choice**: Extend `platform/openspec-store/scripts/sync-workspace-agent-skills.py` (following the pattern established in `2026-11-11-migrate-openspec-1-17-skills-delivery-and-auto-sync`) rather than adding separate shell checks to `workstation-daily-update.sh` or Python steps to `shb-schedule`.
- **Rationale**: Both `workstation-daily-update.sh` (`Stage 6/12`) and `shb-schedule` (`step_skills_refresh`) already execute `python3 sync-workspace-agent-skills.py --check` and fall back to `python3 sync-workspace-agent-skills.py` under `/tmp/openspec-skill-sync.lock` when `DISABLE_UPDATES` is unset. Keeping OpenSpec `2.0.0` topology verification in `sync-workspace-agent-skills.py` avoids script provenance drift (`config/script-provenance-manifest.tsv`) and cross-repo coordination overhead.
- **Alternatives considered**: Adding a bespoke `openspec update --dry-run --json` step in `shb-schedule` and `workstation-daily-update.sh` — rejected because it splits OpenSpec skill governance across two repositories and three files.

### 2. Preserve the 8 Configured Tool Targets in `.agents/skills/.openspec-target`
- **Choice**: Retain the 8 configured targets (`claude own-files`, `codex`, `factory`, `junie`, `kilocode`, `kiro own-files`, `pi`, `qoder`) generated by OpenSpec `2.0.0` in `platform/openspec-store/.agents/skills/.openspec-target`.
- **Rationale**: `~/.kiro` is present on `iosteam-mac-mini`, and `.claude/skills/`, `.kiro/skills/`, `.factory/skills/`, `.junie/skills/`, `.kilocode/skills/`, `.pi/skills/`, and `.qoder/skills/` already exist in `platform/openspec-store` to host tracked Bright Data symlinks (`brightdata-cli`, `data-feeds`, `search`). Retaining `.openspec-target` as generated keeps `openspec update --dry-run --json` at zero changes (`changes: [], notes: [], failures: []`) while eliminating all 60 redundant physical OpenSpec `SKILL.md` copies.
- **Alternatives considered**: Removing `kiro` or pruning `.factory`/`.junie`/`.kilocode` directories — rejected because those directories still hold tracked non-OpenSpec Bright Data symlinks and `~/.kiro` exists on the host.

### 3. Shared-Layout Topology & Dry-Run Verification in `sync-workspace-agent-skills.py`
- **Choice**: Delete the unused import-time `OPEN_SPEC_NAMES` glob, `OPENSPEC_ADAPTER_SKILL_TREES`, the `openspec-delivery-mismatch` gate, and the dead `1.17` `kept: / unchecked: / failures: ` stdout parser, replacing them with a `2.0.0` shared-layout inspector and shared dry-run check:
  1. **Synthetic Test Isolation Guard**: If `.agents/skills/.openspec-target` is absent and zero `openspec-*` skills declare `metadata.author == "openspec"` or `metadata.generatedBy`, return `(True, [])` so minimal unit-test fixtures remain isolated.
  2. **Canonical Generator Parity**: Verify every non-`keep` `openspec-*` directory in `store/.agents/skills/` has a physical `SKILL.md` (not a symlink) whose `metadata.generatedBy` equals `openspec --version`.
  3. **`.openspec-target` & `own-files` Link Integrity**: Parse `.agents/skills/.openspec-target` (`<tool>`, `<tool> own-files`, `keep <skill>`), failing closed on unrecognized lines (`openspec-invalid-target-line`). Require `.openspec-target` to exist and retain `"claude own-files"` when `cli_version` major >= 2 (preventing silent Claude removal and 24 broken workspace/user Claude links). Allow `keep <skill>` entries for user-kept skills and their preserved `own-files` symlinks without triggering stale-entry errors. For each `<tool> own-files` entry (mapping `claude -> .claude/skills`, `kiro -> .kiro/skills`, `hermes -> .hermes/skills`), require each canonical `openspec-*` entry under that tool's `skills/` directory to be a symlink resolving to `store/.agents/skills/<skill>`.
  4. **Generic Non-Linked Dot-Folder & Command Sweep**: Scan every `store.glob(".*")` directory (except `.agents`) containing a `skills/` subdirectory and require zero `openspec-*` entries outside declared `<tool> own-files` link directories, plus zero `*.md` files in `OPENSPEC_RETIRED_COMMAND_DIRS`.
  5. **Isolated Subprocess Env & Shared Dry-Run Check**: Require `--openspec-config` paths to end in `openspec/config.json` (failing closed with `openspec-invalid-config-path` otherwise) so `XDG_CONFIG_HOME` resolves accurately (`str(config_path.parent.parent)`). Pass an isolated `env` copy to all `openspec` subprocesses setting `HOME` from `--home-dir` and `XDG_CONFIG_HOME` from `--openspec-config`. Run `[exe, "update", "--dry-run", "--json", str(store)]` in both `--check` mode and post-`update` reconcile mode, requiring exit `0` with empty `changes`, `notes`, and `failures` arrays (catching `legacy-artifacts`, `edited-skills`, and `legacy-tool-directories`), and return a consistent `(True, [])` shape from `reconcile_openspec_generator_parity()` on clean/paused/reconciled runs.
- **Alternatives considered**: Checking only `.agents/skills/openspec-*/SKILL.md` frontmatter or hardcoding five retired folders — rejected because missing `claude own-files`, kept `notes` in `--dry-run`, or stray copies in `.cursor/skills`, `.omp/skills`, or `.agent/skills` would slip past `--check`.

### 4. Dual Immediate-and-Resolved Symlink Ownership in `reconcile_links()`
- **Choice**: Update `reconcile_links()` in `sync-workspace-agent-skills.py` to evaluate `_is_managed()` against both:
  - `raw = Path(os.path.normpath(os.path.join(path.parent, os.readlink(path)))); immediate_target = raw.parent.resolve() / raw.name` (resolving symlinked parent prefixes like macOS `/tmp -> /private/tmp` and `/var -> /private/var` without dereferencing the intermediate leaf symlink), and
  - `resolved_target = Path(os.path.realpath(path))` (fully dereferenced canonical path),
  while including `store_standard` alongside `store_claude_skills` in `managed_target_roots` for Claude skill surfaces.
- **Rationale**: In OpenSpec `2.0.0`, `~/Developer/.claude/skills/openspec-* -> platform/openspec-store/.claude/skills/openspec-* -> ../../.agents/skills/openspec-*` and `~/.agents/skills/openspec-* -> ~/Developer/.agents/skills/openspec-* -> platform/openspec-store/.agents/skills/openspec-*` are two-hop symlink chains. Resolving `raw.parent` guarantees broken two-hop links match `root.resolve()` even under macOS `/tmp` and `/var` test directories, while checking `resolved_target` recognizes intact multi-hop chains cleanly.
- **Alternatives considered**: Changing `~/Developer/.claude/skills/openspec-*` to point directly at `store/.agents/skills/openspec-*` — rejected because keeping `store/.claude/skills/openspec-*` in the chain exercises and validates OpenSpec `2.0.0`'s own `claude own-files` links continuously.

### 5. Retire `"delivery"` from `~/.config/openspec/config.json` Atomically
- **Choice**: Remove only the `"delivery"` key from `/Users/androidteam/.config/openspec/config.json` via atomic temp-file + `os.replace()` write (preserving `0600`/`0644` permissions and all remaining keys: `featureFlags`, `profile`, `telemetry`, `workflows`, `defaultStore`, `completionTipSeen`), after saving a rollback snapshot outside tracked repositories.
- **Rationale**: Matches `macbook-pro-m5` and OpenSpec `2.0.0`'s `withoutUnsetRetiredDelivery()` contract without disturbing `defaultStore: "openspec-store"` or telemetry state.

### Transaction Boundaries

```text
  [1. Config Boundary]  ~/.config/openspec/config.json
       Atomic temp-write + os.replace() removing retired "delivery" key.
       Independent of Git; backed up to /tmp pre-mutation snapshot for rollback.

  [2. Store & Sync Boundary]  ~/Developer/platform/openspec-store + Symlink Roots
       /tmp/openspec-skill-sync.lock (fcntl.flock exclusive lock) serializes
       `openspec update` + workspace/user symlink reconciliation against
       concurrent scheduled maintenance runs.

  [3. Git Staging Boundary]  ~/Developer/platform/openspec-store (branch: main)
       Path-scoped staging ONLY of OpenSpec 2.0 skill/target/symlink paths,
       sync script, tests, docs, specs, and archive; strictly excludes
       concurrent untracked `openspec/changes/add-tailscale-media-relay-for-ios-and-peers/`.
```

## Risks / Trade-offs

- **[Risk] Concurrent uncommitted OpenSpec change in `platform/openspec-store`** (`openspec/changes/add-tailscale-media-relay-for-ios-and-peers/`) → **Mitigation**: Never run `git add -A`, `git checkout .`, or `git clean`; use explicit pathspecs on every `git status`/`git diff`/`git add` command and verify `add-tailscale-media-relay-for-ios-and-peers/` remains untouched before and after apply/archive.
- **[Risk] `openspec update --dry-run --json` subprocess latency, global config leakage, or mock incompatibility in unit tests** → **Mitigation**: Bound `--dry-run --json` subprocess timeout to `30s`, run it after fast local filesystem checks, propagate `HOME` and `XDG_CONFIG_HOME` from `--home-dir` / `--openspec-config`, and update synthetic `mock_openspec` scripts in `test_ponytail_skill_reconciliation.py` to handle `update --dry-run --json` explicitly (testing non-empty `changes`, `notes`, and `failures` rejection).
- **[Risk] Accidental rotation of third-party `.skill-snapshots/`** → **Mitigation**: Run `sync-workspace-agent-skills.py` and `sync-workspace-agent-skills.py --check` without `--accept-refresh` so `.agents/.skill-snapshots/{current,previous}/` stay pinned to upstream `skills-lock.json` refreshes.

## Migration Plan

1. **Preflight & Backup**: Verify `which -a openspec` (`/Users/androidteam/.npm-global/bin/openspec` `2.0.0`), capture pre-apply `git status --short` in `platform/openspec-store` (recording `add-tailscale-media-relay-for-ios-and-peers/`), and back up `~/.config/openspec/config.json` to `/tmp/openspec-config.pre-2.0.json` (`0600`).
2. **Global Config Cleanup**: Atomically remove `"delivery"` from `~/.config/openspec/config.json` and verify `openspec config list --json` and `openspec doctor --store openspec-store --json`.
3. **Synchronizer & Unit Test Upgrade**: Update `scripts/sync-workspace-agent-skills.py` and `tests/test_ponytail_skill_reconciliation.py` for OpenSpec `2.0.0` shared layout, `.openspec-target` + `own-files` symlinks, `--dry-run --json` verification, and dual immediate/resolved symlink ownership; run `ruff check` and `pytest`.
4. **Surface Convergence & Documentation**: Run `sync-workspace-agent-skills.py` and `sync-workspace-agent-skills.py --check`, update `docs/mac-development-setup.md` (and verify `~/Developer/.claude/CLAUDE.md` needs no command-syntax changes or update version note), and run `workstation-daily-update.sh --check`.
5. **Rollback Strategy**: If any verification gate fails, restore `/tmp/openspec-config.pre-2.0.json` to `~/.config/openspec/config.json`, revert only touched `scripts/`, `tests/`, `docs/`, and OpenSpec skill paths in `platform/openspec-store` via explicit pathspecs, and re-run `sync-workspace-agent-skills.py --check`.
