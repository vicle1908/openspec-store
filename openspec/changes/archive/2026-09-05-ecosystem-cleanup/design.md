## Context

The workspace has 19 Python repos. After months of feature work and agent orchestration, 35 worktrees remain across 7 repos, 3 repos lack virtual environments, and tdt-core sits on a non-main branch. Untracked deploy directories and graphify-out artifacts clutter git status. See proposal.md for full motivation.

## Goals / Non-Goals

**Goals:**
- Restore all repos to a clean `main` (or `master`) branch with no uncommitted changes
- Remove all completed, orphaned, and detached-HEAD worktrees
- Ensure every Python repo has a working `.venv`
- Verify tdt-scheduler embedded repo copies are current

**Non-Goals:**
- No source code changes to any repo
- No spec or architecture changes
- No CI/CD modifications
- No Go repo changes (go-microservices, mcp-router)
- Not deleting branches that represent active feature work

## Decisions

### 1. Worktree cleanup strategy

**Decision:** Audit each worktree individually. Delete if: detached HEAD, branch fully merged to main, or clearly stale (deploy sources, orca worker remnants). Preserve if: branch has unmerged commits and appears to be active feature work.

**Rationale:** Blind deletion risks losing unmerged work. Individual inspection is slower but safe. Detached-HEAD worktrees (webhook-receiver × 4, ai-review × 1) are always safe to remove — they represent deploy snapshots, not ongoing work.

**Alternatives considered:**
- `git worktree prune` — only removes worktrees whose directories are already deleted; won't help here
- Delete all, re-create as needed — too aggressive, risks losing unmerged work

### 2. tdt-core branch resolution

**Decision:** Check if `fix/remove-api-key-env-loader-exemption` has unmerged commits. If merged, delete the branch. If unmerged, merge to main or preserve the worktree.

**Rationale:** A stale feature branch on the main checkout blocks clean status. If the work is complete, it should be merged; if abandoned, the branch should be deleted.

### 3. Uncommitted change handling

**Decision:** For graphify-out changes: commit them (they're generated artifacts that should be current). For untracked `.claude/` directories: leave them (they're agent-local config, not repo content). For deploy source directories: delete if they're orphaned worktrees being cleaned up.

**Rationale:** graphify-out files are generated by hooks and should reflect the current codebase state. `.claude/` dirs are per-session and harmless.

### 4. tdt-scheduler embedded copies

**Decision:** Compare embedded agent-core, jira-skill, code-daily-scan, jira-daily-reports directories against their upstream repos. If stale, update or remove.

**Rationale:** tdt-scheduler uses these as Docker build context. Stale copies could produce incorrect images.

## Risks / Trade-offs

- **[Risk] Unmerged work deleted** → Mitigation: Check `git log main..branch` before deleting any non-detached worktree. If commits exist, preserve or merge first.
- **[Risk] Missing venv breaks a tool** → Mitigation: `uv sync` is idempotent and fast. If it fails, the repo's pyproject.toml has issues that need separate investigation.
- **[Risk] tdt-scheduler copies diverge** → Mitigation: Document the dependency relationship; consider switching to a proper dependency reference if divergence is found.
