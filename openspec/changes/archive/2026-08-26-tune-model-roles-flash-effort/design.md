# Design: tune-model-roles-flash-effort

## Context

`/Users/androidteam/.omp/agent/config.yml` currently binds `smol`/`commit` to `shopapikey/fable-5:xhigh`, leaves `tiny`/`vision` unset (inheriting `defaultThinkingLevel: xhigh` and falling through to the flagship `default` model), and defines a single `retry.fallbackChains.default` terminating in `omniroute/dlg/kimi-k2.6`. Live state on 2026-08-25 after `replace-giaoduc-with-phanmemvip`: `task: phanmemvip/gpt-5.6-sol:xhigh`; `default: openrouter/stealth/ox-alpha:max`; `slow: cockpit/gpt-5.6-luna:max`; `plan: cockpit/gpt-5.6-sol:max`; `advisor: cockpit/gpt-5.6-sol:xhigh`. `models.yml` declares `omniroute`, `shopapikey` (api.phanmemvip.shop, anthropic-messages), `phanmemvip` (api.phanmemvip.shop/v1, openai-responses, gpt-5.6-sol), and `cockpit` (localhost:51006/v1, luna/sol/terra). `google-antigravity` is a NATIVE provider (not in models.yml) whose catalog contains `gemini-3.7-flash` (text+image, reasoning); no 3.7-lite variant exists. This change is a delta against the existing `omp-provider-routing` capability, which already owns role allocation, isolated-profile validation, and the "no live mutation until isolated testing succeeds" gate.

Fallback semantics per OMP `docs/settings.md`: roles without a chain inherit `default`; keys containing `/` bind chains to a model across role reassignment; `provider/*` keys cover every model of a provider and `provider/*` entries swap provider keeping the id (missing ids skipped); selectors accept `:thinking` suffixes (`low`/`medium`/`high`/`xhigh`/`max`), and without a suffix the role inherits `defaultThinkingLevel` (currently `xhigh`).

## Goals / Non-Goals

**Goals:**
- High-frequency roles (`smol`, `tiny`, `vision`) land on `google-antigravity/gemini-3.7-flash` at explicit `:high` effort per the user's high-effort direction.
- `commit` effort drops to `:low` — commit-message generation needs no deep thinking budget.
- Every primary binding keeps multi-hop fallback coverage via model-keyed chains that survive role reassignment, plus the role-inherited `default` chain.
- Omniroute fully out of active routing without deleting its catalog definition.
- All seven distinct final role selectors pass the isolated-profile smoke test, judged on the requested selector, before live mutation.

**Non-Goals:**
- `models.yml` is untouched by THIS change — no provider definitions, catalog entries, or credential edits belong to it. (The `fable-5` → `Claude-Fable` id rename in `models.yml` landed mid-apply from the separate concurrent `canonicalize-claude-fable-and-responses` change; see D7.)
- No changes to `advisor.enabled`, `tier`, compaction, or tool settings.
- No re-enablement of omniroute routing; the catalog entry remains defined and pickable but unrouted. Revisit when OmniRoute deployment/key state is resolved.
- No repair or modification of any credential; if a smoke selector fails, apply is blocked and reported, not worked around.

## Decisions

- **D1: flash-3.7 at explicit `:high` for `smol`/`tiny`/`vision`.** User-directed family and effort level ("use high effort"). `gemini-3.7-flash` is the only fast catalog entry with confirmed image input, which is why it also takes the `vision` role. Every flash selector — the three role bindings and the default-chain terminal hop — carries explicit `:high`. Because `tiny`/`smol` are high-frequency background roles and `defaultThinkingLevel` is `xhigh`, the explicit suffix is what prevents silent inheritance of the top thinking budget. Alternative considered: `:low` for background economy — rejected per explicit user direction.
- **D2: `commit` at the shopapikey gateway model, effort `:low`.** Same proven provider as before, effort reduced from `:xhigh` to `:low`; commit-message generation is short-form and does not benefit from deep thinking. The shopapikey hop additionally remains the terminal provider-jump hop in every model-keyed chain, so its validity stays smoke-gated.
- **D3: default chain = `[phanmemvip/gpt-5.6-sol, shopapikey/Claude-Fable, cockpit/gpt-5.6-sol, google-antigravity/gemini-3.7-flash:high]`.** The first three hops are kept in their current live order (proven providers first); `omniroute/dlg/kimi-k2.6` is removed per the user directive that omniroute is unused, and flash:high is appended as the terminal hop so the inherited chain ends on a validated fast model rather than an unrouted gateway.
- **D4: model-selector keys over role chains for coverage.** Per `docs/settings.md`, keys containing `/` bind a chain to the model across role reassignment — so coverage follows the model, not the role that currently holds it. `phanmemvip/gpt-5.6-sol` and `cockpit/gpt-5.6-luna` fail over to `cockpit/gpt-5.6-sol` then provider-jump to `shopapikey/Claude-Fable`; `cockpit/gpt-5.6-sol` cross-falls back to `cockpit/gpt-5.6-luna` then `shopapikey/Claude-Fable`. `google-antigravity/*` uses the documented `google/* → google-vertex/* → shopapikey/Claude-Fable` wildcard pattern: `provider/*` entries swap provider keeping the model id, and ids absent on the target provider are skipped without error (expected and permitted — `google`/`google-vertex` may not be configured). No role has both a role chain and a matching model key, avoiding precedence ambiguity.
- **D5: isolated smoke test is a hard gate; judged on the requested selector; live update is atomic rename.** All seven distinct final selectors are smoke-tested in a throwaway profile (`/Users/androidteam/.omp/profiles/omp-tune-test/agent`); every one must return pong/exit 0 ON ITSELF — a 401 that silently recovers via fallback (error/model_change lines in output) FAILS the gate, because fallback recovery is a separate resilience scenario and can never substitute for selector acceptance. Fresh profiles lack native-provider credentials, so the profile's `agent.db` `auth_*` tables are seeded READ-ONLY from the live `agent.db` via `sqlite3` `ATTACH ... (mode=ro)` (prior run proved this necessary for `openrouter`/`google-antigravity` resolution). The validated `config.yml` is staged as a temp file beside the live one, permissions-set to match via `stat -f '%Lp'`, then atomically renamed over the live path — no in-place block replacement. YAML parse is verified with `uv run --with pyyaml`. Chain-hop resilience is checked separately inside a PROFILE COPY only, using the bogus env var `DEFINITELY_INVALID_ENV_VAR_XYZ`, never against live credentials.
- **D6: assumption — native catalog id.** The `google-antigravity` native catalog id is taken as `gemini-3.7-flash` per the current cached catalog (text+image, reasoning; no 3.7-lite exists). Confirmed live during apply: the selector ponged in both the isolated gate and live spot-checks.
- **D7: adapting to the interleaved `Claude-Fable` canonicalization.** Mid-apply (22:15:49, ~2.5 min after this change's atomic rename landed at 22:13:12), the separate concurrent `canonicalize-claude-fable-and-responses` change rewrote BOTH live files: it renamed the shopapikey model id `fable-5` → `Claude-Fable` in `models.yml` (the gateway's `/v1/models` now reports `Claude-Fable`) and substituted all six `shopapikey/fable-5` selectors in `config.yml` (the `commit` role plus all five chain hops), preserving this change's tuning structure byte-for-byte otherwise. Per the single-writer convention this rename is owned by that change, not this one; this change adopts the canonical id in its artifacts and final state rather than fighting it (rolling back would restore a now-unresolvable `fable-5` id against a `models.yml` that no longer defines it). Evidence of the interleave: `*.bak-pre-claude-fable.20260825T221454` backups capture this change's tuned-but-pre-rename state; this change's own `*.bak.20260825T221312` backups capture the pre-tune state. After the rename, the full seven-selector gate was re-run in the isolated profile mirrored to the final state, and all seven selectors were re-smoked live.

## Risks / Trade-offs

- **`:high` on background roles costs more thinking tokens** than `:low` — accepted per explicit user direction; revisit if spend/latency becomes an issue.
- **Antigravity unproven in-session** (catalog-cached, not yet observed in a live call at planning time) → the isolated seven-selector smoke test was the gate; it passed, and post-rollout failures are mitigated by the `google-antigravity/*` wildcard chain and the inherited default chain behind it.
- **Cockpit is localhost (51006)** → luna↔sol cross-fallback cannot cover full-cockpit outage; second hops leave the provider by design.
- **`google/*` / `google-vertex/*` hops may be unconfigured** → skipped-if-absent semantics make this benign; `shopapikey/Claude-Fable` is the guaranteed terminal hop of the wildcard chain.
- **Chain-hop checks mutate only a profile copy** — the bogus env var `DEFINITELY_INVALID_ENV_VAR_XYZ` is written into the copy's `models.yml` `apiKey` fields, never into live files; live md5 equality was re-asserted after the smoke phase.
- **Concurrent-writer risk materialized once (D7)** and was absorbed safely because both writers used timestamped backups and structure-preserving edits; future live mutations should re-assert file md5s immediately before staging.
