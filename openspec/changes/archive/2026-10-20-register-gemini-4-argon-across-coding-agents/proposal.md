# Proposal

## Why

Although OmniRoute now serves the four Ultra-pinned Gemini 4 Argon routing combos (`gemini-4-argon`, `gemini-4-argon-high`, `gemini-4-argon-medium`, and `gemini-4-argon-low`) and OMP (`~/.omp/agent/`) declares them in its model catalog, the remaining installed coding agents and editor integrations across the workstation lack `gemini-4-argon*` model declarations under their existing OmniRoute providers, preventing on-demand model and provider selection via CLI flags or interactive `/model` pickers. Registering the four `gemini-4-argon*` combos under each tool's existing OmniRoute provider block while preserving current startup defaults and role bindings (`gemini-3.8-flash-high`, `moa`, `muse-spark-1.3`, `mc/muse-spark-1.3`, `omniroute/sh/codex`, and OMP's `cockpit/gpt-6.1-sol:high` default / `google-antigravity/gemini-4-argon*` roles) enables immediate on-demand Gemini 4 Argon selection across the coding-agent fleet without draining the two-account Google AI `Ultra` quota pool on background or default turns.

### Non-Goals

- Creating duplicate per-model provider blocks literally named `gemini-4-argon` or duplicating `gemini-4-argon*` into secondary/legacy `omniroute` provider blocks in Pi, Prime Agent, OpenCode, or Kilo Code.
- Changing startup default models or role assignments across any CLI or editor.
- Modifying OmniRoute combo definitions, Google AI `Pro`/`Ultra` account pools, or git-tracked files inside `/Users/androidteam/Omniroute`.
- Mutating inactive legacy `~/.kimi/config.toml` or unconfigured/vendor-locked/wrapper CLIs (`qoder`/`qodercli`, `cursor-agent`, `auggie`, `happy`, `buzz`).
