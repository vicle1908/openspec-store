# Design

## Context

See `proposal.md` — Why for motivation.

Earlier today (`2026-10-19-configure-omniroute-gemini-4-argon-tier-combos`), OmniRoute (`http://127.0.0.1:20128`, `v3.8.51`) was provisioned with four Ultra-pinned Gemini 4 Argon routing combos (`gemini-4-argon`, `gemini-4-argon-high`, `gemini-4-argon-medium`, and `gemini-4-argon-low`, `context_length: 1000000`, `max_output_tokens: 65536` per upstream `antigravitySharedModels.ts`, `strategy: "auto"`, `context_cache_protection: false` with per-connection session stickiness across the two Google AI `Ultra` `agy` CLI accounts) and OMP (`~/.omp/agent/models.yml` and `~/.omp/agent/config.yml`) was updated with those four models and fallback chains.

Across the remaining workstation coding CLIs and editor integrations (`pi`, `prime-agent`, `hermes`, `opencode`, `kilo`, `codex`, `kimi-code`, `grok`, `goose`, `droid`, `claude`, `muse`, `qwen`, and Zed), `gemini-4-argon*` is either absent or incomplete (Hermes only lists `gemini-4-argon` and lacks `-high`, `-medium`, `-low` under `discover_models: false`). Unconfigured, vendor-locked, or pass-through wrapper CLIs without an existing OmniRoute provider block (`qoder`/`qodercli`, where `providers.<id>` is gated by remote `featureSwitches.allow_byok >= 2` and hardcoded to `customProviderAccessMode: "disabled"` in headless runs; `cursor-agent`; `auggie`; `happy`; `buzz`) and inactive legacy `~/.kimi/config.toml` remain untouched per `omniroute-agent-cli-routing`.

## Goals / Non-Goals

**Goals:**
- Expose `gemini-4-argon`, `gemini-4-argon-high`, `gemini-4-argon-medium`, and `gemini-4-argon-low` (`1,000,000` context window, authoritative `65,536` max output tokens) under each tool's existing active OmniRoute provider block so users can select both the OmniRoute provider and any of the four Argon models via CLI flags (`--model`, `-m`, `--provider`) or interactive `/model` pickers.
- Preserve every tool's existing pre-mutation startup default model and role bindings (`gemini-3.8-flash-high`, `moa`, `muse-spark-1.3`, `mc/muse-spark-1.3`, `omniroute/sh/codex`, and OMP's live `modelRoles`: unflagged `default` resolving to `cockpit/gpt-6.1-sol:high`, `advisor: cockpit/gpt-6.1-sol:xhigh`, `plan`/`task: google-antigravity/gemini-4-argon:high`, `smol: google-antigravity/gemini-4-argon`, `tiny`/`vision`/`slow`/`commit: omniroute/gemini-3.8-flash-high`).
- Enforce client-specific wire dialect, credential indirection, and permission invariants (`0600` on all credential/provider configs and external backups; `0644` preserved on public metadata catalog `~/.codex/cockpit-model-catalog.json`).
- Verify every mutated CLI with a deterministic catalog check across all four model IDs, a 1-turn non-interactive sentinel call (`gemini-4-argon-low`) with OmniRoute combo attribution (`X-OmniRoute-Combo-Trace` / zero fallback events), and a default-model preservation check.

**Non-Goals:**
- Introducing duplicate per-model provider blocks literally named `gemini-4-argon` or duplicating `gemini-4-argon*` into secondary/legacy `omniroute` Chat-Completions blocks in Pi, Prime Agent, OpenCode, or Kilo Code.
- Modifying OmniRoute combo definitions or git-tracked files inside `/Users/androidteam/Omniroute`.
- Mutating `~/.pi/agent/settings.json`, `~/.prime/agent/settings.json`, `~/.codex/config.toml`, legacy `~/.kimi/config.toml`, or unconfigured/vendor-locked/wrapper CLIs (`qoder`/`qodercli`, `cursor-agent`, `auggie`, `happy`, `buzz`).

## Decisions

### Decision 1: Register Only Under Each Tool's Active OmniRoute Provider Without Duplication

- **Choice**: Add `gemini-4-argon`, `gemini-4-argon-high`, `gemini-4-argon-medium`, and `gemini-4-argon-low` exclusively inside each tool's active OmniRoute Responses/primary provider (`omniroute-responses` in Pi, Prime Agent, OpenCode, and Kilo Code; `omniroute` in OMP, Hermes, Codex, Grok, and Zed; `omniroute-anthropic` in Kimi Code; `custom_omniroute` in Goose; `customModels[]` in Droid; `modelPicker.options` in Claude `omniroute-pm.json`; `model_catalog` under `meta` in Muse Code; `modelProviders.openai[]` in Qwen Code).
- **Rationale**: In Pi, Prime Agent, and OpenCode, `gemini-3.8-flash-high` lives solely in `omniroute-responses` while `omniroute` holds legacy `sh/*` entries (`api.endpoint: "chat"` in OpenCode); in Kilo Code (`~/.config/kilo/kilo.jsonc`), `provider.omniroute` uses `@ai-sdk/openai-compatible` and has no `options.apiKey` configured, whereas `provider.omniroute-responses` uses `@ai-sdk/openai` (`/v1/responses`) with `"{env:OMNIROUTE_API_KEY}"`. Registering only in `omniroute-responses` prevents unauthenticated fallback, dialect regressions, and duplicate `/model` picker entries.
- **Alternatives Considered**: Registering in both `omniroute` and `omniroute-responses` or creating a new `providers.gemini-4-argon` block — rejected because it duplicates picker rows and hits unauthenticated/Chat-Completions `provider.omniroute` in Kilo and OpenCode.

### Decision 3: External Execution Boundary, Owner Mode-Tightening Gate, and Atomic Rollback

- **External Execution Boundary & Backup Directory (`~/.omniroute/backups/register-gemini-4-argon-across-coding-agents/`)**:
  - Central store `allowedEditRoots` covers `/Users/androidteam/Developer/platform/openspec-store`. Mutating the 14 external `$HOME` files listed in Decision 2 requires recording an external execution packet in `evidence.md` (exact target paths, timestamps, pre/post SHA-256 digests, file modes, and read-back verification).
  - Before mutating any file, copy the original file into `~/.omniroute/backups/register-gemini-4-argon-across-coding-agents/` with mode `0600` (`chmod 600`), relocate the 4 stale `~/.prime/agent/*.bak*` files into that backup directory, and record each file's pre-mutation SHA-256 digest and mode (`stat -L -f '%04Lp'`).
- **Owner Mode-Tightening & Rotation Gates**:
  - Per `omniroute-agent-cli-routing` (`Requirement: Mode tightenings SHALL be named-approved before apply`) and `omniroute-closure-integrity`, record the owner's named approval (`approver`, timestamp, target path, `0644 -> 0600`) in `evidence.md` when tightening `/Users/androidteam/.factory/settings.json`, `/Users/androidteam/.config/muse/settings.json`, and `/Users/androidteam/.qwen/settings.json` to `0600` (while `/Users/androidteam/.codex/cockpit-model-catalog.json` preserves `0644`).
  - For `/Users/androidteam/.kimi-code/config.toml`, cite the archived accepted-risk rotation release (`2026-09-02-invalidate-archive-gaps-closure-fabrications/evidence/rotation-gate-release.json`, `decision: "authorized_without_rotation"`) and perform value-blind TOML updates without exposing or rotating any `[providers.*]` `api_key`.
- **Pre-Write SHA-256 Guard, Atomic Write, and Per-File Rollback**:
  - Immediately before writing each target file, verify that its current on-disk SHA-256 still equals its recorded pre-mutation backup SHA-256 (preventing silent overwrite of concurrent edits).
  - Write each updated configuration to a sibling `.tmp` file with its target mode (`0600` for provider/credential configs; `0644` for `~/.codex/cockpit-model-catalog.json`), validate syntax (`jq`, `python3 -c 'import tomllib'`, `uv run --with pyyaml python3 -c 'import yaml'`), and atomically replace via `os.replace()`.
  - If any CLI fails its 4-model catalog check, 1-turn attributed sentinel check (`gemini-4-argon-low`), or default-preservation check, immediately restore its backup from `~/.omniroute/backups/register-gemini-4-argon-across-coding-agents/`.

## Risks / Trade-offs

- **Risk: Exhausting the 2-account Google AI `Ultra` quota during fleet verification** → **Mitigation**: Keep all startup defaults unchanged, verify all 4 model IDs (`gemini-4-argon{,-high,-medium,-low}`) via deterministic local catalog/parser commands, and run the 1-turn live sentinel probes using `gemini-4-argon-low` (`reasoning_effort = low`, single-token reply `"ARGON_<CLI>_OK"`).
- **Risk: Silent fallback masking a broken `gemini-4-argon-low` route** → **Mitigation**: Correlate every 1-turn sentinel probe with OmniRoute's combo trace / request log (`model=gemini-4-argon-low` -> `agy/gemini-4-argon-low` on Ultra connection `338764b8-1cd7-4946-b789-ee5dad4c5073` or `0532bad4-2486-4286-8f06-510e9c678620`, zero client fallback events).
- **Risk: Kimi Code literal credential exposure during edit** → **Mitigation**: Update `~/.kimi-code/config.toml` programmatically in memory without printing or logging any `[providers.*]` `api_key` values (`value-blind-config-audit`).
