# Proposal

## Why

The Pi Coding Agent (`pi` v1.4.0) runtime configuration and its supporting integrations suffer from eight verified regressions and misconfigurations that bloat per-turn prompt schemas by ~40,000 tokens, register 108 skill snapshots as bogus project subagents, fail AgentMemory authentication with `HTTP 401`, invalidate provider prompt caches, inject unwanted OmniRoute built-in `Memory context:` prefixes, expose plaintext secrets in `0644` files, and corrupt file-read tool outputs over OmniRoute's `/v1/responses` compression pipeline.

Specifically:
1. **Oversized Direct MCP Surface & Startup Blocking (`~/.pi/agent/mcp.json`)**: Setting `"exposure": "direct"` on `mcp-router` injects 138 tool schemas into every turn (duplicating Pi's native `read`/`write`/`edit`/`bash` with 25 Desktop Commander tools, 7 `pi-gitnexus` tools, 3 `agentmemory` tools, and `pi-web-access` search tools) and forces `hasDirectTools(entry) === true`, blocking the first prompt for up to 10 seconds while `npx -y @mcp_router/cli@latest connect` starts. It also stores a literal `MCPR_TOKEN` inline.
2. **Skill Snapshot Subagent Pollution (`pi-subagents` v0.84.0)**: `isLegacyAgentSkillPath()` in `pi-subagents` only skips `.agents/skills/**` and does not skip `~/Developer/.agents/.skill-snapshots/{current,previous}/**`, causing 108 skill markdown files to be registered as high-precedence `(project)` subagents that can shadow builtin agents (`scout`, `researcher`, `worker`, `reviewer`, `oracle`, `delegate`).
3. **Silent `HTTP 401` Auth Failure & Prompt-Cache Busting in `~/.pi/agent/extensions/agentmemory/index.js`**: `AGENTMEMORY_SECRET` is defined in `~/.agentmemory/.env` rather than `~/.zshenv` (and is stripped by parent agent harnesses), causing every `smart-search`, `remember`, and `observe` call to fail with `HTTP 401 Unauthorized` while `health` reports green. Furthermore, `before_agent_start` has no request timeout and returns `{ systemPrompt: ... }`, which sets `forceSystemPrompt` in Pi 1.4.0—destroying structured `SystemPromptSections` and overwriting byte 0 of the system prompt on every user turn, invalidating 100% of the provider prompt cache whenever memories are recalled.
4. **OmniRoute `/v1/responses` RTK File-Read Corruption (`~/Omniroute/scripts/container-entrypoint-compat.sh`)**: When adapting OpenAI Responses `body.input` (`function_call` and `function_call_output`) for compression engines inside the `omniroute` container (`chunks/{14211,41669,72459,88137,98542,53846}.js`), `bodyAdapter` omits `function_call` items and synthesizes `{ role: "tool" }` messages without `tool_call_id` or `toolCallLookup` entries. Consequently, `resolveToolMeta()` in `rtk` receives `callId = null` and returns `{ command: null, skipFilters: false }` for non-shell tools (`read`, `grep`, `edit`), running 55 shell log filters (`npm-audit`, `json-output`) against file-read outputs and stripping ~80% of lines from JSON/config files.
5. **World-Readable `web-search.json` & Broken Placeholder (`~/.pi/web-search.json`)**: Lives at the legacy `~/.pi/web-search.json` path with mode `0644`, embeds literal `exaApiKey` and `geminiApiKey` strings alongside a broken placeholder `"perplexityApiKey": "pplx-..."`, and fails to wire `$BRAVE_SEARCH_API_KEY`, `$TAVILY_API_KEY`, and `$FIRECRAWL_API_KEY` into `pi-web-access` v0.46.0's `searchRouting` and `fetchRouting`.
6. **Missing `pi-lens` Global Configuration (`~/.pi-lens/config.json`)**: Without a global config, `pi-lens` v4.4.7 defaults to `contextInjection.retain = false` (dropping injected diagnostics on the next turn and invalidating prefix caches) and `contextInjection.requirePreExistingFixes = true` (instructing the agent to fix pre-existing repository lint/type errors outside the active OpenSpec task scope), while accumulating unbounded logs (`latency.log` 9.9 MB, `sessionstart.log` 4.9 MB).
7. **Core `settings.json` & `models.json` Schema, Header, and Thinking-Map Drift**: Both files lack official `"$schema"` declarations; `settings.json` sets `"transport": "websocket"` globally instead of `"auto"`, keeps a redundant `"extensions": ["+builtin:mcp"]` entry, uses a small `reserveTokens: 16384` / `keepRecentTokens: 20000` compaction budget for 1M-context models, and references a non-existent `"cockpit/gpt-5.6-sol"` in `modelThinkingLevels`; and `models.json` omits `"headers": { "x-omniroute-no-memory": "true" }` on OmniRoute providers (causing OmniRoute to prepend `Memory context:` onto Pi prompts) and has conflicting `thinkingLevelMap` definitions for `sh/codex-x` between `omniroute` and `omniroute-responses`.
8. **Stale Release Artifacts, Updater Verb, Hermes Skill & Notion/Wiki Docs**: `~/.pi/agent/` retains 147 MB of superseded `releases/1.3.0`, `.bak*` clutter, and orphaned `pi-hermes-memory` directories (`memory/`, `tdt/`, `projects-memory/`); `workstation-daily-update.sh` runs `pi update --self` (leaving the 5 managed npm packages un-updated); `~/.hermes/skills/autonomous-ai-agents/pi/SKILL.md` is stuck at Pi `v0.84.1` (`/opt/homebrew/bin/pi`, `shopapikey/fable-5`, `pi-mcp-adapter`); and `wiki/entities/pi.md` (synced to Notion page `3efc4b21-deb4-8129-b9c3-d7c22a453212`) still prescribes `"exposure": "direct"`.

### Non-Goals

- Changing Pi's default startup provider or model (`omniroute-responses/gemini-3.8-flash-high`), removing existing providers in `~/.pi/agent/models.json`, altering OmniRoute combo definitions, or modifying git-tracked files inside `/Users/androidteam/Omniroute`.
- Narrowing project trust in `~/.pi/agent/trust.json` (`/Users/androidteam/Developer` remains trusted by explicit operator policy).
- Rewriting third-party npm packages inside `~/.pi/agent/npm/node_modules/` (all package customizations use supported configuration files).
- Modifying any Go, Python, or mobile application service code.

## What Changes

- **Switch `mcp-router` in `~/.pi/agent/mcp.json` to `"exposure": "codemode"` with `toolExposure` filtering and credential indirection**: Set `"exposure": "codemode"`, add a static `"description"` so the `mcp_servers` prompt section is stable from Turn 1, set `"toolExposure"` to `"hidden"` for the 25 redundant Desktop Commander tools, replace the inline `MCPR_TOKEN` literal with `"${MCPR_TOKEN}"` (exported in `~/.zshenv`), and enable `"defaultTools": ["+codemode", "+tool_search"]` in `~/.pi/agent/settings.json`.
- **Configure `pi-subagents` discovery boundaries and role overrides in `~/.pi/agent/settings.json`**: Configure `subagents.agentExcludeDirs` to exclude `~/.agents/skills`, `~/.agents/.skill-snapshots`, `/Users/androidteam/Developer/.agents/skills`, and `/Users/androidteam/Developer/.agents/.skill-snapshots` (eliminating all 108 bogus project subagents), and configure role-appropriate `agentOverrides` (`scout`, `researcher`, `reviewer`, `oracle`) using explicit `model` and `thinking` fields.
- **Harden and make `~/.pi/agent/extensions/agentmemory/index.js` prompt-cache safe**: Export `AGENTMEMORY_SECRET` in `~/.zshenv` and add a fallback loader in `agentmemory/index.js` reading `AGENTMEMORY_SECRET` from `~/.agentmemory/.env` when stripped from `process.env`; bound `callAgentMemory` requests with a 2,500 ms `AbortSignal.timeout`; unconditionally push `TOOL_GUIDANCE` into `event.systemPromptOptions.promptGuidelines` before early returns; return `{ message: { customType: "agentmemory-recall", content: recallBlock, display: false } }` instead of overwriting `systemPrompt`; and remove the stale `/Users/androidteam/Developer/.agentmemory/` directory.
- **Fix OpenAI Responses tool-call metadata preservation in OmniRoute (`~/Omniroute/scripts/container-entrypoint-compat.sh`)**: Patch compiled `bodyAdapter` and `rtk` server chunks (`14211.js`, `41669.js`, `72459.js`, `88137.js`, `98542.js`, `53846.js`) via `~/Omniroute/scripts/container-entrypoint-compat.sh` (`ensure-muse-wire-compat.sh`) with fail-closed `requiredMarkers`—keeping `~/Omniroute` git status clean—so `adaptBodyForCompression()` preserves `call_id` -> `tool_call_id` and `rtk` populates `toolCallLookup` from `body.input` `type: "function_call"` items, ensuring `resolveToolMeta()` sets `skipFilters: true` for non-shell tools (`read`, `glob`, `grep`, `write`, `edit`) over `/v1/responses`.
- **Migrate `pi-web-access` config to `~/.pi/agent/web-search.json` (`0600`) with `$ENV_VAR` indirection and multi-provider routing**: Export `GEMINI_API_KEY` in `~/.zshenv`, relocate `~/.pi/web-search.json` (`0644`) to `~/.pi/agent/web-search.json` (`0600`), replace literal keys with `"$EXA_API_KEY"`, `"$BRAVE_SEARCH_API_KEY"`, `"$TAVILY_API_KEY"`, `"$FIRECRAWL_API_KEY"`, and `"$GEMINI_API_KEY"`, remove `"perplexityApiKey": "pplx-..."`, and configure `searchRouting` (`["exa", "brave", "tavily"]`) and `fetchRouting` (`["http", "firecrawl"]`).
- **Create `~/.pi-lens/config.json` (`0600`) and truncate oversized logs**: Configure `contextInjection.retain = true` (cache-stable injections), `contextInjection.requirePreExistingFixes = false` (scope-bounded error demands), global `ignore` patterns for `.skill-snapshots`, `graphify-out`, `.gitnexus`, and `openspec/changes/archive`, and truncate `~/.pi-lens/latency.log` and `sessionstart.log`.
- **Align `~/.pi/agent/settings.json` and `~/.pi/agent/models.json` with Pi v1.4.0 schemas and OmniRoute memory opt-out**: Add official `"$schema"` URLs, set `"transport": "auto"`, remove redundant `"extensions": ["+builtin:mcp"]`, tune `compaction` (`reserveTokens: 65536`, `keepRecentTokens: 40000`), add `"headers": { "x-omniroute-no-memory": "true" }` to `omniroute`, `omniroute-anthropic`, and `omniroute-responses` in `models.json`, align `sh/codex-x` `thinkingLevelMap` across `omniroute` and `omniroute-responses` while preserving all existing providers, and reconcile `modelThinkingLevels` keys in `settings.json` with actual `models.json` entries.
- **Reclaim ~150 MB of stale `~/.pi` artifacts, upgrade Stage 5 to `pi update --all`, and sync Hermes Skill + Wiki + Notion**: Remove `~/.pi/agent/install/releases/1.3.0`, `.bak*` files, and orphaned `pi-hermes-memory` directories (`memory/`, `tdt/`, `projects-memory/`); update `pi:Pi:update --self` to `pi:Pi:update --all` in `~/Developer/scripts/workstation-daily-update.sh` and `platform/openspec-store/scripts/workstation-daily-update.sh`; update `~/.hermes/skills/autonomous-ai-agents/pi/SKILL.md` to Pi v1.4.0; and update `~/Developer/wiki/entities/pi.md` with Notion sync (`--section entities` -> page `3efc4b21-deb4-8129-b9c3-d7c22a453212`).

## Capabilities

### New Capabilities
- `pi-agent-harness-config`: Governs Pi Coding Agent (`~/.pi/agent/` and `~/.pi-lens/`) configuration, schema conformance, OmniRoute `x-omniroute-no-memory` header opt-out, native MCP `codemode` and `toolExposure` routing, `pi-subagents` discovery exclusions and role overrides, `pi-web-access` credential indirection and provider routing, `pi-lens` cache-preserving context injection, artifact hygiene, and documentation parity.

### Modified Capabilities
- `developer-memory`: Update the Pi AgentMemory integration requirement so `~/.pi/agent/extensions/agentmemory/index.js` resolves `AGENTMEMORY_SECRET` from the environment or `~/.agentmemory/.env` fallback with bounded timeouts and injects guidance/recall without overwriting `systemPrompt` (`forceSystemPrompt`) on subsequent turns.
- `omniroute-compression-and-routing`: Update the RTK tool-result compression requirement so OpenAI Responses `input[]` adaptation preserves `function_call` tool metadata (`toolName`, `command`, `tool_call_id`), preventing content-based shell filters from truncating non-shell file-read tool outputs.

## Impact

- **Ownership Boundaries**:
  - **Pi Agent Configuration & Extensions (`~/.pi/agent/`, `~/.pi-lens/`)**: `~/.pi/agent/settings.json`, `~/.pi/agent/models.json`, `~/.pi/agent/mcp.json`, `~/.pi/agent/web-search.json` (moved from `~/.pi/web-search.json`), `~/.pi/agent/extensions/agentmemory/index.js`, `~/.pi-lens/config.json`, and cleanup of `~/.pi/agent/install/releases/1.3.0`, `.bak*`, and orphaned `pi-hermes-memory` directories.
  - **Shared Shell Credentials (`~/.zshenv`)**: Exports `MCPR_TOKEN`, `AGENTMEMORY_SECRET`, and `GEMINI_API_KEY` (`0600` preserved).
  - **OmniRoute Gateway (`~/Omniroute/`)**: Untracked startup patch script `~/Omniroute/scripts/container-entrypoint-compat.sh` (`ensure-muse-wire-compat.sh`) applied inside running Docker container `omniroute` (`git status` on tracked files remains clean).
  - **Workstation Automation & Knowledge (`~/Developer/`, `~/.hermes/`)**: `~/Developer/scripts/workstation-daily-update.sh` (and its mirror in `platform/openspec-store/scripts/workstation-daily-update.sh`), `~/.hermes/skills/autonomous-ai-agents/pi/SKILL.md`, `~/Developer/wiki/entities/pi.md`, and Notion page `3efc4b21-deb4-8129-b9c3-d7c22a453212`.
