# Proposal

## Why

The Pi Coding Agent (`pi` v1.4.0) runtime and its OmniRoute `/v1/responses` gateway pipeline still suffer from five verified post-alignment defects that strip up to 93% of non-shell and custom tool outputs (`subagent`, `codemode`, `pi-lens`, `gitnexus`), silently disable multi-provider web-search routing and Firecrawl extraction, overwrite Pi 1.4.0's structured `SystemPromptSections` via `pi-gitnexus`'s `forceSystemPrompt` while firing redundant `agentmemory` network calls in child subagents, collapse mid-conversation system prompt patches on `omniroute-responses`, and bloat every session's `<available_skills>` prompt with 44 internal OmniRoute CLI management skills alongside unbounded `~/.pi-lens/*.log` growth.

Specifically:
1. **OmniRoute `/v1/responses` Stacked Compression Corrupts Non-Shell and Custom Tool Outputs (`~/Omniroute/scripts/container-entrypoint-compat.sh`)**: In `strategySelector.ts`, `adaptBodyForCompression(body)` runs before `applyStackedCompression` and executes `delete t.input`. Consequently, when `applyRtkCompression` (`chunks/53846.js` and `72459.js`) runs inside the `default-caveman` stacked pipeline (`[session-dedup, lite, rtk, codex-responses, headroom]`), `Array.isArray(a.input)` is `false` and `toolCallLookup` (`m`) is always empty (`m.size === 0`). Because `markCodexResponseEligibility` (`chunks/{14211,41669,72459,88137,98542}.js`) skips `custom_tool_call_output` and `apply_patch_call_output` items before setting `c._rtkSkip` and only protects the 9 hardcoded names in `DEFAULT_CODEX_PROTECTED_TOOL_NAMES` (`read`, `glob`, `grep`, `write`, `edit`, `websearch`, `webfetch`, `web_search`, `web_fetch`), every other Pi tool (`subagent`, `codemode`, `tool_search`, `effective_config`, `module_report`, `project_report`, `symbol_search`, `read_symbol`, `read_enclosing`, `lens_diagnostics`, `gitnexus_*`, `memory_*`, `fetch_content`, `get_search_content`, `source_check`, `intercom`, plus grammar-constrained `custom_tool_call_output` items) receives `c._rtkSkip = false`. In live sessions, `subagent({ action: "list" })` loses 14 of 15 lines (matching RTK's `npm-audit` filter on the word `High` in `High-context`), `subagent({ action: "models" })` loses 100% of agent names, `subagent({ action: "doctor" })` loses 29 lines to `codex-responses` `collapseLines`, and `bash` tool calls lose their `command` metadata.
2. **`pi-web-access` Multi-Provider Search Routing Disabled & Firecrawl Unavailable (`~/.pi/agent/web-search.json`)**: In `pi-web-access` v0.46.0 (`gemini-search.ts`), `getConfiguredSearchRouting()` returns `undefined` whenever `"provider"` or `"searchProvider"` is present in `web-search.json` (`config.searchProviderConfigured === true`). Because `~/.pi/agent/web-search.json` sets `"provider": "exa"`, `searchRouting` (`["exa", "brave", "tavily"]`) is completely bypassed. Additionally, `firecrawl.ts` has no default base URL and requires `firecrawlBaseUrl` (or `FIRECRAWL_BASE_URL`), so `isFirecrawlAvailable()` returns `false` and `fetchRouting` (`["http", "firecrawl"]`) never falls back to Firecrawl. Finally, `"workflow": "summary-review"` blocks top-level interactive/RPC `web_search` calls for 20 seconds on the local Curator UI server, and `"searchModel": "gemini-2.5-flash"` overrides the v0.46.0 default `"gemini-3.6-flash"`.
3. **`pi-gitnexus` (`0.6.4`) Sets `forceSystemPrompt` and Appends Empty Banners while `agentmemory` Fires Redundant Child-Subagent Calls (`~/.pi/pi-gitnexus.json`, `~/.pi/agent/extensions/agentmemory/index.js`)**: Because `/Users/androidteam/Developer/.gitnexus` exists at the workspace root (holding `groups/workspace/`), `findGitNexusIndex(ctx.cwd)` returns `true` across `/Users/androidteam/Developer`. On every turn, `pi-gitnexus`'s `before_agent_start` handler returns `{ systemPrompt: event.systemPrompt + "\n\n[GitNexus active] ..." }`, setting `currentOptions.forceSystemPrompt` in Pi 1.4.0—which forces `_installAgentForcedPromptProjection()` to collapse mid-conversation `role: "system"` section updates and invalidates prompt-cache reuse for forked subagents (`oracle`). Furthermore, on every `read`, `grep`, `find`, and `bash` tool call, `pi-gitnexus` spawns `gitnexus augment <pattern>`, treats the bare stderr version line `"GitNexus Augment (1.6.12)"` as a non-empty hit, and appends `---\n[GitNexus: <name>]\nGitNexus Augment (1.6.12)\n---` even when zero symbols match. Meanwhile, `agentmemory/index.js` runs `smart-search` and `observe` network calls for every child subagent (`PI_SUBAGENT_CHILD` / `parentSession`), adding latency and polluting long-term memory with child scratch work.
4. **Missing `compat` Flags on `omniroute-responses` and Custom Providers (`~/.pi/agent/models.json`)**: Custom models in `~/.pi/agent/models.json` default to `supportsMidConvoSystemMessages: false`, causing Pi 1.4.0 to call `collapseSystemMessages(transcript)` and rewrite byte 0 of the leading system prompt whenever any structured prompt section (`active_subagents`, `advertised_subagents`, `mcp_servers`, or `selectedTools`) changes mid-session. In addition, `omniroute-responses` (Pi's default provider) is missing `"compat": { "supportsLongCacheRetention": true }`.
5. **Unfiltered OmniRoute Internal Skills, Unadvertised Core Subagents, Untrusted OmniRoute Path & Unbounded Pi-Lens Logs (`~/.pi/agent/settings.json`, `~/.pi/agent/trust.json`, `~/Developer/scripts/workstation-daily-update.sh`)**: Pi auto-discovers 196 skills (`92,157` chars / `~23,000` tokens in `<available_skills>`), including 44 non-symlinked OmniRoute internal CLI skills (`cli-*` and `omni-*`) in `~/.agents/skills/`; `subagents.agentOverrides` in `settings.json` omits `"advertise": true` (leaving `<advertised_subagents>` empty); `~/.pi/agent/trust.json` omits `"/Users/androidteam/Omniroute": true` (causing `pi-lens` to refuse project-local LSP binaries when inspecting `~/Omniroute`); and `~/.pi-lens/*.log` (`latency.log`, `read-guard.log`, `extension.log`) regrows without automated size-bounded truncation.

### Non-Goals

- Changing Pi's default provider/model (`omniroute-responses/gemini-3.8-flash-high`), removing any of the 6 providers in `~/.pi/agent/models.json`, or removing any of the 5 managed npm packages in `~/.pi/agent/settings.json`.
- Deleting or modifying `/Users/androidteam/Developer/.gitnexus` (which is governed by `refresh-gitnexus-index-groups` and `gitnexus-stable-contract`) or deleting skill directories inside `/Users/androidteam/Developer/.agents/skills/` or `~/.agents/skills/` (which are governed by `agent-skill-distribution` and `sync-workspace-agent-skills.py`).
- Modifying git-tracked files in `/Users/androidteam/Omniroute` or patching files inside `~/.pi/agent/npm/node_modules/`.

## What Changes

- **Preserve OpenAI Responses `toolName`/`command` metadata across `adaptBodyForCompression`, protect `custom_tool_call_output`/`apply_patch_call_output`, and update `requiredMarkers` (`~/Omniroute/scripts/container-entrypoint-compat.sh`)**: Update the `markCodexResponseEligibility` replacement rule across compiled chunks `14211.js`, `41669.js`, `72459.js`, `88137.js`, and `98542.js` so it extracts both `toolName` and `command` (from `arguments.command` / `arguments.cmd`) from `body.input` `type: "function_call"` items before `delete t.input`, sets `c._rtkSkip = true` on `custom_tool_call_output` and `apply_patch_call_output` items, sets `a.eligible` to `true` on `function_call_output` items only for shell tools (`/\b(bash|shell|terminal|run_command|execute_command|exec|command)\b/i` and not in `skippedCallIds`), and attaches `c._toolCommand` and `c._rtkSkip = !isShellTool || !a.eligible` to the adapted `role: "tool"` message. Update `applyRtkCompression` in `53846.js` and `72459.js` to read `a._toolCommand` when `toolCallLookup` (`m`) is empty, and update the 5 `responses_tool_call_id_*` and 2 `rtk_stacked_meta_skip_*` entries in `requiredMarkers` so fail-closed startup verification passes.
- **Enable `pi-web-access` multi-provider routing and Firecrawl fallback (`~/.pi/agent/web-search.json`)**: Remove `"provider": "exa"` so `getConfiguredSearchRouting()` activates `searchRouting` (`["exa", "brave", "tavily"]` with `exa` primary), add `"firecrawlBaseUrl": "https://api.firecrawl.dev"` so `isFirecrawlAvailable()` returns `true`, set `"workflow": "none"` so top-level `web_search` calls do not block on the Curator server, and set `"searchModel": "gemini-3.6-flash"`.
- **Disable `pi-gitnexus` auto-augment subprocesses (`~/.pi/pi-gitnexus.json`), intercept only the exact `[GitNexus active]` suffix on `forceSystemPrompt`, and skip child-subagent network calls (`~/.pi/agent/extensions/agentmemory/index.js`)**: Create `~/.pi/pi-gitnexus.json` (`0600`) with `{"autoAugment": false}` so `pi-gitnexus` stops spawning `gitnexus augment` and appending empty `GitNexus Augment (1.6.12)` banners on `read`/`grep`/`find`/`bash`. In `agentmemory/index.js`, install a `forceSystemPrompt` setter on `event.systemPromptOptions` that matches only the exact `\n\n[GitNexus active] ...` suffix (converting it into a `promptGuidelines` entry and leaving `forceSystemPrompt` `undefined` while passing child subagent `<active_agent>` boundary prompts through untouched), and skip `smart-search` and `observe` network calls when `process.env.PI_SUBAGENT_CHILD` or `parentSession` is present.
- **Configure `compat` flags on custom providers in `~/.pi/agent/models.json`**: Add `"compat": { "supportsLongCacheRetention": true, "supportsMidConvoSystemMessages": true }` to `omniroute-responses`, and add `"supportsMidConvoSystemMessages": true` to the `compat` blocks of `cockpit`, `omniroute`, `phanmemvip`, `shopapikey`, and `omniroute-anthropic`.
- **Filter internal OmniRoute CLI skills, advertise core subagents, trust `~/Omniroute`, and bound `~/.pi-lens/*.log` files (`~/.pi/agent/settings.json`, `~/.pi/agent/trust.json`, `~/Developer/scripts/workstation-daily-update.sh`)**: Add `"skills": ["!**/cli-*", "!**/omni-*"]` to `~/.pi/agent/settings.json`, add `"advertise": true` to `scout`, `researcher`, `reviewer`, `oracle`, and `worker` in `subagents.agentOverrides`, add `"/Users/androidteam/Omniroute": true` to `~/.pi/agent/trust.json`, add size-bounded (>5 MB) truncation of `~/.pi-lens/*.log` to `workstation-daily-update.sh` (and its mirror in `platform/openspec-store/scripts/workstation-daily-update.sh`), and update `~/.hermes/skills/autonomous-ai-agents/pi/SKILL.md` and `~/Developer/wiki/entities/pi.md` (synced to Notion page `3efc4b21-deb4-8129-b9c3-d7c22a453212`).
