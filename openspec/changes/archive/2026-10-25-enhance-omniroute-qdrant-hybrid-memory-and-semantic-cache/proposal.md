# Proposal

## Why

OmniRoute (`v3.8.52`, serving both local Mac Mini clients on `127.0.0.1:20128`/`20129` and remote Tailnet machines on `macbook-pro-ca-l-1.tailc6b508.ts.net` (`100.101.64.56`, `/Users/vinhlk`) via `https://iosteam-mac-mini.tailc6b508.ts.net`) currently runs only its Layer-1 exact-match SHA-256 response cache (`14.8%` hit rate, `393,864` tokens saved) with Layer-2 vector semantic caching disabled, Qdrant (`qdrant/qdrant:v1.12.4`) inactive, and internal memory turned off. Furthermore, five upstream and cross-machine behavioral constraints must be coordinated:
1. **Cross-machine API key vs. keyless pool unification (`mac-mini-1` vs. keyless)**: Remote MacBook Pro (`/Users/vinhlk`) and local OMP/CLI sessions authenticate with the shared `mac-mini-1` key (`id: 6a72d8ab-88db-4d49-973b-864c6cbdace5`, `21,850` calls) alongside `3,153` keyless local calls. Upstream `resolveMemoryOwnerId()` returns `null` for keyless requests (skipping memory) and `apiKeyId` prefixing splits Layer-1/Layer-2 cache and memory pools between keyless and `mac-mini-1` traffic unless keyless fallback defaults to the shared workspace owner (`6a72d8ab-88db-4d49-973b-864c6cbdace5` / `"global"`).
2. **Coexistence with MacBook Pro OMP session's 8 `container-entrypoint-compat.sh` rules & combo pins**: The concurrent MacBook Pro OMP session recently landed 8 production rules in `/Users/androidteam/Omniroute/scripts/container-entrypoint-compat.sh` (Gemini-4 trailing `role: "model"` turn stripping, `\bmodel(?!\s+turn\b)` lockout guards, `agy` exact-model lockout scoping, `{id:"model-turn",pattern:/ending with a model turn/i}`, immediate 1-turn `model-turn` stop `function v(a)`, and consumer `agy` OAuth `aicode-consumers` header omission in `86370.js`), added `OMNIROUTE_SQLITE_SLOW_MS=200` to `docker-compose.override.yml`, and pinned `gemini-4-argon*` combos to the 2 Ultra `agy` accounts (`338764b8`, `0532bad4`). All 8 compat rules, combo pins, and `default-caveman` compression assignments MUST be preserved intact.
3. **Semantic cache embedding, bootstrap, and contract gates**: `resolveProviderConnectionDetails()` (`src/lib/cache/semanticCacheDbBridge.ts`) does not fall back to `EMBEDDING_PROVIDERS[provider].baseUrl`, causing cloud embedding probes to fail when `provider_specific_data.baseUrl` is unset; `ensureSemanticCacheDbBridge()` is not invoked on `/v1/responses` or `/v1/messages`; and `SemanticCacheManager` (`open-sse/services/cache/semanticCacheManager.ts:298,424`, `semanticProjection.ts`) skips Layer-2 vector similarity on both `lookup()` and `store()` whenever `outputContractOf(body)` is non-null (`tools`, `tool_choice`, `max_tokens`, `reasoning_effort`, `response_format`), `messages.length > 3`, or messages include tool fields—excluding nearly all coding-agent and reasoning traffic.
4. **Qdrant hybrid retrieval bypasses BM25 FTS5 fusion**: When `vectorStore === "qdrant"` and `strategy === "hybrid"`, `src/lib/memory/retrieval.ts:496-535` (and `retrievePreview`) returns Qdrant dense Cosine hits early without fusing SQLite `memory_fts` (BM25) lexical results via Reciprocal Rank Fusion (`RRF, k = 60`).
5. **Canonical spec alignment**: `openspec/specs/omniroute-compression-and-routing/spec.md` currently mandates `memoryEnabled: false`, which must be updated via `MODIFIED Requirements` (preserving existing requirement and scenario headers) to reflect always-on Qdrant + BM25 RRF + Rerank memory while keeping `skillsEnabled: false`.

Enabling a hybrid local+cloud architecture—combining **Host Ollama on Apple Metal (`nomic-embed-text`, `768d`, `<10ms`) + `omniroute-redis` (`redis:8.6.5-alpine`) for all-request Layer-2 Semantic Caching** with **`omniroute-qdrant` (`qdrant/qdrant:v1.12.4`, `int8` scalar quantization + `rescore: true`) + SQLite `FTS5` BM25 + `sqlite-vec` (`int8`) fallback + `voyage-ai/voyage-code-3` (`1024d`) + `voyage-ai/rerank-2.5` for Always-On Hybrid Memory**—maximizes cache hit rates and retrieval precision across both local Mac Mini and remote MacBook Pro sessions without exposing Qdrant externally.

## What Changes

- **Deploy Internal Qdrant Sidecar (`omniroute-qdrant`) & Enable `sqlite-vec` `int8` Quantization**:
  - Enable `qdrant` (`docker.io/qdrant/qdrant:v1.12.4`, `container_name: omniroute-qdrant`, persistent volume `qdrant-data:/qdrant/storage`, bound to `127.0.0.1:6333` and `127.0.0.1:6334` only, not exposed via Tailscale Serve) in `/Users/androidteam/Omniroute/docker-compose.override.yml` while preserving all existing `omniroute-base` settings (`OMNIROUTE_SQLITE_SLOW_MS=200`, `API_HOST=0.0.0.0`, log/table caps).
  - Set `QDRANT_ENABLED=true`, `QDRANT_HOST=qdrant`, `QDRANT_PORT=6333`, `QDRANT_COLLECTION=omniroute_memory`, `QDRANT_VECTOR_SIZE=1024`, `QDRANT_HNSW_EF_CONSTRUCT=128`, `MEMORY_VEC_QUANTIZATION=int8`, `MEMORY_RRF_K=60`, and `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS=true` on `omniroute-base`.
  - Configure `PUT /api/settings/qdrant` with strict-schema fields (`enabled: true`, `host: "qdrant"`, `port: 6333`, `collection: "omniroute_memory"`, `embeddingModel: "voyage-ai/voyage-code-3"`, `quantization: "int8"`), while `QDRANT_VECTOR_SIZE=1024` and `QDRANT_HNSW_EF_CONSTRUCT=128` are supplied via environment variables.
- **Enable Always-On Hybrid Memory (`Qdrant Cosine` + `FTS5 BM25` RRF + `Voyage Rerank 2.5`) Across Local Mac Mini & Remote MacBook Pro Requests**:
  - Configure `PUT /api/settings/memory` with `enabled: true`, `maxTokens: 2000`, `retentionDays: 60`, `strategy: "hybrid"`, `skillsEnabled: false`, `embeddingSource: "remote"`, `embeddingProviderModel: "voyage-ai/voyage-code-3"`, `rerankEnabled: true`, `rerankProviderModel: "voyage-ai/rerank-2.5"`, `vectorStore: "qdrant"`, and `primaryBackend: "sqlite"`.
  - Enhance `/Users/androidteam/Omniroute/scripts/container-entrypoint-compat.sh` (preserving all 8 existing MacBook Pro rules) so `resolveMemoryOwnerId()` and keyless semantic-cache calls fall back to `process.env.OMNIROUTE_DEFAULT_OWNER_ID || "6a72d8ab-88db-4d49-973b-864c6cbdace5"` when `apiKeyInfo?.id` is absent (unifying keyless local/Tailnet requests and `mac-mini-1` API-key requests into the shared workspace memory and semantic-cache pool while honoring `x-omniroute-no-memory: true` opt-out), and gate server-side `memory_*` tool injection (`memory_save`, `memory_search`, `memory_update`, `memory_delete`) on `skillsEnabled === true` so `memoryEnabled: true, skillsEnabled: false` only injects `Memory context:` text without mutating `body.tools`.
  - Enhance `retrieveMemoriesInternal()` (strictly scoped to `case "hybrid":` while leaving `case "semantic":` vector-only) and `retrievePreview()` (across both compiled memory chunks `72089.js` and `87878.js`) via `container-entrypoint-compat.sh` so `strategy: "hybrid"` with `vectorStore: "qdrant"` executes **both** Qdrant Cosine search (with `topK` raised to `100` in `searchSemanticMemory`) and SQLite `memory_fts` BM25 search unconditionally when `qdrant.ok` is true (even if Qdrant returns 0 vector hits), fuses their rankings via **Reciprocal Rank Fusion (`RRF, k = 60`)**, and applies cross-encoder reranking (`voyage-ai/rerank-2.5` via loopback `POST /v1/rerank`), falling back to `sqlite-vec` (`int8`) + `FTS5` RRF if Qdrant is unavailable.
- **Enable All-Request Layer-2 Redis Semantic Cache with Host Ollama Metal Embeddings**:
  - Configure `PUT /api/settings/cache-config` with `semanticCacheEnabled: true`, `semanticCacheVectorEnabled: true`, `semanticCacheBackend: "redis"`, `semanticCacheRedisUrl: "redis://redis:6379"`, `semanticCacheRedisPrefix: "omniroute:semcache:"`, `semanticCacheThreshold: 0.90`, `semanticCacheMaxSize: 1000`, `semanticCacheTTL: 18000000`, `semanticCacheEmbeddingProvider: "ollama-local"`, `semanticCacheEmbeddingModel: "nomic-embed-text"`, `semanticCacheEmbeddingDimension: 768`, and `semanticCacheEmbeddingBaseUrl: "http://host.docker.internal:11434/v1/embeddings"`.
  - Set `OMNIROUTE_SEMANTIC_CACHE_ENABLED=true`, `OMNIROUTE_SEMANTIC_CACHE_BACKEND=redis`, `OMNIROUTE_SEMANTIC_CACHE_REDIS_URL=redis://redis:6379`, `OMNIROUTE_SEMANTIC_CACHE_THRESHOLD=0.90`, `OMNIROUTE_SEMANTIC_CACHE_EMBEDDING_PROVIDER=ollama-local`, `OMNIROUTE_SEMANTIC_CACHE_EMBEDDING_MODEL=nomic-embed-text`, `OMNIROUTE_SEMANTIC_CACHE_EMBEDDING_DIMENSION=768`, `OMNIROUTE_SEMANTIC_CACHE_EMBEDDING_BASE_URL=http://host.docker.internal:11434/v1/embeddings`, `OMNIROUTE_SEMANTIC_CACHE_HISTORY_DEPTH=10`, and `OMNIROUTE_SEMANTIC_CACHE_HISTORY_THRESHOLD=50` in `docker-compose.override.yml`.
  - Enhance `SemanticCacheManager` (`lookup` and `store`), `isCompleteTextProjection`, `normalizeConversationForEmbedding`, `RedisVectorStore`, and `resolveProviderConnectionDetails` via `container-entrypoint-compat.sh` so requests carrying `outputContractOf(body)` (`tools`, `tool_choice`, `max_tokens`, `reasoning_effort`, `response_format`, `text.format`) or multi-turn tool messages are **not** excluded from Layer-2 semantic caching; `outputContractOf(body)` is deterministically SHA-256 hashed into the vector store partition filter (`filter.cacheKey` / `entry.cacheKey`), `normalizeConversationForEmbedding` always appends serialized `tool_calls`/`function_call`/`output` and Anthropic `tool_use`/`tool_result` blocks alongside text content so distinct tool arguments or outputs never collide, `RedisVectorStore.searchNearest` batches stale ID removal via `srem`, and `resolveProviderConnectionDetails` falls back to `EMBEDDING_PROVIDERS[provider]?.baseUrl`.
