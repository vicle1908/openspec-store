# Proposal: Harden Jev System One Fail-Closed Answer Validation, Speculative Batching, Multimodal Grounding, and Full Feature Adoption

## Why

The SHB TypeSafe Jev System One runtime currently exhibits a fail-open incomplete-response vulnerability (`noul_prob(..., default=0.0)` and `default=1.0` when `answers` omits required question IDs or returns wrong answer kinds), duplicates guardrail evaluation and PAN-sanitization logic across sync/async and MCP paths, executes sequential per-item HTTP round-trips in `shb-ai-review` and `screen_beneficiary`, and leaves upstream `typesafe-sdk==0.7.5` / `jev-1.14.0` capabilities (`TypeSafe-Danger-Zone-Images` / `TypeSafe-Danger-Zone-Long-Context` headers, `Box` + companion presence `Noul` grounding, `TypeSafeProvider(typesafe_client=...)` HTTP/2 pool sharing, `DecisionHandOff` SDE cascade, `SkillMatcher` relevance gating, and online output guardrails) only partially wired. Hardening the response validation contract and completing full feature adoption across the SHB ecosystem closes this security/compliance gap while achieving upstream's ~10x latency and ~12x token-cost savings.

Specifically:
1. **Fail-Open Incomplete-Response & Partial-Dict Gap (`shb-core`, `shb-agent-core`, `shb-mcp-servers`, `shb-ai-review`, `shb-ai-harness-skills`)**:
   - `typesafe_sdk.SystemOneResponse.answers` (`typesafe_sdk/_core/response_types.py:127`) defaults to `{}` and silently skips unrecognized answer kinds (`docs.typesafe.ai/sdk/python/usage/advanced.md#unknown-answer-kinds`).
   - `shb_core/decisions.py:1205-1208` (`evaluate_guardrail_policy`) and `shb-agent-core/src/shb_agent/tools/guardrails.py:313` (`JevToolGuardrail.a_evaluate_invocation`) read every required guardrail condition via `eval_res.noul_prob(q_key, default=0.0)` (`shb_core/jev.py:501-510`). When an upstream response is empty or omits a required question key, all 4 hazard probabilities become `0.0`, `certainty = |2*(0.0) - 1| = 1.0` bypasses the `uncertainty_band` (`0.40..0.60`), and the guardrail returns `GuardrailOutcome.PROCEED` even on `FINANCIAL_TRANSFER` and `COMPLIANCE_CRITICAL` tools (`initiate_fund_transfer`, `pay_bill`, `screen_beneficiary`, and MCP `execute_tool`).
   - Furthermore, when `JevToolGuardrail.a_evaluate_invocation` calls `evaluate_guardrail_policy(..., probabilities=probs)`, `evaluate_guardrail_policy` skips its `if probabilities is None:` `try/except` block and trusts the caller-supplied dict (`cond_probs = {k: float(v) for k, v in probabilities.items()}`), while existing unit tests (`tests/test_decisions.py:119-139`) pass 2-key synthetic probability dicts (`{"prompt_injection": 0.10, "structuring_risk": 0.01}`).
   - `shb-agent-core/src/shb_agent/tools/compliance.py:135-152` wraps `active_client.evaluate(..., AML_SCREENING_QUESTIONS)` in `with contextlib.suppress(Exception):` and reads `noul_prob(..., default=0.0)`, failing open to `status="CLEARED"` on timeout or partial response instead of failing closed as required by `jev-decision-runtime/spec.md:115`.
   - `shb-ai-review/src/shb_review/validation/hunk_gate.py:387-391` wraps `active_client.evaluate(...)` in `with contextlib.suppress(Exception):` and reads `eval_res.noul_prob("grounded_in_diff", default=1.0)`, causing an incomplete response to accept ungrounded AI findings.
2. **Unbatched Sequential Requests & Hook/Tool Split in `shb-ai-review`, `screen_beneficiary`, and `shb-mcp-servers`**:
   - `AiReviewer.review_diff()` (`shb-ai-review/src/shb_review/ai/reviewer.py:465-475`) calls `_should_skip_hunk_via_jev` in a synchronous loop ($N$ HTTP calls for $N$ diff files), and `HunkGate.filter_findings()` (`hunk_gate.py:405-449`) calls `_verify_ai_finding_citation` in a loop ($M$ HTTP calls for $M$ AI findings) instead of batching all file hunks and all findings into parallel state-referenced `system_one` calls.
   - `screen_beneficiary` (`shb-agent-core/src/shb_agent/tools/compliance.py:103-148`) issues 2 sequential Jev calls on the same invocation (`GUARDRAIL_QUESTIONS` then `AML_SCREENING_QUESTIONS`)—even when `ShbAgent`'s `@hooks.on.before_tool_execute` (`agent.py:196`) already ran `a_evaluate_invocation("screen_beneficiary", ...)` with only the 4 `GUARDRAIL_QUESTIONS`! Meanwhile, `shb-mcp-servers/src/shb_mcp/tools.py:209,413` skips `GUARDRAIL_QUESTIONS` on `compliance_sanction_screen` (missing `prompt_injection` screening on the MCP path).
3. **Upstream `jev-1.14.0` / `typesafe-sdk==0.7.5` Feature & Contract Gaps**:
   - **Multimodal `Box` & `Image` Contract (`docs.typesafe.ai/primitives/box.md`, `images.md`)**: Upstream requires the `TypeSafe-Danger-Zone-Images: true` header whenever `assets` or `Box` questions are sent, and `BoxAnswer` (`{type: "box", box: {top, bottom, left, right}, confidence}`) **always returns a box** with no `present` field (requiring a companion presence `Noul` in the same request). In addition, `sanitize_jev_state()` (`shb_core/jev.py:375`) calls `json.dumps(sanitized, default=str)` on `state`, which corrupts embedded `typesafe_sdk.Image` instances if they exceed `max_chars` or are stringified.
   - **Long Context (`262k` tokens, `docs.typesafe.ai/models.md#long-context`)**: Upstream supports opt-in `262k` per-request/per-question context via `TypeSafe-Danger-Zone-Long-Context: true`; `JevDecisionClient` lacks an opt-in `long_context: bool = False` parameter.
   - **`TypeSafeProvider` Client Pooling & `DecisionHandOff` SDE Cascade (`pydantic-ai==2.59.0`)**: `resolve_typesafe_decision_model()` (`shb-agent-core/src/shb_agent/model.py:100-104`) instantiates `TypeSafeProvider(api_key=..., base_url=...)` instead of `TypeSafeProvider(typesafe_client=active_jev.get_async_sdk_client())`, bypassing `JevDecisionClient`'s pooled HTTP/2 client, custom mock transports, and `effective_compression` guard, and lacks a helper for `FallbackModel(TypeSafeModel, GenerativeModel, fallback_on=DecisionHandOff)` SDE cascades.
   - **Two-Stage Skill Suggestion Gate & Output Guardrail Battery (`cookbooks/skill_suggestion.md`, `cookbooks/llm_guardrails.md`)**: `SkillMatcher.match_jev()` lacks a `needs_any_skill` gate `Noul` / `min_probability` floor, and `shb_core.decisions` / `shb-agent-core` lack an online `OUTPUT_GUARDRAIL_QUESTIONS` + `Score` severity battery (`evaluate_output_guardrail()`).

## What Changes

1. **Enforce Strict Fail-Closed Required-Answer & Answer-Type Validation (`shb-core`, `shb-agent-core`, `shb-mcp-servers`, `shb-ai-harness-skills`, `shb-ai-review`)**:
   - In `JevDecisionClient._build_evaluation_result()` (`shb-core/src/shb_core/jev.py`), validate by default (`require_all_answers: bool = True` on `evaluate()` / `a_evaluate()`) that every requested question key in `questions` is present in `raw_response.answers` and that its returned answer `type` (`"noul"`, `"choice"`, `"score"`, `"box"`) matches the requested question primitive; raise `TypeSafeError` on any missing or wrong-kind answer before returning `JevEvaluationResult`.
   - Add `JevEvaluationResult.require_noul_prob(key)`, `require_choice(key)`, `require_score(key)`, and `require_box(key)` strict accessors that raise `TypeSafeError` if the key is absent or of the wrong answer type.
   - Add `a_evaluate_guardrail_policy()` in `shb_core/decisions.py` and share a single `_extract_and_compose_guardrail_result()` helper between `evaluate_guardrail_policy()` and `a_evaluate_guardrail_policy()` (eliminating the duplicated 55-line async evaluation/fallback block in `JevToolGuardrail.a_evaluate_invocation()`). For live/client evaluations (`probabilities is None`), require all 4 `GUARDRAIL_QUESTIONS` via `require_noul_prob()`; for explicit caller-supplied `probabilities` dicts, require at least one non-empty finite probability in `[0.0, 1.0]` (failing closed on `{}` or non-finite values while preserving 2-key partial unit-test fixtures in `tests/test_decisions.py:119-139`).
   - Consolidate PAN + `<field>_untrusted_text` preservation directly into `sanitize_jev_state()` in `shb_core/jev.py` so `shb-agent-core` (`guardrails.py`) and `shb-mcp-servers` (`tools.py`) share one implementation without duplication.
2. **Batch Multi-Item Evaluations in `shb-ai-review` and Unify Guardrail + AML Fan-Out in `shb-agent-core` & `shb-mcp-servers`**:
   - In `AiReviewer` (`shb-ai-review/src/shb_review/ai/reviewer.py`), add `_triage_hunks_via_jev_batch()` to evaluate all non-preserved diff files in a **single** batched `system_one` request (`state={"hunks": {f"hunk_{i}": ...}}`, `questions={f"hunk_{i}": Noul(...)}`, with unprefixed fallback to `"requires_ai_review"` strictly restricted to single-item batches `len(batch) == 1`). Multi-hunk batches strictly require exact `f"hunk_{i}"` IDs so a flat response cannot skip multiple files across an MR; test mocks are migrated to return exact `hunk_i` IDs.
   - In `HunkGate.filter_findings()` (`shb-ai-review/src/shb_review/validation/hunk_gate.py`), batch all in-hunk AI-generated findings (`finding.source.startswith("ai:")`) into a **single** parallel `system_one` call (`3 * M` `Noul` questions over `state={"hunks": ..., "findings": ...}`, with transparent fallback to unprefixed `"grounded_in_diff"` keys for single-finding test mocks). Require all 3 citation answers via `require_noul_prob` when `eval_res` is returned: an incomplete `answers: {}` map drops the ungrounded AI finding (`ungrounded_ai_filtered += 1`), while transport timeouts/5xx errors still fail open (`True`) so deterministic hunk checks stand.
   - In `shb_core.decisions`, define `COMBINED_AML_GUARDRAIL_QUESTIONS = {**GUARDRAIL_QUESTIONS, **AML_SCREENING_QUESTIONS}`. Update `JevToolGuardrail.evaluate_invocation()` and `a_evaluate_invocation()` so when `clean_name in {"screen_beneficiary", "compliance_sanction_screen"}`, they automatically include `AML_SCREENING_QUESTIONS` in the single request and attach `aml_probabilities: dict[str, float]` on `GuardrailEvaluationResult`. Both `screen_beneficiary` (`shb-agent-core`) and `compliance_sanction_screen` (`shb-mcp-servers`) consume the cached or freshly evaluated `GuardrailEvaluationResult` in **1 Jev call total** (even under `ShbAgent`'s `@hooks.on.before_tool_execute` hook!), failing closed to `FLAGGED_FOR_MANUAL_REVIEW` (`risk_score >= 75.0`, `"JEV_AML_FAIL_CLOSED"`) on any Jev error or incomplete response (including an AML-only response missing the 4 guardrail questions), or `REJECTED` (`risk_score = 100.0`) on `prompt_injection`. Test mocks are migrated to return all 6 answers.
3. **Complete Upstream `jev-1.14.0` / `typesafe-sdk==0.7.5` Feature Adoption Across SHB**:
   - **Danger-Zone Headers, `Image`-Safe State Sanitization, & Long Context (`shb-core`)**: Preserve `typesafe_sdk.Image` objects untouched during `sanitize_jev_state()` (computing serialized size with a short `"<ImageAsset>"` placeholder so binary image buffers are never stringified or truncated), automatically inject `"TypeSafe-Danger-Zone-Images": "true"` in `JevDecisionClient.evaluate()` / `a_evaluate()` whenever `assets` is non-empty, `state`/`questions` contain an `Image`, or any question is a `Box`, and add `long_context: bool = False` (`JevSettings.long_context`) injecting `"TypeSafe-Danger-Zone-Long-Context": "true"` (`max_tokens=262_000`).
   - **Multimodal `Box` + Companion Presence `Noul` Grounding (`shb-core`, `shb-agent-core`, `shb-browser-cli`)**: Add `GroundedBoxResult`, `build_box_grounding_questions(target_key, *, target_description, image_path_ref="image")`, and `extract_grounded_box(eval_res, target_key, *, presence_threshold=0.5, min_confidence=0.6, pad=0.05)` in `shb_core.decisions`, and wire multimodal region localization into `shb-agent-core` (`locate_vietqr_region`) and `shb-browser-cli` (`DocumentExtractor.locate_visual_region` + `shb-browser-cli locate-region`).
   - **`TypeSafeProvider(typesafe_client=...)` & `DecisionHandOff` SDE Cascade (`shb-agent-core`)**: Update `resolve_typesafe_decision_model()` (`shb_agent/model.py`) to pass `typesafe_client=active_jev.get_async_sdk_client()` to `TypeSafeProvider` when a credential or custom transport is present, and add `create_typesafe_sde_cascade_chain()` wrapping `FallbackModel(TypeSafeModel, primary_llm, *fallback_llms, fallback_on=DecisionHandOff)`.
   - **Two-Stage Skill Suggestion Gate & Online Output Guardrails (`shb-agent-skills`, `shb-core`, `shb-agent-core`)**: Add `SKILL_NEEDS_ANY_GATE_QUESTION` (`Noul`), `min_probability: float = 0.0`, and `require_skill_gate: bool = False` to `SkillMatcher.match_jev()` / `a_match_jev()` (plus `--min-prob` on `shb-skills match`), and add `OUTPUT_GUARDRAIL_QUESTIONS` (4 `Noul`s + 1 `Score` harm-severity rubric) and `evaluate_output_guardrail()` / `a_evaluate_output_guardrail()` in `shb_core.decisions` and `JevToolGuardrail.evaluate_output()`.

## Non-Goals

- Modifying any files under `/Users/androidteam/Developer/tdt/` (`tdt/agent-core`, `tdt-core`, `~/.tdt/` remain strictly frozen at `5085b45`).
- Changing OmniRoute's container entrypoint or adding `/v1/systemone` reverse-proxy monkeypatches in `~/Omniroute`.
- Enabling `SHB_JEV_ENABLED=true` by default in unconfigured unit-test environments.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `jev-decision-runtime`: Enforce fail-closed required-answer & answer-type validation on `JevDecisionClient` and `evaluate_guardrail_policy`/`a_evaluate_guardrail_policy`, preserve `Image` instances in `sanitize_jev_state`, batch multi-file diff triage and multi-finding citation verification in `shb-ai-review`, unify guardrail + AML screening into a single fan-out call in `shb-agent-core` and `shb-mcp-servers`, auto-inject `TypeSafe-Danger-Zone-Images` and opt-in `TypeSafe-Danger-Zone-Long-Context` headers, align `Box` spatial grounding with companion presence `Noul`s across `shb-core` / `shb-agent-core` / `shb-browser-cli`, bind `TypeSafeProvider(typesafe_client=...)` and `DecisionHandOff` SDE cascades in `shb-agent-core`, and add `SkillMatcher` relevance thresholding and online output guardrails.
