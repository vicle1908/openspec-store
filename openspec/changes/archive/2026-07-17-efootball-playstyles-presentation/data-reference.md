# Verified Data Reference — eFootball 2026

> Ground-truth research for the presentation. Sources: FIFPlay eFootball 2026
> Playing Styles list and Attributes list (fetched 2026-07-14), cross-checked
> against community activation guides. Player exemplars are **illustrative**
> archetypes, not sourced in-game numbers.

## A. Position-activated Playing Styles (22)

Each style activates only in its compatible position(s). This is the canonical
list the deck MUST cover in full.

### Forwards
| Style | Positions | One-line behavior |
|-------|-----------|-------------------|
| Goal Poacher | CF | Predatory striker on the last defender's shoulder, pounces on chances. |
| Fox in the Box | CF | Lurks inside the 18-yard box to finish. |
| Target Man | CF | Physical focal point; holds up and shields the ball. |
| Dummy Runner | CF / SS / AMF | Attracts defenders to open space for teammates. |
| Deep-lying Forward | CF / SS | Drops deep to link play and create. |

### Midfield creators
| Style | Positions | One-line behavior |
|-------|-----------|-------------------|
| Creative Playmaker | SS / RWF / LWF / AMF / RMF / LMF | Vision-driven; exploits openings with decisive passes. |
| Classic No. 10 | SS / AMF | Traditional playmaker near the box; creates and finishes, conserves stamina. |
| Hole Player | SS / AMF / RMF / LMF / CMF | Makes penetrating runs into the box in possession. |

### Midfield engines
| Style | Positions | One-line behavior |
|-------|-----------|-------------------|
| Box-to-Box | RMF / LMF / CMF / DMF | All-action, covers box to box for 90'. |
| Orchestrator | CMF / DMF | Sits deep to dictate tempo and initiate attacks. |
| Anchor Man | DMF | Deep-lying screen sitting in front of the defence. |
| The Destroyer | CMF / DMF / CB | Disrupts attacks with aggressive pressing and tackling. |

### Wingers
| Style | Positions | One-line behavior |
|-------|-----------|-------------------|
| Prolific Winger | RWF / LWF | Stays wide to receive, occasionally cuts inside. |
| Roaming Flank | RWF / LWF / RMF / LMF | Frequently cuts inside from the flank to create chances. |
| Cross Specialist | RWF / LWF / RMF / LMF | Hugs the touchline, delivers accurate crosses. |

### Defenders
| Style | Positions | One-line behavior |
|-------|-----------|-------------------|
| Build Up | CB | Drops to collect and initiate, often long passes. |
| Extra Frontman | CB | Adventurous CB who pushes forward to join attacks. |

### Full-backs
| Style | Positions | One-line behavior |
|-------|-----------|-------------------|
| Attacking Full-back | RB / LB | Pushes forward to join attacking play. |
| Defensive Full-back | RB / LB | Prioritises defensive stability, stays back. |
| Full-back Finisher | RB / LB | Joins attacks in central areas to reach scoring positions. |

### Goalkeepers
| Style | Positions | One-line behavior |
|-------|-----------|-------------------|
| Attacking Goalkeeper | GK | Sweeper-keeper; leaves line to cover space behind the defence. |
| Defensive Goalkeeper | GK | Stays on the line; shot-stopping and positioning. |

**Count:** 5 + 3 + 4 + 3 + 2 + 3 + 2 = **22 styles.**

## C. Full attribute list (30) grouped into six buckets

FIFPlay groups attributes as Attack / Defence / Strength / Characteristics. The
deck re-groups the *outfield-relevant* attributes into six teaching buckets:

| Bucket | eFootball attributes |
|--------|----------------------|
| **Attacking** | Attacking Awareness, Finishing, Kicking Power, Set Piece Taking |
| **Technique** | Ball Control, Dribbling, Tight Possession, Balance |
| **Passing** | Low Pass, Lofted Pass, Curl |
| **Defending** | Defensive Awareness, Tackling, Aggression, Defensive Engagement |
| **Physical** | Speed, Acceleration, Stamina, Physical Contact |
| **Aerial** | Heading, Jumping |

**Not bucketed (special cases):**
- **GK attributes** (GK Awareness, GK Catching, GK Parrying, GK Reflexes, GK Reach)
  — used only by the two GK styles; the six-bucket dial does not apply to keepers,
  so GK slides use a GK-specific mini-set.
- **Characteristics** (Weak Foot Usage, Weak Foot Accuracy, Form, Injury Resistance)
  — meta traits, out of scope for style dials.

## G. Player image sourcing + attribution

Real player photos are sourced **only** from Wikimedia Commons under rights-safe
licenses (CC-BY, CC-BY-SA, CC0, or public domain). Copyrighted agency/press photos
are never embedded. Photos are fetched at authoring time via the player's
Wikipedia lead image (`pageimages`), license-checked against the Commons
`imageinfo.extmetadata` allowlist, downscaled, and embedded inline as base64 data
URIs so the deck stays a single offline file.

Any exemplar without a rights-safe photo falls back to a deterministic,
name-seeded inline SVG avatar (initials + hashed hue) — never a blank or broken
image.

The regeneration script (`scripts/fetch-player-images.mjs` in the change dir)
writes an image manifest and the per-photo provenance table below is generated
from that manifest. License allowlist: `cc0`, `pd`/`public domain`,

## H. Real per-exemplar key attributes (peek panel)

The interactive peek panel pairs each style's illustrative 0–5 dial (section D)
with the exemplar's **real eFootball 2026 key attributes**. This section pins the
sourcing method, the card-selection rule, and the schema, then records the
captured values (execution task 9.2, **done** — 40/44 exemplars captured
2026-07-15). Every recorded row is transcribed from the player's own pesdb
`?id=` page, never estimated.

### H.1 Source pinning (hard rules)

- **Source:** pesdb.net eFootball database, per-player page (`https://pesdb.net/efootball/?id=<id>`).
- **Dataset:** the **eFootball 2026** export only. pesdb also hosts 2025 pages
  with the same URL shape — each page footer states its game version
  ("Players have been exported from the game **eFootball 2026**"). A row is
  invalid unless its page reads 2026.
- **Fetch date:** a single capture pass; stamp the panel and this section with the
  month/year of capture (e.g. "stats as of Jul 2026"). No live fetching.
- **Attribution:** the peek panel credits "stats: pesdb.net" plus the card type.

### H.2 Card-selection rule (deterministic)

| Exemplar era | Card to capture | Panel label |
|--------------|-----------------|-------------|
| modern (has a current Standard card) | the **Standard** (base) card | "Base card" |
| modern without a Standard card (e.g. TAA, Ramos, Ederson\*) | the **primary current special** card (Epic/Highlight), lowest level | its card type |
| historical / retired legend | the player's **primary released Epic** card at base level (not the newer ML1 "Legendary" re-issue) | "Epic (legend)" |
| legend with no clean 2026 card | **no source row** — see H.2.2 | "Illustrative only" |

Rationale: capture the neutral, base-level rating for each player so a modern
Standard card and a legend Epic card sit on the same scale and map 1:1 to the
0–5 dial. Where a player has multiple cards, pin the **primary** one (the
released Epic for legends; the current Standard for active players) and record
its `pesdb id` so the row is exactly reproducible.

\* "Ederson" is a name-collision trap: pesdb has both a Manchester City keeper
and an outfielder of the same name. The keeper is pinned by id, not name search.

#### H.2.1 Legend data availability — CORRECTED (verified 2026-07-15)

> **This reverses the earlier "moderns-only" decision.** An earlier draft of this
> section claimed the eFootball 2026 export "indexes current-roster players only"
> and that legends had "no rights-clean, reproducible source row." **That was
> wrong.** It conflated *name search returns nothing* with *no card exists*.

What is actually true, confirmed by direct probing of pesdb id-pages:

- **Legends ARE present** in the eFootball 2026 export as full cards. Example:
  Pelé at `?id=88037702764935` returns a complete Epic card (every attribute
  present), footer stamped *"exported from eFootball 2026."*
- The gap is only in the **discovery path**: pesdb's *name search* is not indexed
  for legends, so `?name=Zidane` surfaces only current namesakes (Theo/Luca
  Zidane). Legends are reachable by **direct `?id=`**, and those id-pages are
  web-search-indexed, so the id for each legend can be resolved and pinned.
- Each legend typically has **several** cards (a released Epic at Maximum Level
