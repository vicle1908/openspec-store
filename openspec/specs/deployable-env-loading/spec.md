# deployable-env-loading Specification

## Purpose

`deployable-env-loading` is the capability that defines how TDT services (`ai-review`, `webhook-receiver`) load environment variables at runtime. It ensures that a malformed line in `~/.tdt/.env` cannot crash a production service, and that the deploy script is idempotent.
## Requirements

_(Baseline: no requirements defined. All requirements are introduced by the `deployable-env-loading` change.)_

### Requirement: No bash env sourcing in runtime launchers

The runtime launcher script (generated by `scripts/deploy.sh` and invoked by launchd) SHALL NOT call `source ~/.tdt/.env` or any similar shell-parse step against the env file.

#### Scenario: launcher does not source .env

- **WHEN** the runtime launcher is invoked by launchd
- **THEN** the launcher SHALL execute uvicorn directly without loading `~/.tdt/.env` via bash

### Requirement: Python env loading is fault-tolerant

The Python service MUST load `~/.tdt/.env` via `tdt_core.env.load_tdt_env()` (which wraps `python-dotenv`). Malformed lines SHALL be skipped with a warning; the service SHALL continue starting.

#### Scenario: .env contains malformed line

- **WHEN** `~/.tdt/.env` contains a line that bash cannot parse (e.g. unescaped `|`)
- **AND** the service is started via the runtime launcher
- **THEN** the service SHALL start successfully
- **AND** python-dotenv SHALL log a warning for the malformed line
- **AND** all valid env vars from the file SHALL be loaded

### Requirement: launchd plist provides required env vars

The launchd plist's `EnvironmentVariables` dict SHALL provide at minimum: `PATH` (with `.venv/bin` first), `HOME`, `SSL_CERT_FILE` and `REQUESTS_CA_BUNDLE` (pointing to certifi bundle in the deployed venv).

#### Scenario: plist env vars are present

- **WHEN** launchd starts the service
- **THEN** the service process SHALL have `PATH`, `HOME`, `SSL_CERT_FILE`, and `REQUESTS_CA_BUNDLE` set in its environment

### Requirement: deploy script is idempotent and uses latest code

`scripts/deploy.sh` SHALL, on each invocation: (1) `git pull` the latest source, (2) rebuild the venv with `uv sync --frozen`, (3) regenerate the runtime launcher from the heredoc template, (4) reload the launchd plist.

#### Scenario: clean deploy from local source

- **WHEN** `bash scripts/deploy.sh` is invoked
- **THEN** the deployed runtime tree SHALL contain the latest source from the dev tree
- **AND** the runtime launcher SHALL be the version defined in the deploy script's heredoc
